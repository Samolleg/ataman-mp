## EI-LEGACY-LIGHT-NID-COLLISION — объект и свет с одинаковым ID

- Сообщение владельца 2026-09-27: после копирования объекта в игре вместо него оказался источник света. Приложенный снимок содержит вывод другого чата о совпадении ID 334/335; это исходная гипотеза, а не подтверждение текущего состояния файла. Ожидаемый результат при отдельном поручении на исправление: создание, копирование и перенумерация объектов не выдают ID, уже занятый светом, звуком, частицами или другим объектом игрового семейства; диагностика сообщает о таком конфликте; существующие данные не меняются автоматически. Связано с ручной приёмкой EI-FRESH-TECHNICAL-OBJECT-73, но не закрывает её.
- Диагностика без записи игровых данных: `CMob::freeMapId` проверяет только `m_aNode`; при загрузке `CMob::deserialize` пропускает отдельные `LIGHT_SECTION`, `PARTICL_SECTION`, `SOUND_SECTION`. `CMobDocument::collectObjects` собирает только `OBJECT_SECTION`, поэтому `--validate` не сообщает о пересечении NID объекта и `LIGHT_ID`; семейный подбор ID также опирается на неполный список владельцев. В установленном журнале 2026-09-26 21:18:41 есть `Allocated family-aware NID 335 for zone1.mob`. Текущая JamaisVu135/Maps/zone1.mob содержит Light-334/335 и мост/колонну уже под 7334/7335; старая отдельная копия MODS/test/Maps/zone1.mob содержит колонну NID 335 и Light-335 одновременно. Проверка `--validate --json` обеих копий завершилась без предупреждения о конфликте, что воспроизводит пробел диагностики. Поведение самой игры и исходный момент копирования по журналу не воспроизведены.
- Решение владельца 2026-09-27: исправить маппер, чтобы конфликт не повторялся. Код и временные тесты разрешены; игровые данные и установка не меняются без отдельного запроса сборки. Ветка `codex/legacy-section-id-collision-v74` от версии 73 (`7f782936ec1b876aba7aa80ae77efc56938d4a2a`).
- Статус: код исправлен и проверен, ручная приёмка открыта. Парсер MOB учитывает ID старых LIGHT/SOUND/PARTICL; локальный и семейный подбор и массовая перенумерация исключают занятые ID, диагностика отмечает пересечения, непрозрачные записи не предлагаются для автоматической правки. Release 74, 33 семейных теста, 185 тестов документов (18 внешних fixtures пропущено), сценарий создания/копирования/сохранения, старый реальный MOB только на чтение прошли. Общая UI-проверка exit 1 с теми же семью отказами, что и версия 73. Доказательства: `docs/validation/ATAMAN_LEGACY_SECTION_NID_74_20260927.md`. Конкретная историческая операция копирования и внешний результат в игре не доказаны. Следующий шаг: ручная проверка копирования объекта в редакторе и появления в игре; конфликтующие игровые данные исправлять только отдельно и с резервной копией.

## EI-FRESH-TECHNICAL-OBJECT-73 — создание объектов без старой записи MOB

- Сообщение владельца 2026-09-26: окно «Создать объект» требует выбрать уже существующий объект того же типа, поэтому на новой пустой карте нельзя создать объект мира. Ожидаемый результат: все типы технических объектов создаются на пустом MOB с собственной проверенной полной записью, сохраняются и повторно открываются; выбранный локальный объект при необходимости по-прежнему может дать точный сырой шаблон. Границы: только код и временные тестовые MOB; игровые данные и Endurance не изменять. Ветка `codex/fresh-technical-object-creation-v73` от `40a47063f09a94a3c691681516b22cac5ad67fdb`.
- Исходный случай: при отсутствии выделенного объекта обработчик `CCreateObjectForm::on_buttonCreate_clicked` отклонял любой тип кроме света до вызова `CMob::createNode`, несмотря на существующий путь самодостаточной записи для объектов базы. После исправления проверены восемь типов на пустом синтетическом MOB: создание, охраняемое сохранение, повторное чтение, удаление с восстановлением исходных байтов. Проверены отказы при отсутствующей модели и несовместимой модели ловушки. `--database-creation-check` и Release73 PASS. `--ui-widget-check` exit1 на прежних проверках буфера обмена; сценарный набор 48 PASS / 2 FAIL из-за тестового резервного каталога, эти наборы не засчитаны. Чистый пакет финализирован и независимо проверен; постоянная установка обновлена с 72 до 73, 127 управляемых и 15089 пользовательских файлов сверены. Статус: код, синтетическое сохранение и установка проверены, ручная проверка в окне редактора открыта. Доказательства: `docs/validation/ATAMAN_FRESH_TECHNICAL_OBJECT_73_20260926.md`. Следующий шаг: вручную создать объект мира на новой пустой карте, сохранить, открыть снова, удалить и проверить сохранение; затем проверить нужные остальные типы.

Контрольная OpenGL-текстура: до исправления уничтожалась при `refreshConfiguredSources` (FAIL), после исправления выдержала три обновления и освободилась без открытого MOB (PASS).
