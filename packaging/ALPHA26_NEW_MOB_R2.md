# New MOB creation R2

## What changed

- Newly generated primary and supplemental MOBs now contain an empty,
  runtime-compatible object container, so the first pasted object can be saved
  and staged safely.
- Existing object-free MOBs generated by R1 are upgraded on their first object
  save. The upgrade inserts only the missing empty container and preserves all
  existing MOB records and unknown top-level bytes.
- MOB save failures are now shown by the owning editor window after its progress
  dialog closes. The error remains readable and closable instead of being hidden
  behind editor refocusing.
- Multi-MOB unload/save uses the same parented safe-save path as ordinary MOB
  saves.

## Focused test

1. Open the R1-created `autozone-new1.mob`, paste the same two Zone 1 trees,
   save, close, and reopen it. Both trees should remain and the editor must not
   lock.
2. Load the primary MOB and this supplemental MOB together, then use **Test
   Current Map**. Staging should proceed instead of refusing the dirty
   supplemental MOB.
