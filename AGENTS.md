## Вход соавтора и другой компьютер

- Инструкции действуют в этом checkout и его явно разрешённых рабочих копиях,
  независимо от имени каталога и компьютера. Новый участник начинает с
  docs/COAUTHOR_HANDOFF.md, затем читает перечисленные ниже действующие договоры.
  Шаблон конкретного задания — docs/CODEX_TASK_TEMPLATE.md.
- Приватный GitHub-клон ataman-mp содержит очищенную линию. Его main и SHA
  отличаются от исходной локальной истории владельца. На новом компьютере
  базой служит SHA очищенной линии, назначенный сопровождающим, либо main
  этого клона, уже принятый сопровождающим. Не искать отсутствующий исходный
  SHA и не подменять его похожим коммитом. Происхождение ниже историческое.
- Все рабочие пути определяются от фактического корня checkout. Пути
  C:/GOG Games/... в старых отчётах описывают компьютер автора, не обязательную
  установку соавтора. Игру, мод, toolchain и тестовые данные настроить отдельно;
  ничего не копировать с чужого компьютера и не включать в Git автоматически.
- Сопровождающий согласует базу, номера новых версий и непересекающиеся задания.
  Единственная рабочая ветка проекта — main. Соавтор также работает в main;
  чужие незавершённые пункты ROADMAP и незакоммиченные файлы сохраняются.
- Подготовка документации не выдаёт доступ GitHub. По решению владельца
  2026-10-03 «сделай коммит» означает scoped-коммит в main, а «отправь на GitHub»
  означает обновить GitHub main текущим согласованным результатом. Отдельное
  разрешение на интеграцию в main не требуется; уже разрешённый шаг не спрашивать.

## Проект и база

- Это самостоятельный локальный репозиторий ei-mapper-ataman, не worktree Endurance.
  Исходный проект, его рабочие копии и сборки не изменять.
- Историческая основа кода: 19168b91a10562525fb6c83b665275c2fd43cf4c.
  В исходной локальной линии новые задачи начинаются от принятого main —
  потомка этой основы, либо от базы владельца. В очищенном GitHub-клоне
  используют принятую базу его линии по секции входа выше.
  Не импортировать более новые изменения Endurance автоматически.
- При входе и возобновлении проверить актуальность AGENTS.md; читать изменённые
  или отсутствующие в контексте правила. CONTRIBUTING.md задаёт краткий порядок;
  docs/PROJECT_CONTRACT.md нужен для работы с данными, docs/TEST_BUILD_HANDOFF.md —
  для сборки/передачи, docs/PARALLEL_THREAD_WORKERS.md — при делегировании.
  Читать текущий пункт ROADMAP и открытые зависимости, не весь журнал.
  Новое сообщение само по себе не требует перечитывать неизменный контекст.
  Старые upstream-документы и ссылки — история, не разрешение на действия.
- Новое явное решение владельца важнее старой проектной записи; системные
  ограничения сохраняются. Неоднозначность сначала исследовать без изменений,
  затем уточнять у владельца.

## Назначение документов

- AGENTS.md задаёт полномочия и рабочий процесс; CONTRIBUTING.md — краткий
  порядок его выполнения. docs/PROJECT_CONTRACT.md задаёт сохранность и
  совместимость данных. docs/TEST_BUILD_HANDOFF.md — обязательный договор
  передачи сборок; docs/BUILDING_ENDURANCE.md содержит технические команды
  и не может ослаблять этот договор. При делегировании дополнительно действует
  docs/PARALLEL_THREAD_WORKERS.md. На новом компьютере руководство входа
  docs/COAUTHOR_HANDOFF.md дополняет их и не отменяет договоров.
- ROADMAP.md хранит текущую задачу и открытые цели, CHANGELOG.md — историю
  версий, docs/validation — доказательства с датой и границами проверки.
  Исторические разрешения и статусы из Endurance не действуют в Ataman.
- При продолжении сверять текущие правила и карту с последним поручением.
  Уже полученное разрешение не запрашивать повторно; запись в карте сама
  по себе не расширяет объём работ. Если конфликт не разрешается последним
  решением владельца и назначением документов, уточнить только спорный шаг.

## Версии Ataman

- Канонический номер хранится в VERSION. Начальное состояние Ataman — версия 1;
  далее целые номера 2, 3, 4… независимо от старых версий Endurance.
- Каждое отдельное исправление программы или новая функция получает следующий
  номер, локальный коммит и запись CHANGELOG.md с ID задачи и проверками.
  Одни документы, аудит без исправлений, промежуточные эксперименты и повторная
  сборка тех же исходников номер не увеличивают. Правка только документов сама
  по себе не требует сборки или обновления установки. Настройка нумерации
  относится к исходной версии 1.
- Перед назначением номера сверять VERSION, CHANGELOG.md и принятую базу.
  При работе нескольких участников согласовать уникальные номера и базу main;
  номер версии не заменяет полный SHA и проверку согласованного результата.
- Обновлять текущие указатели версии в Readme.md и ROADMAP.md; исторические
  записи версий и отчёты не переписывать. Постоянную установку обновлять по
  docs/TEST_BUILD_HANDOFF.md. Номер 1 не означает стабильный
  релиз и не закрывает унаследованные дефекты. Сборка и передача — по
  docs/TEST_BUILD_HANDOFF.md. Рабочие изменения и коммиты выполняются в main.

## Единственная ветка main и коммиты

- По поручению владельца от 2026-10-01 создан приватный GitHub-репозиторий
  Samolleg/ataman-mp; remote origin указывает на него. Поручение разрешает
  первоначальную публикацию текущей версии88 с очищенной историей и
  авторством: владелец явно потребовал исключить игровые файлы и старые сборки
  из всей переносимой истории. Очистка выполняется в отдельном экспорте;
  исходная локальная история сохраняется. Нельзя отправлять исходные ветки
  напрямую в origin или использовать push --all/--mirror: они возвращают
  исключённые файлы. Историческое требование отдельного разрешения на main
  отменено владельцем 2026-10-03. Запрос «отправь на GitHub» разрешает необходимые
  проверки remote/fetch и обновление только main; запрос «сделай коммит» сам
  по себе не означает push. PR/issues, новые remotes и отдельные ветки не создавать
  без конкретного нового поручения.
  Не менять OAuth, токены, аккаунты и глобальные настройки Git.
- Запрет прямого push исходных веток относится к старой неочищенной линии
  владельца. В обычном клоне очищенной GitHub-линии разрешённая публикация
  идёт конкретным проверенным SHA в main без повторной фильтрации всей истории.
  Не смешивать эти линии через merge, cherry-pick игровых файлов или старые теги.
- Единственная рабочая ветка — main: реализацию, исправления и scoped-коммиты
  делать непосредственно в ней. Не создавать codex/<task> или другую рабочую
  ветку. Проверять исходный SHA, рабочий каталог и статус.
- Если владелец просит исправить только что переданный результат, сверить его
  проверенный SHA с текущим main и записать зависимость в карте; продолжать
  в main, сохраняя уже принятые и чужие изменения.
- Локальный scoped-коммит согласованной реализации входит в работу. Анализ
  сам по себе не разрешает исправления. Проверять staged diff; не брать чужие правки.
- «Сделай коммит» — сделать scoped-коммит в main. «Отправь на GitHub» —
  опубликовать согласованный результат в GitHub main; отдельное подтверждение
  переноса в main не запрашивать. Проверять удалённый SHA до и после отправки.
  Сохранять чужие удалённые изменения; при конфликте не угадывать решение.
  Не переписывать историю, не выполнять reset --hard/force push и не удалять
  worktrees без поручения. Игровые файлы исключать по docs/PUBLISHING_SOURCE.md.
- Не коммитить сборки, настройки, журналы, дампы, сохранения, игровые ресурсы,
  секреты и приватные исходники. Сохранять LICENSE, NOTICE, авторство и историю.

## Дорожная карта и проверка

- Каноническая карта длительной, многоэтапной работы и продолжения между сеансами —
  ROADMAP.md. Кратко хранить ID, исходную проблему, полный результат, разрешение,
  критерии, статус, подтверждения и следующий шаг. Для небольшого самостоятельного
  вопроса достаточно цели и результата в разговоре; новую карту не создавать.
- Обновлять пункт при существенном результате, изменении решения, блокере и перед
  передачей незавершённой работы. Перед записью перечитать актуальный фрагмент,
  сохранить чужие пункты; неизменное состояние перед каждым ответом не переписывать.
  Симптомы не заменяют основную цель, выполнение части не закрывает родительскую задачу.
- Для дефекта установить условия и ожидаемый результат, проследить причину до
  неверного значения или состояния. Если воспроизведение нестабильно или недоступно,
  использовать логи, дампы, исходники и наблюдения; новые попытки назначать под
  конкретную гипотезу. Неподтверждённую причину обозначать гипотезой.
  Для новой функции определить проверяемое ожидаемое поведение.
- Каждая проверка должна влиять на действие или вывод о готовности. Проверять
  исходный случай и связанный регресс; расширять набор по конкретному риску.
  Повторять после относящихся изменений, новых свидетельств ошибки, утраты
  актуальности или при исследовании нестабильности. Успешный результат на тех же
  входах/артефактах без новой причины не повторять.
- После полного согласованного результата и достаточной проверки переходить
  к следующему разрешённому этапу или завершать. Недоступную обязательную проверку
  указывать точно; независимую работу продолжать, косвенные проверки не повторять
  вместо неё. Таймаут, сбой и SKIP не являются PASS; упаковка не доказывает исправность.
- В итоге сообщать результат, существенную проверку и реальные ограничения.
  Для коммита/сборки дать ветку, полный SHA, версию и путь, когда они применимы;
  детали тестов можно вынести в evidence по ссылке. Пустые разделы не нужны.
  Подготовку, установку и ручную/игровую приёмку различать, не скрывать важные пробелы.

## Данные и исследование

- Чтение установленных игр, модов и разрешённых данных допустимо в рамках задачи.
  «Не трогать» означает не изменять, если чтение отдельно не запрещено.
- Необходимые рабочие/тестовые копии уже разрешённых игровых данных входят
  в согласованную задачу и не требуют повторного разрешения. Хранить их приватно
  вне живой установки, Git и выдаваемых пакетов; исходники данных сохранять.
  Новый источник или расширение объёма согласовать. Живые данные менять только
  с разрешением и резервной копией.
- Не переносить приватный код и игровые данные в репозиторий или сборки.
- При наличии навыков evil-islands-modding и evil-islands-private-engine-reference
  прочитать относящиеся инструкции до соответствующего исследования. При их
  отсутствии сообщить ограничение: работа с обычным кодом проекта допустима,
  работу, зависящую от неизвестных правил приватных источников, приостановить.
  Не придумывать разрешения на доступ или раскрытие приватного кода.
- Диагностика не разрешает автоматический ремонт данных.
  Совместимость и сохранение: docs/PROJECT_CONTRACT.md.

## Задачи и сборки

- Решение владельца2026-10-24 (EI-MCP-HEADLESS-225): MCP-мост может сам
  запускать маппер с `--agent-headless` без видимых окон. Полномочия и Save

  Это разрешение продуктового сценария, а не интерактивного запуска редактора
  Codex-разработчиком при сборке/проверках: соответствующий запрет ниже сохранён.

- Новые пользовательские задачи и делегирование — только по соответствующей
  явной просьбе владельца. Следовать docs/PARALLEL_THREAD_WORKERS.md.
- Поручения разделяют разрешения на чтение и запреты на изменение; назначать
  конкретное владение файлами, не использовать неоднозначное «не трогать».
- Для сборок соблюдать docs/TEST_BUILD_HANDOFF.md. Не запускать редактор
  интерактивно вместо пользователя. По решению владельца2026-10-04 будущие
  комплекты для распространения выдавать в ZIP без повторного запроса разрешения.
  Архивировать только проверенную чистую staging-папку, проверять содержимое
  ZIP по manifest и давать ссылку на архив. Обычная тестовая сборка обновляет
  постоянную установку по договору; отдельный ZIP для неё без просьбы не нужен.
- Финализатор удаляет настройки, логи, сохранения и кэш. Запускать его только
  на собственной staging-папке, изначально созданной заново для этой версии,
  никогда на пользовательской установке. Повторный запуск допустим лишь пока
  папка не передана и не содержит пользовательских данных, по договору передачи.
  По решению владельца от 2026-09-17 используется одна постоянная установка:
  `artifacts/EI-Mapper-Ataman-2-first-test` относительно корня Ataman.
  Её имя сохраняется для совместимости пути и не определяет текущую версию.
  Каждый запрос сборки включает обновление программы в этой папке после проверки;
  повторное разрешение на замену программных файлов не требуется. Настройки,
  карты, сохранения и прочие пользовательские файлы сохранять. Финализатор
  на постоянной установке не запускать. Другие установки/сборки не менять.
