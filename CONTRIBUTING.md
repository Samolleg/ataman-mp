Проект ведётся в отдельном локальном репозитории. Git сохраняет историю;
приватный GitHub-репозиторий — Samolleg/ataman-mp. Первоначальная публикация
версии88 разрешена владельцем 2026-10-01; последующие сетевые операции требуют
соответствующего явного поручения.
Владелец потребовал очищенный экспорт истории без игровых файлов и старых
сборок. SHA опубликованной линии отличаются от исходной локальной истории;
её ветки нельзя отправлять напрямую через push --all/--mirror. См.
[состав публикации](docs/PUBLISHING_SOURCE.md).
Историческая исходная основа: 19168b91a10562525fb6c83b665275c2fd43cf4c.
Этот SHA не является базой для нового GitHub-клона: используйте назначенный
сопровождающим SHA очищенной линии или принятый main своего клона.
main — принятая владельцем линия, а не обещание отсутствия всех дефектов.

## Порядок работы

1. Открыть checkout Ataman (имя папки может быть ataman-mp), прочитать AGENTS.md
   и ROADMAP.md; для первого входа также docs/COAUTHOR_HANDOFF.md.
2. Проверить HEAD, затрагиваемые файлы и адреса remotes. Обращаться к GitHub
   только в пределах текущего поручения; не изменять исходный Endurance.
3. Работать только в main текущей линии. Проверить принятую базу и зависимость
   от только что переданного результата; не создавать ветки для задач.
   Сохранять чужие изменения и не импортировать более новый Endurance.
4. Воспроизвести дефект или определить тест функции. Выполнить согласованный
   объём, проверить исходный случай и регресс, сохранить чужие изменения.
5. Для каждого отдельного исправления или новой функции увеличить целый номер
   VERSION по правилам AGENTS.md, обновить CHANGELOG.md и текущие указатели
   версии. Проверить staged diff и сделать локальный scoped-коммит без
   сборок/личных данных. Аудит без исправлений и повторная сборка номер не меняют.
6. Передать ветку, полный SHA, результаты и ограничения. Запрос сборки включает
   обновление одной постоянной установки по docs/TEST_BUILD_HANDOFF.md
   с сохранением пользовательских данных. «Сделай коммит» означает коммит
   в main; «отправь на GitHub» означает обновить GitHub main проверенным
   согласованным результатом. Отдельное разрешение на интеграцию не требуется.
7. Перед push сверить remote, сохранить чужие изменения и проверить конечный
   SHA main. При конфликте сохранить состояние и сообщить, не угадывать решение.

## Шаблон задания

```text
Работай в локальном проекте ei-mapper-ataman.
Прочитай AGENTS.md, CONTRIBUTING.md и текущую ROADMAP.md.
Задача: <описание и ожидаемый результат>.
База: <полный SHA принятой линии текущего checkout>.
В новом клоне ataman-mp использовать очищенную линию GitHub;
исторические SHA из локальных отчётов не подставлять вместо назначенной базы.
Работай только в main; новые рабочие ветки не создавай.
Публикация нужна только по поручению «отправь на GitHub» и обновляет main.
Не меняй установленную игру и чужие файлы. Запрошенную сборку установи
в постоянную папку Ataman по docs/TEST_BUILD_HANDOFF.md, сохрани настройки.
Проверь задачу и регресс, сделай локальный scoped-коммит.
Сообщи полный SHA, изменения, результаты тестов и оставшиеся пробелы.
Если нужна сборка, следуй docs/TEST_BUILD_HANDOFF.md.
```

Новую задачу Codex или параллельную работу агент создаёт только по просьбе
владельца. Достаточно описать следующую работу в текущем разговоре.
