Проект ведётся в отдельном локальном репозитории. Git сохраняет историю;
приватный GitHub-репозиторий — Samolleg/ataman-mp. Первоначальная публикация
версии88 разрешена владельцем 2026-10-01; последующие сетевые операции требуют
соответствующего явного поручения.
Владелец потребовал очищенный экспорт истории без игровых файлов и старых
сборок. SHA опубликованной линии отличаются от исходной локальной истории;
её ветки нельзя отправлять напрямую через push --all/--mirror. См.
[состав публикации](docs/PUBLISHING_SOURCE.md).
Историческая исходная основа: 19168b91a10562525fb6c83b665275c2fd43cf4c.
Этот SHA не является базой для нового GitHub-клона: используйте назначенный
сопровождающим SHA очищенной линии или принятый main своего клона.
main — принятая владельцем линия, а не обещание отсутствия всех дефектов.

## Порядок работы

1. Открыть checkout Ataman, проверить актуальность инструкций по AGENTS.md.
   Читать текущий пункт ROADMAP и зависимости; профильные документы — по задаче.
   Для первого входа на другом компьютере использовать docs/COAUTHOR_HANDOFF.md.
2. Перед изменениями проверить HEAD и затрагиваемые файлы. Проверку remote
   выполнять для относящихся сетевых действий в пределах поручения.
   Исходный Endurance, живые данные и чужие правки сохранять.
3. Работать в main принятой линии; не создавать ветки для задач и не импортировать
   новый Endurance. При продолжении переданного результата учитывать его базу.
4. Выполнить согласованный объём, проверить исходный случай и связанный регресс
   по критерию достаточности AGENTS.md. Для нестабильного дефекта использовать
   доступные свидетельства и адресную диагностику; для функции задать ожидаемый
   сценарий. Гипотезу и недоступную проверку не выдавать за подтверждение.
5. Отдельное исправление программы/функция получает следующий VERSION,
   CHANGELOG и обновлённые указатели. Одни документы, аудит и повторная сборка
   номер не меняют. Изменения фиксировать scoped-коммитом в main после проверки
   staged diff, без чужих правок, сборок и личных данных.
6. Сообщить результат и ограничения; SHA/версию/путь — для применимого коммита
   или сборки. Запрос сборки включает обновление постоянной установки по
   docs/TEST_BUILD_HANDOFF.md с сохранением данных; нового разрешения не нужно.
7. «Сделай коммит» означает scoped-коммит в main, «отправь на GitHub» — обновление
   GitHub main проверенным результатом. Перед push сверить remote, сохранить
   чужие изменения и проверить конечный SHA. Отдельное разрешение на интеграцию
   не требуется; при конфликте сохранить состояние и уточнить спорный шаг.

В новом клоне ataman-mp использовать очищенную линию GitHub;
исторические SHA из локальных отчётов не подставлять вместо назначенной базы.
Работай только в main; новые рабочие ветки не создавай.
Публикация нужна только по поручению «отправь на GitHub» и обновляет main.
Не меняй установленную игру и чужие файлы. Запрошенную сборку установи
в постоянную папку Ataman по docs/TEST_BUILD_HANDOFF.md, сохрани настройки.
Проверь исходный случай и связанный регресс; для реализации сделай scoped-коммит.
Сообщи результат и существенные пробелы; для коммита/сборки — SHA и применимые детали.

Новую задачу Codex или параллельную работу агент создаёт только по просьбе
владельца. Достаточно описать следующую работу в текущем разговоре.
