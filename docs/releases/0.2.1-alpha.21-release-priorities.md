# 0.2.1-alpha.21 Release priorities

This build completes the remaining release-facing editor implementation pass.

## Changes

- Reopening the same canonical MOB activates its existing document instead of
  loading a duplicate copy.
- Opening a different MPR through File, Recent Files, drag/drop, or the command
  line now uses the same dirty-state guard as the Maps browser before replacing
  the complete workspace.
- Manual MOB/MPR loads and safe saves use blocking, named progress phases so a
  healthy long operation does not look frozen.
- Periodic autosave writes deduplicated, versioned candidates under Endurance's
  backup area. It never overwrites the source file. Recoverable candidates are
  reported on startup only while their source still matches the captured hash.
- The optimized profile-correct humanoid appearance, equipped visuals,
  standing animation, spatial query, and bounded render-queue work is merged.

## Focused checks

1. Open the same MOB twice using direct Open, Recent Files, and differently
   cased paths where possible. It must remain one Loaded Map/outliner entry.
2. Dirty a MOB, then manually open a different MPR. Test Save, Discard, and
   Cancel; Cancel must retain the complete current workspace.
3. Save a large MOB and MPR and confirm meaningful progress phases appear.
4. Set autosave to one minute, make an edit, and verify a recoverable generation
   is written without touching the live source. Saving normally must retire the
   stale recovery notification.
5. Recheck representative Base and JMV humanoids, armor, weapons, idle poses,
   locked-MOB selection colors, and large-map frame pacing.

The final gameplay/runtime matrix remains the release-candidate validation gate;
it is not replaced by this editor-side regression pass.
