# EI Mapper Endurance 0.3.0-alpha.21 - minimap fidelity and hot reload

## Changelist

- Treats any loaded MOB source as the static-geometry source for minimap
  capture. The MPR-only warning now appears only when no MOB is loaded.
- Captures minimaps with deterministic unlit rendering, disabled scene lights,
  fog, shadows, animation, and terrain mipmapping. Viewport lighting mode and
  time of day no longer alter the result.
- Corrects the vertical game orientation while retaining world +X to the right.
- Matches the game's non-square-map framing. The MMP remains 256 x 256, while
  an 11 x 9 map occupies a 256 x 209 top-left active rectangle instead of
  being stretched to a square.
- Removes smooth supersample reduction from the game texture. A copied Zone 1
  control confirmed that both the embedded and generated texture are
  single-level 256 x 256 `8888` MMPs, so no profile-specific format or
  resolution change is required.
- Adds three persisted viewport-minimap sizes with `-` and `+` controls. Both
  embedded and generated square textures are displayed using the map's active
  aspect rectangle.
- Makes destination inspection and RES export run off the UI thread behind a
  blocking, determinate 0-100 progress window.
- Extends the owned hot-reload protocol so each generated minimap gets a
  generation-specific texture name and private RES. The runtime bridge verifies
  and registers that RES, then selects generated or embedded minimap metadata
  before the New Game rebootstrap.

## Automated validation

- Synthetic minimap/export tests cover vertical orientation, aspect-correct
  active rectangles, deterministic layer composition and exclusion, 256 x 256
  `8888` encoding, new/append/replace/refuse archive paths, failed-save
  preservation, catalog gating, and temporary staging.
- Hot-reload protocol tests cover owned generated-minimap RES fields, unsafe
  names, bridge-control round trips, and escaping/live-path refusal.
- The non-interactive widget check verifies Embedded/Generated switching and
  all three `-`/`+` size levels.
- The 32-bit JMV bridge and a clean Qt 5.12.12 / MinGW 7.3 release are rebuilt
  through the documented ASCII `subst` path.

## Manual acceptance cases

1. Load a copied 11 x 9 MPR and MOB. Confirm Generated reports complete MOB
   capture, remains identical across all lighting modes and times, has the same
   aspect as Embedded, and is no longer vertically inverted.
2. Close every MOB while retaining the MPR. Confirm only this state reports
   incomplete MPR-only capture; reload a MOB and confirm the warning clears.
3. Use the viewport minimap `-` and `+` buttons. Confirm exactly three sizes,
   correct disabled end states, persistence after restart, and working collapse.
4. Export to a large copied RES. Confirm the modal progress advances from 0 to
   100, the UI does not look frozen, append does not ask for replacement, and an
   existing member asks only after Export is pressed.
5. In a controlled JMV test, compare the generated minimap with the copied
   embedded control at equivalent game zoom. Confirm orientation, framing, and
   useful detail. The game texture must reopen as 256 x 256 `8888`.
6. Start Test Current Map with Embedded, switch to Generated, and hot reload.
   Then switch back to Embedded and hot reload again. Confirm each generation
   changes the in-game minimap without stopping the test process.
7. Confirm every generated hot-reload `minimap.res` is inside its owned
   generation directory, hash-validated, and removed with normal run cleanup.

## Private runtime validation still required

The bridge/resource registration path and the final visual comparison require a
controlled private JMV run against hash-recorded copies. Do not install, modify,
or redistribute a live proprietary archive while performing these checks.
