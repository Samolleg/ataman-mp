# 0.2.1-alpha.6 validation source and projection hardening

This tester build fixes the copied-workspace false-collision flood, long GUI
stall, and phantom dirty document observed in the alpha.5 Zone 7 test.

## What changed

- Runtime-family sources are identified by case-insensitive logical MOB
  filename. An opened workspace copy shadows an installed file of the same
  name instead of both being counted as live family members.
- The validation panel shows the complete active path, source role, inclusion
  reason, shadowed alternatives, and source hash. Its context menu can copy a
  path or complete finding.
- Relevant warnings offer **Open Validation Panel** beside **OK**.
- Family traversal, parsing, range/reference indexing, and collision analysis
  run off the GUI thread. Repeated edits are debounced and obsolete generations
  are discarded. Large reports render an initial bounded page with **Show
  more**.
- Structurally bounded unknown root records are retained byte-for-byte as
  opaque compatibility data. `Autozone7chest.mob` now opens its known editable
  content and reports one `mob.opaque_unknown` warning for `0xACCEECCC`.
- Failed or provenance-unsafe MOB loads are destroyed before registration and
  cannot become active, dirty, undoable, or validation candidates.
- Candidate validation is observational and no longer refreshes or mutates the
  document dirty flag.

## Focused validation

- Endurance document suite: 33 passed, including the supplied
  `Autozone7chest.mob` opaque-record fixture and a known-leaf edit that keeps
  the unknown record at the same offset with identical bytes.
- Workspace-overlay suite: copied logical MOBs shadow installed equivalents;
  different logical names remain independent.
- Supplied Zone 7 corpus: seven resolved logical MOBs, exactly eight genuine
  `Autozone7altar` critical NID collisions, and no copied-versus-installed
  false duplicates. The focused run completed in approximately 0.4 seconds.
- Full Qt 5.12.12/MinGW x64 editor build completed.

## Tester checklist

1. Open the supplied six-MOB tester directory with the JMV profile active.
   Confirm the family rows show tester paths and installed alternatives only as
   shadowed sources.
2. Confirm the eight genuine `Autozone7altar` collisions remain and copied
   `zone7`/Autozone files do not collide with their installed twins.
3. Open `Autozone7chest.mob`. It must remain clean and editable, with one
   non-blocking opaque-record warning and no projection error popup.
4. Edit a known chest property, Save As to a disposable file, reopen it, and
   confirm only the intended field changed.
5. Unload/reopen Zone 7 and Altar repeatedly while validation is running. The
   viewport must remain responsive and obsolete warning dialogs must not
   appear.

NID/range findings remain advisory: they do not block editing, saving, Save As,
Test Current Map, or hot reload.
