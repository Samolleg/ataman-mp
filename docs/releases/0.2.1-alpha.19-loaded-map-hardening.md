# 0.2.1-alpha.19 Loaded Map hardening

This build supersedes alpha.18 after an unload-time Qt widget crash.

## Fixes and changes

- MOB lookup now returns no document when a path/name is stale instead of
  incorrectly returning the last loaded MOB.
- Loaded Map rows store stable source paths rather than raw MOB pointers.
- Activating another MOB preserves selections in the MOB that becomes locked.
- Selected locked-MOB objects use an amber viewport highlight; active-MOB
  selections retain the cyan highlight.
- Loaded Map rows show selected-object counts and use `*` next to a dirty MOB
  filename. The misleading inferred Primary/Supplemental labels were removed.
- Paste into another MOB transfers selection to the pasted objects.
- The outliner shows Active/Locked ownership, tooltips, and a sticky selected
  hierarchy while its owning MOB row is scrolled out of view.
- Shift/Ctrl multi-selection is available in Loaded Map; a single context-menu
  command unloads the selected MOB rows with one combined dirty-state choice.
- MOB activation remains double-click-only.

## Focused tester pass

1. Reproduce the alpha.18 sequence by loading Zone 6 with supplemental MOBs,
   unloading the main MOB and multiple supplementals, then continuing to use
   the viewport, outliner, validation panel, and Loaded Map for several minutes.
2. Select an object in one MOB, double-click another MOB row, and confirm the
   old selection remains amber/locked while the new MOB becomes active.
3. Double-click a locked object in the outliner and confirm its owner becomes
   active and the Loaded Map row follows it.
4. Copy from a locked MOB and paste into the active MOB; only the pasted objects
   should remain selected.
5. Shift-select several MOB rows and unload them together, exercising Save All,
   Discard, and Cancel for dirty documents.
