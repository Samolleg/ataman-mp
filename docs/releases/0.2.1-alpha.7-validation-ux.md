# 0.2.1-alpha.7 validation UX follow-up

## Changes

- Validation warning dialogs are wide and intentionally brief: at most three
  single-line, length-limited findings followed by `...` when more exist.
- The complete report remains available through **Open Validation Panel** and
  the workflow log.
- MOB Family Validation starts detached, remains dockable, has ordinary native
  minimize/maximize/close controls, and can always be reopened from View after
  its close button is used.
- Double-click an NID-backed object row, or use **Select object in editor** from
  its context menu, to activate and select that object when its source MOB is
  currently loaded. Duplicate NIDs are resolved with raw section provenance;
  ambiguous or unloaded objects are not guessed.
- The roadmap records the low-priority crash observed when hot reload is sent
  while the game is between zones.

## Temporary runtime files

Endurance retains complete run payloads below its AppData test-run directory.
The proven JMV bridge also requires a randomly named `ed*.mpr`/`ed*.mob` alias
in the active mod's `Maps` directory so the unmodified engine map lookup can
resolve the temporary identity. These are not source-map saves. Their hashes
are recorded before launch and cleanup removes them only while those hashes
still match. Interrupted-run recovery retries the same guarded cleanup.

## Repair status

**Tools > Review and Repair NID Collisions** is already available as a limited,
explicit repair assistant. It proposes deterministic IDs and applies selected
safe repairs as one undoable operation. It does not run automatically, repair
range overlaps, guess script/ParentID references, or yet coordinate saving a
multi-MOB repair cohort.
