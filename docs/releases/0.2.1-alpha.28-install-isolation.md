# EI Mapper: Endurance Edition 0.2.1-alpha.28

Closed-test correction for resource switching and dual-install JMV isolation.

- Changing an effective game root, mod root, resource path, map path, or editing
  profile prompts for dirty documents before unloading the complete workspace.
- After applying setup, Endurance reinitializes resources and refreshes Maps &
  Collections. Loaded maps can no longer retain resources from the previous
  profile or installation.
- JMV Test Current Map continues to launch the profile-selected
  `Starter/Engine/game.exe` through the editor-owned injector.
- Inside that owned process only, Endurance supplies the selected Starter root
  and JMV `AddonPath`. The user's global Starter registry values are not edited.
- Starter/JMV read those values through the wide-character Win32 registry API;
  alpha.27 intercepted only the ANSI path API. Alpha.28 covers the observed
  `RegOpenKeyExW` / `RegQueryValueExW` path and records it as
  `STARTER_ROOT_OVERRIDE ... api=wide`.
- Requests for the same logical JMV mod that still contain another
  installation's absolute path are redirected to the selected mod root and
  recorded as `JMV_ROOT_REDIRECT` in the runtime log.
- The owned injector now prepares path/file isolation while `game.exe` is
  suspended, then resumes JMV and observes its executable patch phase. Engine
  map/player detours are installed only after that phase becomes quiescent.
  This removes the alpha.27 race where Endurance modified game code before
  JMV `AddonMain` had applied its own startup patches. That ordering fault is
  consistent with the menu MOB subsequently failing to resolve JMV prototypes
  such as `WolfGreyF10`.
- Patch-phase readiness is observed from the owned `game.exe` executable image;
  JMV addon/ASI hashes are still not runtime-manifest dependencies.
- The unfinished environment, weather, sky, light, and shadow prototype is
  reverted. Approved database-driven humanoid visuals, equipment, animation,
  texture decoding, and renderer optimizations remain.

Focused validation:

1. With global Starter values pointing at installation A, select the JMV profile
   under installation B and run Test Current Map.
2. Confirm the splash/content belongs to B and `runtime.log` contains
   `STARTER_ROOT_OVERRIDE`; any stale request must be followed by
   `JMV_ROOT_REDIRECT` to B.
3. Confirm `runtime-host.log` reports the completed JMV executable patch phase
   before `bridge-result.log` reports active engine detours. The test must reach
   gameplay without a prototype lookup failure.
4. Change Game & Mod Setup while a dirty MOB is loaded. Cancel must retain the
   old setup and workspace; accepting the close/save flow must unload everything
   and refresh Maps & Collections for the new root.
5. Restart with the environment options previously disabled. The viewport must
   render normally without the black-screen regression.
