# EI Mapper: Endurance Edition 0.2.1-alpha.30

## Runtime ownership and Hot Reload

- The owned x86 host now writes `game.pid` as explicit ASCII. The editor also
  accepts alpha.29's UTF-16LE-without-BOM PID journal for clean recovery.
- A separately launched `game.exe` no longer blocks Test Current Map or claims
  ownership for an empty/legacy recovery journal. Recovery requires the
  journal's live recorded PID or the complete guarded process identity.
- Focused launcher tests pass while an unrelated game process is running.
- The exact Test Current Map dependency contract is documented in
  [`../TEST_CURRENT_MAP_DEPENDENCIES.md`](../TEST_CURRENT_MAP_DEPENDENCIES.md).
  Only the selected profile's approved `game.exe` is an Endurance manifest
  component. JMV addons and SpellAddon remain gameplay components rather than
  bridge-delivery gates; `AutoRunSpellAddon123.mob` is required only for Play
  from Here, Godmode, or explicit supplemental-MOB bootstrap commands.

## World Object to Lever

- `Edit > Object > Convert World Object to Lever...` is available for exactly
  one selected basic world object in the active MOB.
- The dialog exposes the proven lever fields before conversion and warns if the
  object's NID appears in the active MOB script.
- Conversion replaces only the raw `OBJECT` envelope, inserts the six standard
  lever fields, and changes `OBJTYPE` 54 to 60. All existing common and opaque
  child records remain byte-identical and in their original order.
- Conversion is one undo/redo command. Save uses the lossless raw structural
  replacement path and never falls back to the legacy rebuilding serializer.
- Known alpha.30 limitation: the first build accepted only `OBJTYPE 54` even
  though valid `OBJECT` records also use types 53 and 55. This is corrected in
  the next build; alpha.30 itself rejects those objects before mutation.
