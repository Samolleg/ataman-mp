# 0.2.1-alpha.10: generation reload and recovery test

This build replaces the rejected persistent test-save model with disposable,
generation-scoped saves. In-game Save, Load, and Main Menu remain available.
The live JMV campaign-save directory is still redirected and must remain
unchanged.

## Implemented

- Initial Ctrl+F5 uses `generations/000000/saves` inside its test-run folder.
- Every hot reload stages an immutable next generation with an empty save
  directory. The bridge switches save paths on the game thread immediately
  before starting the reload transition.
- Failed staging retains the active generation. Once transition begins, the new
  empty namespace remains active because the runtime state is uncertain.
- Protocol v2 records the generation, save path, source/target zone, bootstrap
  mode, and latest observed runtime-state sequence.
- The exact JMV runtime has guarded states for initialization, Main Menu,
  gameplay, inventory, store, transition, and unknown state. Unsafe transient
  states defer the newest request.
- Startup recovery identifies an owned game by PID, executable path, creation
  time, and SHA-256. A surviving orphan is monitored but never attached to or
  killed. Dead runs are cleaned with hashes; externally changed artifacts are
  retained and reported.
- Recovery journals are written before generation directories or live aliases.
  Disposable save generations are removed only after the game exits.

## Focused runtime test

Use only disposable edits. After every test, open the test-run folder through
the editor's quick-access link and retain `manifest.json`, `runtime.log`, and
`bridge-result.log` if behavior differs from the expected result.

1. Launch a map. Save twice, load each save, return to Main Menu, and load the
   same generation again.
2. Hot reload from gameplay. Load must show no saves from generation `000000`.
   Create and load a new save in generation `000001`.
3. Press Ctrl+F5 from Main Menu, inventory, and store. Expected: controlled
   rebootstrap into the staged map, not a frozen overlay or unsafe direct call.
4. Press Ctrl+F5 during a zone transition/loading screen. Expected: the request
   waits until a stable state, then only the newest queued request runs.
5. Test from the world map. This is an observation probe: `WorldMapReady` has no
   proven exact-hash provider yet. Preserve logs whether it succeeds, defers, or
   times out; do not treat it as validated in this build.
6. Close Endurance through Task Manager while its test game remains open.
   Restart Endurance: Test Current Map stays unavailable for that orphan, the
   game continues, and cleanup runs automatically after normal game exit.
7. Force-close both processes, restart Endurance, and confirm startup cleanup.
   Live JMV maps, `plugin.dll`, configuration, and campaign saves must match
   their pre-test inventory.
