# 0.2.1-alpha.8 outliner filter validation

## Changes

- The object outliner now has a debounced search field and live match count.
- Bare text fuzzy-searches object name, NID, type, model, texture,
  database/prototype, active MOB name, and validation state.
- Field queries are available for `name:`, `id:`/`nid:`, `type:`, `model:`,
  `texture:`, `db:`/`database:`/`prototype:`, `mob:`, and `validation:`.
- Multiple terms are AND-combined. Double quotes preserve a phrase.
- The current object selection is not changed by filtering. Clearing the query
  restores the expansion state captured when filtering began.
- Property edits, undo, and redo immediately re-evaluate an active filter.

## Focused checks

1. Open a large MOB such as Zone 18 and enter `unhufe`. Confirm every visible
   result contains that value in one of the supported fields and the viewport
   remains responsive.
2. Try `model:unhufe`, `type:unit`, an exact `id:`, and two combined terms.
3. Select an object, filter it out, then clear the filter. The viewport
   selection must remain unchanged.
4. Collapse several groups, filter, then clear. Their previous expansion state
   must return.
5. While a `model:` or `texture:` filter is active, edit the matching property,
   then undo and redo it. The visible result set and count must follow the data.
6. With family validation findings present, check `validation:critical` and
   `validation:warning`.

The application was compiled with Qt 5.12.12 / MinGW x64 without launching the
GUI. Existing compiler warnings are unchanged.
