# 0.2.1-alpha.5 runtime-family ID validation

This focused build introduces parser-backed runtime-family ID validation. It is
intentionally warning-heavy so the first UX pass can reveal which findings are
useful and which should later be downgraded or moved into the log.

## What is new

- Runtime families start from `map.txt` or an explicit collection and follow
  transitive `AddMob(...)` script dependencies.
- The MOB Family Validation dock lists family membership, missing/dynamic
  dependencies, effective ranges, out-of-range objects, range overlaps, and
  actual cross-file/intra-file NID collisions.
- Direct ID edits show the current object/range owners but remain allowed.
- Create, paste, and duplicate allocate against the combined family ID map.
  Fully shared legacy ranges remain usable after a warning.
- Save, Save As, Save All, Test Current Map, and hot reload perform a fresh
  consolidated preflight but are never blocked by ID/range findings.
- Tools provides current-MOB, selected-files, and active-family validation.
- Review and Repair NID Collisions offers deterministic range-aware IDs. It
  changes nothing until Apply, preserves the mapped primary by default, and
  applies safe selected rows as one undoable action. Script or typed ParentID
  evidence requires manual resolution and disables automatic repair.

## Focused checks

1. Open Zone 7 with `zone7.mob` and `Autozone7altar.mob` (or a collection that
   resolves them). The family report should show six legacy range overlaps and
   eight critical incompatible collisions: `1000305`, `1000306`, `1000307`,
   `1000308`, `1000309`, `1000312`, `1000314`, and `1000316`.
2. Open Review and Repair. The Autozone objects should receive deterministic
   suggestions `1000321` through `1000328`; Zone 7 scenery should be unchecked.
3. Cancel and confirm nothing changes. Reopen, apply only the eight Autozone
   rows, then Undo and Redo once. Confirm the changes are one history step.
4. Save As disposable copies and test them in game. Never overwrite the
   supplied fixture during this test.
5. Copy or duplicate objects into a supplemental MOB with a shared range. Note
   how many warnings feel useful versus repetitive; all actions must remain
   available.

## Automated evidence

- Full Qt 5.12.12/MinGW x64 application build completed.
- Endurance document test suite passed after the parser additions.
- The supplied Zone 7 corpus probe resolved six family MOBs, detected all eight
  collisions and six overlaps, and produced exactly `1000321`-`1000328`.

## Known limits

- Script and ambiguous typed references are detected and shown, but this build
  does not offer per-occurrence target assignment or coordinated multi-MOB
  save cohorts yet.
- Background cancellation/caching and a frozen full 162-MOB golden manifest
  remain follow-up validation work.
