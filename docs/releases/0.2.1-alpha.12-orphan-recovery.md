# 0.2.1-alpha.12: same-session orphan recovery

Alpha.11 runtime testing successfully switched among gameplay and briefing maps,
but an editor force-close exposed a recovery race. The restarted editor detected
the verified orphaned game and disabled Test Current Map correctly. When the game
was then closed manually, Windows briefly still reported a game process while the
owned plugin remained locked. Endurance attempted recovery once, stopped its
monitor, and left the action disabled. A second editor restart performed cleanup.

Alpha.12 keeps polling while either the verified process or the short exit race
still prevents cleanup. After hash-owned cleanup succeeds, Test Current Map is
re-evaluated immediately; no map reload or editor restart is required. Startup
also offers to send a normal close request to the exact process recorded in the
recovery journal. It never attaches to or closes an unverified process, and the
prompt warns that unsaved game progress will be lost.

After a successful hot reload, Endurance now restores, maximizes, raises, and
focuses the verified owned game window.

The reported editor freeze itself produced no crash marker or dump. Its last log
entry is the start of a rapid repeated `bz8k.mob` load, so the artifact proves an
interrupted synchronous load but not its underlying cause.

## Focused retest

1. Start a test, force-close only Endurance, and restart it.
2. Choose **Leave Running**, close the game manually, and confirm Test Current
   Map becomes enabled without opening another map or restarting Endurance.
3. Repeat and choose **Close Game**. Confirm the game exits normally, cleanup
   completes, and the action becomes enabled.
4. Start another test immediately. Confirm there is no DEV Plugin collision.
5. Hot reload a different gameplay or briefing map and confirm the game window
   is maximized/focused when the reload completes.
