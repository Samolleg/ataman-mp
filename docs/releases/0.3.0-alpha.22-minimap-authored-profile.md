# EI Mapper Endurance 0.3.0-alpha.22 - authored minimap profiles

## Changelist

- Fixes the editor-only vertical presentation of both Embedded and Generated
  minimaps without changing the game-correct MMP payload orientation.
- Replaces raw unlit capture with deterministic environment diffuse shading at
  the MOB-authored zone time. Projected shadows, fog, sky, local lights,
  animation, particles, and dynamic units remain excluded.
- Enables terrain mip filtering and smooth supersample reduction, removing the
  nearest-neighbour grain that made roads, foliage, and rivers unreadable.
- Matches the resolved embedded minimap's square power-of-two size and its
  DXT1 or 8888 storage profile. With no embedded profile, JMV zone generation
  explicitly defaults to 1024 x 1024 DXT1.
- Adds a deterministic principal-axis DXT1 encoder. Existing verified archive
  create/append/confirmed-replace safety now accepts supported 64 through 2048
  pixel square MMPs.
- Preserves opaque square padding for non-square maps. No universal decorative
  border is invented: copied controls show a large authored lower pad in
  `zone5_1map` and a small authored frame in `zone12dun2map`.
- Shows resolution, codec, and embedded-profile provenance in the export review
  and viewport minimap details.

## Copied-corpus findings

Inspection used only a user-provided copied RES and ignored analysis output;
no live installation or proprietary resource was modified or packaged.

- `zone1map` is the 256 x 256 8888 exception.
- Most inspected JMV outdoor zone minimaps, including `zone2map`,
  `zone3obrmap`, and `zone4map`, are 1024 x 1024 single-level DXT1.
- `zone5_1map` is 1024 x 1024 DXT1; `zone12dun2map` is 512 x 512 DXT1.
- Regional Gipat/Ingos atlases are 2048 x 2048 DXT3 and Suslanger regional
  atlases are 512 x 512 DXT3. They are authored world-map assets rather than
  the default per-zone export profile, but disprove a universal 256 profile.

## Automated validation

- Minimap/export tests: 16 passed, covering orientation/framing, deterministic
  composition and dynamic exclusion, 256 8888 compatibility, deterministic
  1024 DXT1 encode/decode, opaque high-resolution aspect padding, safe RES
  create/append/replace/refuse, failed-save preservation, catalog gating, and
  temporary test staging.
- Clean Qt 5.12.12 / MinGW 7.3 release build completed through the documented
  ASCII `subst` path.
- Headless widget interaction and secondary-window lifecycle check passed.

## Manual acceptance cases

1. Compare Embedded and Generated in the editor for copied zone1, zone3obr,
   zone5_1, and zone12dun2 controls. Both must have the same north/south
   orientation; in-game orientation must remain unchanged.
2. With each control MOB loaded, confirm Generated reports complete MOB capture
   and includes static geometry. MPR-only must appear only after all MOB sources
   are closed.
3. Compare Generated against Embedded at 100% and equivalent in-game zoom.
   Roads, river edges, foliage, and buildings must not show the former grain.
   Confirm 256 8888 for zone1, 1024 DXT1 for common JMV zones, and 512 DXT1 for
   the inspected dungeon control.
4. Change viewport lighting mode and preview clock. Regeneration must remain
   stable because it uses MOB-authored time and environment, while
   Gipat/Ingos/cave maps retain their distinct lighting families.
5. For an 11 x 9 map, confirm the exported square texture has an opaque unused
   lower area and the active map is not stretched. Do not require a decorative
   frame when none exists in the source terrain.
6. Export to copied new, append, and replacement RES fixtures and stage each
   result for Test Current Map. Reopen and inspect dimensions, codec, and hash
   before controlled private runtime comparison.
