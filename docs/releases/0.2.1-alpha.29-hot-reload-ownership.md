# EI Mapper: Endurance Edition 0.2.1-alpha.29

Focused closed-test correction for JMV hot reload after the editor-owned
runtime-host transition.

- The Endurance launcher process is the x86 runtime host; `game.exe` is its
  owned child process.
- Hot-reload readiness already read `game.pid` and verified the bridge thread
  against the owned game process.
- The final dispatch path incorrectly repeated the check against the runtime
  host PID, so no request could be posted and no `HOT_RELOAD dispatch` marker
  appeared in alpha.28 logs.
- Readiness, dispatch, and game-window focus now use one runtime-game PID
  resolver. Base/non-hosted transport continues to use the direct process PID.
- The focused launcher regression test covers hosted PID-file resolution,
  direct transport resolution, and missing PID evidence.

Test against one currently active JMV Starter installation:

1. Launch Test Current Map and wait for gameplay.
2. Change the current MOB or load another map in the editor.
3. Press Ctrl+F5 again.
4. Confirm the staging progress appears, the existing game process remains
   active, and the runtime log records `HOT_RELOAD dispatch` followed by
   `HOT_RELOAD completed`.

Independent dual-Starter investigation remains unresolved. Alpha.28 evidence
shows that launches requiring stale absolute-path redirection are unreliable,
while matching Starter state reaches gameplay. Do not use alpha.29 as evidence
that two independent Starter roots are supported.
