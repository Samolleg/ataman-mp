# Database editor r15 tester notes

## Changed

- Replaced the eager `QTableWidget` database grid with a lazy Qt model/view.
  Sorting and filtering no longer allocate a widget item for every cell, and
  live-size refreshes now spend almost all their time publishing the database
  snapshot rather than rebuilding the grid.
- Established reference fields use searchable editable pickers. Referenced
  cells are visually marked and can open their target row from the context menu
  or with Ctrl+Enter.
- `Monster Prototypes.Base Race` links to `Race Models`. The mapping is checked
  against a real exported database; legacy missing race rows remain warnings,
  not blockers.
- Repeated categorical text values (type, class, material, terrain, damage,
  target, and school fields) receive editable suggestions without restricting
  the source database's accepted values.
- Clone refreshes and reselects the new row without rebuilding the table twice.
- Cross-table validation now indexes identities once, avoiding repeated
  full-table scans and false mismatches between physical row keys and display
  identities.

## Manual checks

1. Open Monster Prototypes, double-click a Base Race cell, and confirm the
   searchable picker appears and accepts a race.
2. Right-click that cell and choose `Open Referenced Row`; confirm the editor
   switches to Race Models and selects it.
3. Clone a monster row and confirm the new row appears promptly and remains
   selected.
4. Search and sort a large table, then edit a normal and a long structured
   value; confirm undo/redo and live unit updates still work.

## Known limitation

Only identity-compatible relationships are exposed as row links. Compound
spell expressions and transformed-name relationships are not mislabeled as
direct references; they remain editable and receive suggestions only where the
field meaning is established.
