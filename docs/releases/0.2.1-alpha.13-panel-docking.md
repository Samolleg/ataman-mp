# 0.2.1-alpha.13: validation responsiveness and modular panels

Alpha.13 collects the post-alpha.12 editor-side fixes into one focused test
build.

- Automatic family validation no longer computes replacement IDs for every
  visible collision. Explicit Review and Repair remains the only place that
  performs range allocation.
- Repeated validation requests are coalesced, stale results are discarded, and
  map/collection loading reports blocking progress instead of resembling a
  frozen editor.
- A completed map switch refreshes the map/test identity before validation, so
  mutually exclusive MOB families are not combined accidentally.
- Missing `AddMob(...)` dependencies explicitly say that the target MOB file
  was not found and identify the referring MOB path, script line, and exact
  expression.
- Object Outliner and Object Properties are independent docks, initially
  arranged as a vertical column on the right edge.
- History is now dockable. History and MOB Family Validation retain detached
  use with native minimize/maximize/close controls.
- Maps and Collections, Object Outliner, Object Properties, History, and MOB
  Family Validation can all be restored from **View** after being closed.

## Focused test

1. Confirm Outliner and Properties start docked on the right and can be moved,
   detached, redocked, closed, and restored from View.
2. Open History and MOB Family Validation. Confirm both detached windows expose
   normal minimize, maximize/restore, and close controls and can also be docked.
3. Rearrange the panels, restart Endurance, and confirm layout/visibility state
   persists.
4. Open Zone 14 and confirm the incomplete-family entry states that
   `Autozone14dm4.mob` was not found and points to `zone14.mob` script line
   1646.
5. Switch repeatedly between large Zone 19 map/briefing pairs and confirm the
   editor remains responsive and does not combine the previous family with the
   newly loaded one.
