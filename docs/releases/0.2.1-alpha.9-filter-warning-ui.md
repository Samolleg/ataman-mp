# 0.2.1-alpha.9 filter and validation-warning UI

## Changes

- Outliner search now uses contiguous, case-insensitive matching by default.
  A bare `unhufe` query must occur as one sequence in a searchable field.
- `id:123` requires the contiguous sequence `123`, so values such as `1293`
  and `1623` no longer match.
- `field=value` requests an exact case-insensitive match; `id=123` matches only
  NID 123.
- The earlier subsequence-fuzzy search remains available explicitly with `~`,
  for example `~unhufe`, `model:~unhufe`, or `id:~123`.
- MOB-family warning summaries keep the icon at its normal width, align the
  first three findings to the left, and truncate each line to the available
  width. The full report remains in the validation panel and workflow log.

## Focused checks

1. In Zone 1, enter `id:123`. Every result must contain the consecutive text
   `123`; `1293` and `1623` must not appear.
2. Enter `id=123`; only NID 123 may match. Enter `id:~123`; the deliberately
   broad subsequence results may appear again.
3. In Zone 18, enter `unhufe`. ID 203 must not appear unless one of its indexed
   fields literally contains `unhufe`. Enter `~unhufe` to request fuzzy search.
4. Trigger a MOB-family warning. Verify three concise, left-aligned one-line
   findings followed by `...`, with both buttons fully visible.

The application is compiled with Qt 5.12.12 / MinGW x64 without launching the
GUI during the build.
