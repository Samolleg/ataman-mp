# Отдельные задачи и параллельная работа в Ataman

Этот документ не разрешает самостоятельное делегирование. Отдельная
пользовательская задача и подагенты требуют соответствующей просьбы владельца.

## Отдельная пользовательская задача

1. Найти сохранённый проект с корнем ei-mapper-ataman. Исходный Endurance и
   родительская папка maped не являются заменой.
2. Если проекта нет, попросить владельца открыть/добавить папку Ataman.
   Не создавать работу в другом проекте ради обхода отсутствующего проекта.
3. Проверить назначенную базу; по умолчанию это принятый локальный main —
   текущей линии. В исходном локальном репозитории историческая основа —
   19168b91a10562525fb6c83b665275c2fd43cf4c; в GitHub-клоне используют SHA
   очищенной линии по docs/COAUTHOR_HANDOFF.md. Сообщить полный исходный SHA.
4. Создать явно запрошенную задачу в checkout Ataman на main. Отдельную ветку
   или worktree не создавать; проверить путь и HEAD. При непересекающихся
   заданиях использовать согласованный порядок записи в общий main.
5. Незакоммиченные изменения включать только по явному поручению владельца.

## Ограниченные подзадачи

При разрешённом делегировании назначать непересекающееся владение файлами.
Подагенты могут разделять файловую систему; same-directory fork не изолирует
параллельные правки. Не заменять подзадачу новым пользовательским тредом без
просьбы. При отсутствии безопасной изоляции работать последовательно.

## Содержание поручения

- задача, ожидаемый результат и границы;
- точный путь, исходный SHA и единственная рабочая ветка main;
- права чтения отдельно от запрета изменения живых данных;
- владение файлами и сохранность чужой работы;
- тесты, локальный коммит, ручные пробелы;
- конкретные сетевые полномочия; по умолчанию без remotes, fetch/pull/push,
  PR и публикации, если человеческое поручение не разрешило их явно;
- «сделай коммит» означает scoped-коммит в main; «отправь на GitHub» —
  обновление GitHub main, без отдельного разрешения на интеграцию;
- соблюдение docs/TEST_BUILD_HANDOFF.md.

## Передача результата

Передать полный SHA main, тесты и ограничения. Работу и scoped-коммиты выполнять
в main с проверкой исходного случая и регресса. Публикация по поручению
«отправь на GitHub» обновляет main. Не сбрасывать main и не угадывать конфликты,
не удалять worktree после завершения без разрешения.
