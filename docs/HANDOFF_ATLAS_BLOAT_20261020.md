Журналы: `artifacts/EI-Mapper-Ataman-2-first-test/logs/workflow*.log`. Число страниц атласа видно по строкам `MPR terrain atlas complete file:<map> textureCount:N`.

**История zone2:** 8 → 13–16 → 22 (17.10 23:03) → **85 (17.10 23:09)** → 19 после сжатия.

Скачок каждый раз совпадает с функцией **«Перевести базовые тайлы в HD»** (кнопка в «Дополнительно»; код `source/render/view_base_hd.cpp`, `source/render/terrain_base_hd.cpp`; введена в 190 `fb16fe8a` «Add base-only HD tile conversion with preserved native pages», доработана в 195 `09195d83` и 196 `87fa0825`):

Русский текст в журнале записан в неверной кодировке (бывший UTF-8 испорчен до «�»). Строку сводки см. в `view_base_hd.cpp:88`: «Заменено клеток: %1. Исходных тайлов: %2. HD-вариантов в наборах: %3…».

**Механизм.** Это гипотеза по коду и журналам, подтвердить на копии.
1. Перевод базовых тайлов в HD **импортирует в атлас карты целые наборы HD-вариантов** (`plan.importedVariants`): все варианты всех затронутых материалов, а не только те, что ставятся в клетки. Отсюда тысячи слотов, из которых SEC использует малую часть.
2. **Исходные native-страницы сохраняются** («preserved native pages», ради стыков). Старые 128-px страницы остаются в атласе рядом с HD.
3. **Повторный запуск снова добавляет наборы:** у zone2 сначала +376, потом +3 988. Похоже, уже импортированные варианты не переиспользуются, и неиспользуемые слоты не вычищаются ни при запуске, ни при сохранении.
4. **Публикация пишет в исходный namespace без hash.** У zone2 и gipat1 расширенный атлас лежит прямо в namespace `zone2` / `gipat1`. То есть публикация расширяла исходный (stock) атлас, хотя должна была создать свой опубликованный namespace. Это отдельный риск: исходные namespace — ещё и HD-источники маппера и, возможно, общие для других карт или профиля Base. Сжатие 208 их не удаляет, поэтому старые страницы `zone2` остались в паке, и пак после сжатия **растёт**: новый компактный namespace добавляется рядом.

**Механизм подтверждён по `source/render/terrain_base_hd.cpp`:**
- **стр. 211–221:** для каждого используемого слота импортируются HD-якорь и все его варианты, а также все прочие исходники того же материала с тем же краем и все их варианты. Импортируются целые наборы.
