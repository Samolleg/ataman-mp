# Задание для Codex соавтора

Для составного задания заполните относящиеся поля; короткому поручению не нужна
полная анкета. Объём и разрешения определяет поручение пользователя, пример ниже
сам по себе ничего не разрешает. Если задача не выбрана, ограничьтесь проверкой
окружения и нужных документов.

```text
Работай в проекте EI Mapper Ataman, приватный репозиторий Samolleg/ataman-mp.
Корень моего checkout: <абсолютный путь на МОЁМ компьютере>.
Проверь актуальность AGENTS.md и прочитай изменённые или недостающие правила.
Из ROADMAP прочитай текущий пункт и открытые зависимости. CONTRIBUTING.md задаёт
порядок; COAUTHOR_HANDOFF нужен для первого входа, PROJECT_CONTRACT — для данных,
TEST_BUILD_HANDOFF — для сборки/передачи. Не перечитывай неизменный контекст.

Основная задача и ID: <ID существующего пункта либо новый согласованный ID>.
Исходная проблема: <что происходит, шаги, карта/профиль, ссылка на свидетельство>.
Ожидаемый полный результат: <что пользователь сможет сделать>.
Критерии завершения: <воспроизведение, регресс, ручные/игровые проверки>.
Границы: <затрагиваемые области и файлы; что остаётся вне этой задачи>.

База: <полный SHA очищенной линии, согласованный с сопровождающим>.
Работай только в main от проверенной базы; новые рабочие ветки не создавай.
Не импортируй исходную неочищенную историю владельца или более новый Endurance.
Перед изменениями проверь путь, HEAD и затронутые файлы; VERSION — для выпуска, remotes — для сетевых действий.
Исторические SHA и абсолютные пути в старых отчётах не подставляй как мои.

Разрешаю: <например: код в указанной области, необходимые тесты,
локальный scoped-коммит; явно укажи, нужна ли сборка>.
Сетевые действия: <без сетевых действий / только clone или fetch указанного
репозитория / отправить согласованный результат в GitHub main>.
«Сделай коммит» означает scoped-коммит в main; «отправь на GitHub» означает
обновить GitHub main. Отдельное разрешение на интеграцию не требуется.
Установка зависимостей: <не разрешена / конкретный согласованный набор и путь>.
Разрешённые данные: <источники и границы; дополнительные источники согласовать>.
Необходимые приватные тестовые копии этих данных входят в задачу без повторного
согласования. Изменяющие тесты — только на копиях вне живой установки, Git и пакета.
Живые карты, мод и установку игры не изменяй без отдельного разрешения.
Сборка/передача: <не нужна / подготовить по docs/TEST_BUILD_HANDOFF.md>.
Путь к моей постоянной установке: <по умолчанию artifacts/
EI-Mapper-Ataman-2-first-test относительно моего checkout либо согласованный путь>.

Для дефекта установи исходный случай и причину; если воспроизведение нестабильно
или недоступно, используй имеющиеся свидетельства и конкретные гипотезы.
Для новой функции определи ожидаемый сценарий. Проверь исходный случай и связанный
регресс. Не повторяй успешную проверку на тех же входах без новых оснований.
Не ослабляй проверки ради PASS; важный SKIP/сбой/недоступную приёмку укажи явно
и продолжай независимую разрешённую работу. Сохраняй чужие изменения; приватные
данные/код, сборки, настройки и логи в Git не переносятся.

Для длительной работы веди текущий пункт ROADMAP, обновляя его по существенным
изменениям; небольшой самостоятельный вопрос не требует отдельной записи.
Основную цель не заменяй последним симптомом. Для отдельной правки программы или
функции согласуй следующий VERSION и обнови CHANGELOG; одни документы и повторная
сборка номер не увеличивают. По достаточному результату переходи к следующему
разрешённому этапу либо заверши запрос.
Не создавай новые чаты или подагентов без моего явного поручения.
Не открывай редактор/игру вместо меня для ручной приёмки.

В итоге сообщи результат, существенные проверки и реальные ограничения.
Для коммита/сборки укажи ветку, полный SHA, применимые VERSION и путь; exit codes
и подробные результаты можно дать ссылкой на evidence. Подготовку, установку
и ручную/игровую приёмку различай; пустые технические поля не нужны.
```

Сопровождающий и соавтор согласуют спорный объём задания до зависимых действий.
Чтение документов, проверка локального статуса и подготовка плана не требуют
повторного подтверждения уже полученного поручения. Доступ GitHub и одно
предыдущее разрешение на публикацию не означают автоматический push при каждом
коммите. Поручение «отправь на GitHub» уже разрешает обновление main.
