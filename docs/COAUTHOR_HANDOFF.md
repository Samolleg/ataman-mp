# EI Mapper Ataman: вход соавтора в проект

Дата передачи: 2026-10-01. Руководство рассчитано на другой компьютер и новый
контекст Codex. Оно дополняет действующие договоры; каноническая дорожная карта
остаётся в [ROADMAP.md](../ROADMAP.md).

## 1. Что передаётся

Приватный репозиторий: [Samolleg/ataman-mp](https://github.com/Samolleg/ataman-mp).
Версия приложения на момент подготовки — **88**. Последняя опубликованная база
перед этой документацией: `7ecf7933c777427746b3585d1679828d1c328b08`, ветка `main`.
Это зафиксированная точка передачи, не обещание, что она всегда будет последней.
Перед новой работой сопровождающий назначает актуальную базу.

В GitHub находится очищенная история исходников. SHA из старых локальных
отчётов могут отсутствовать в клоне: фильтрация игровых файлов изменила цепочку
коммитов. Не требуется получать старый локальный репозиторий, повторять очистку
или искать исходный `19168b91...`. Старые отчёты сохраняют смысл как исторические
свидетельства, но команды checkout выполняют только для существующей принятой базы.
Правила состава: [PUBLISHING_SOURCE.md](PUBLISHING_SOURCE.md).

В клоне есть C++/Qt-код, интерфейсы, переводы, тесты, скрипты, лицензии и встроенные
служебные ресурсы редактора. Нет установленной игры, карт MOB/MPR/GRP, игровых RES,
готовых EXE/DLL, личных настроек, Qt/MinGW или Visual Studio. Исключение RES —
публичный служебный `assets/resources/auxData.res`, необходимый для QRC приложения.
Внешние игровые данные настраиваются локально; их нельзя коммитить или загружать.

## 2. Что прочитать и кому принадлежат решения

При первом входе прочитайте актуальные полномочия и относящиеся договоры;
при продолжении перечитывайте только изменённый или недостающий контекст:

1. [AGENTS.md](../AGENTS.md) и [CONTRIBUTING.md](../CONTRIBUTING.md): рабочий процесс.
2. [ROADMAP.md](../ROADMAP.md): текущий пункт и открытые зависимости, не весь журнал.
3. Для данных — [PROJECT_CONTRACT.md](PROJECT_CONTRACT.md).
4. Для сборки/передачи — [TEST_BUILD_HANDOFF.md](TEST_BUILD_HANDOFF.md) и нужные
   команды [BUILDING_ENDURANCE.md](BUILDING_ENDURANCE.md).
5. Для публикации — [PUBLISHING_SOURCE.md](PUBLISHING_SOURCE.md).
6. Для запрошенной параллельной работы — [PARALLEL_THREAD_WORKERS.md](PARALLEL_THREAD_WORKERS.md).

Новое сообщение само по себе не требует повторного чтения. Длительная работа
ведётся в существующей карте; небольшой самостоятельный вопрос — в разговоре.

Сопровождающий проекта согласует базу и номера версий нескольких участников.
По решению владельца 2026-10-03 единственная рабочая ветка — main.
«Сделай коммит» означает коммит в main, «отправь на GitHub» — обновление GitHub
main; отдельное разрешение на интеграцию не требуется. Соавтор ставит своему Codex конкретную
задачу, разрешённые действия и пути на своём компьютере. Доступ к приватному
репозиторию не означает автоматического разрешения агенту на push/PR/merge,
установку зависимостей, изменение живых карт или приглашение других участников.
Уже явно разрешённые действия не требуют повторного согласования.

Работа с обычным кодом возможна без приватных источников. Если задача зависит
от неизвестных правил закрытого движка и соответствующие навыки/разрешения
недоступны, фиксируйте эту границу и продолжайте независимые части; не переносите
чужие приватные исходники в этот проект. Чтение разрешённых установленных данных
не является разрешением на их автоматический ремонт.

## 3. Начало на другом компьютере

Владелец должен отдельно предоставить человеку доступ к приватному репозиторию.
Войдите в GitHub своей учётной записью обычным способом, без обмена токенами
в чате или файлах проекта. При явно разрешённом получении исходников клонируйте
`https://github.com/Samolleg/ataman-mp.git` в свою папку, например `C:\dev\ataman-mp`.
Этот путь — пример, а не обязательная установка. Откройте эту папку как проект Codex.

До правок выполните локальную сверку:

```powershell
git rev-parse --show-toplevel
git status --short
git branch --show-current
git rev-parse HEAD
git remote -v
Get-Content -LiteralPath VERSION
```

Сравните origin с ожидаемым приватным адресом и запишите полный SHA в свою задачу
ROADMAP. Fetch/pull делают только в пределах поручения; не обновляют базу
самостоятельно посреди реализации. Проверяют незакоммиченные файлы до переключения.
Согласованную реализацию выполняют непосредственно в main от проверенного SHA;
новые рабочие ветки не создают. Не выполняют reset --hard, force push
и не подтягивают более новый Endurance как «обновление» Ataman.

Личные абсолютные пути из отчётов владельца не являются обязательными.
Настройте собственные пути к игре/моду через интерфейс профиля редактора.
Перенос чужого `endurance-options.json` может направить запись в неверную игру.
`model-catalog.json` с русскими именами/связями текстур — пользовательские данные
рядом с активным `database.res` профиля; их передача и изменение требуют своего
поручения, в Git/чистый пакет их не включают. Атласы черновиков и готовых карт
используют `HDPack_Terrain.res` по действующей реализации и профилю.

## 4. Сборка

Проверенный исходный стек: **Windows x64, Qt 5.12.12 win64_mingw73, MinGW 7.3 x64,
qmake, C++11**. Qt-модули перечислены в `ei_maper.pro`, включая OpenGL, Concurrent,
Multimedia и gui-private. Для полного release-wrapper также нужны **Visual Studio
2022 C++ tools, Windows SDK и x86 compiler**: runtime bridge/host собираются
отдельно как 32-битные компоненты. Это не переход основного приложения на MSVC.
Другие ОС/Qt6/другой компилятор не являются проверенной заменой.

Сначала найдите уже установленные инструменты; Git-клон не содержит `.tooling`.
Настройку отсутствующих зависимостей выполняйте только в согласованном окружении,
по [BUILDING_ENDURANCE.md](BUILDING_ENDURANCE.md). Не изменяйте общий Endurance-kit.
Пути можно передать явно или через process environment:

```powershell
$env:EI_MAPPER_QT_BIN = 'C:\Qt\5.12.12\mingw73_64\bin'
$env:EI_MAPPER_MINGW_BIN = 'C:\Qt\Tools\mingw730_64\bin'
# Для нестандартного пути VS укажите существующий VsDevCmd.bat:
$env:EI_VS_DEV_CMD = 'C:\Program Files\Microsoft Visual Studio\2022\BuildTools\Common7\Tools\VsDevCmd.bat'
$env:PATH = "$env:EI_MAPPER_QT_BIN;$env:EI_MAPPER_MINGW_BIN;$env:PATH"
& "$env:EI_MAPPER_QT_BIN\qmake.exe" -query QMAKE_SPEC
& "$env:EI_MAPPER_QT_BIN\qmake.exe" -query QT_INSTALL_PREFIX
& "$env:EI_MAPPER_MINGW_BIN\mingw32-make.exe" --version
```

Значения выше заменяют фактическими путями. QMAKE_SPEC должен быть `win32-g++`.
Если установка VS не BuildTools, не оставляйте примерный путь. Оба build-x86.cmd
поддерживают `EI_VS_DEV_CMD`; wrapper передаёт окружение дочерним процессам.

Для согласованной сборки из корня checkout:

```powershell
.\scripts\build_release.cmd -BuildDirectory build-release-88-coauthor
if ($LASTEXITCODE -ne 0) { throw 'Release build failed' }
& '.\build-release-88-coauthor\release\EIMapperEndurance.exe' --version
if ($LASTEXITCODE -ne 0) { throw 'Version check failed' }
```

Используйте актуальный VERSION и новую build-папку для новой версии/проверки,
не перезаписывая чужой build. EXE по-прежнему называется `EIMapperEndurance.exe`.
Wrapper пересобирает runtime-компоненты и кладёт их в `release/runtime`.
Нельзя заменить это копией старого bridge/host. Ошибка `Qt5OpenGL.dll` или
`0xC0000135` обычно означает неполный PATH/runtime; наличие одного EXE не является
готовой сборкой. Для проверки raw EXE нужен корректный Qt/MinGW PATH, для передачи
пакета — `windeployqt --release --compiler-runtime` и договор упаковки.

## 5. Проверки и отсутствующие fixtures

Тесты запускают отдельно от пользовательской установки, в своих рабочих
каталогах. У Qt5 Windows-проверок должен быть штатный Windows plugin;
произвольное переключение на `offscreen` не является эквивалентной UI-проверкой.
Не открывайте редактор/игру для ручной приёмки вместо пользователя.

| Изменяемая область | Начальные проверки по текущему коду |
|---|---|
| Свойства, модели, текстуры, поиск | `--profile-model-catalog-check`, `--model-gallery-check`, `--ui-widget-check` |
| Создание объектов, ID, копирование | `--database-creation-check`, `--ui-widget-check`, `duplicate_id_report_tests` и document-тесты по затронутому пути |
| Тема, иерархия, вращение | `--dark-theme-check`, `--ui-widget-check`; исходный жест проверяется отдельно |
| Сценарий/переходы | `--scenario-layer-check`, профильные/document/runtime-тесты по изменению; отдельно открытие и закрытие панели |
| MPR/MOB/RES, рельеф, сохранение | Соответствующие document-тесты, roundtrip, save/reopen, undo/redo и проверки соседних карт |
| Упаковка | Финализатор на новом staging уже вызывает `validate_distribution.ps1`; успешный результат засчитывается без отдельного повтора на неизменном пакете |

Это ориентир, а не обязательный полный прогон для любой текстовой правки.
Параметры EXE сверяют с `source/app/main.cpp`. Не каждый набор автономен:
некоторые читают профиль, игровые файлы или runtime. Часть исторических fixtures
удалена только из публикации, их проверки остались в коде. Например,
`endurance_document_tests` поддерживает `ENDURANCE_CHEST_FIXTURE` и
`ENDURANCE_MPR_SAVE_FIXTURES`; перед назначением пути прочитайте конкретный тест.
Необходимые тестовые копии уже разрешённых данных входят в согласованную задачу;
дополнительное разрешение на них не нужно. Храните их приватно вне живого мода,
Git и пакетов; контролируйте исходную identity и изменяйте только копии. Новые
источники/объём согласуйте. Отсутствующие fixtures не возвращайте в Git и не
ослабляйте проверки ради PASS.

qmake-наборы из `tests/*.pro` собирают в отдельных shadow-каталогах. Пример
для автономного теста ID из корня checkout при настроенном PATH:

```powershell
$repoRoot = (Get-Location).Path
$testBuild = Join-Path $repoRoot 'build-tests-coauthor-ids'
if (Test-Path -LiteralPath $testBuild) { throw 'Choose a new test directory' }
New-Item -ItemType Directory -Path $testBuild | Out-Null
Push-Location $testBuild
try {
    & "$env:EI_MAPPER_QT_BIN\qmake.exe" (Join-Path $repoRoot 'tests\duplicate_id_report_tests.pro') CONFIG+=release
    if ($LASTEXITCODE -ne 0) { throw 'qmake failed' }
    & "$env:EI_MAPPER_MINGW_BIN\mingw32-make.exe" -j4
    if ($LASTEXITCODE -ne 0) { throw 'Test build failed' }
    & '.\release\duplicate_id_report_tests.exe'
    if ($LASTEXITCODE -ne 0) { throw 'ID test failed' }
} finally { Pop-Location }
```

Отсутствующие данные/EXE/зависимости, timeout, SKIP и ошибка сборки не являются
PASS. Для выполненных проверок сохраните результат и существенные ограничения;
exit code, PASS/FAIL/SKIP, source SHA, toolchain и профиль — в применимом evidence.
В итоговом сообщении достаточно результата и ссылки на детали. Выбирайте регресс
по изменению; не повторяйте успешный набор на тех же входах без новой причины.
Недоступная обязательная проверка остаётся открытой, независимая работа продолжается.

## 6. Карта кода

| Каталог/файл | Назначение |
|---|---|
| `source/app/main.cpp`, `main_window*.cpp` | Запуск, команды проверки, окно и связи панелей |
| `source/app/operationmanager.*`, `source/core/undo.*` | Режимы действий и история undo/redo |
| `source/layout_components/tablemanager.*`, `dynamiccombobox.*` | Свойства и выбор моделей/текстур |
| `source/layout_components/tree_view.*` | Иерархия объектов |
| `source/documents/technical_model_catalog.*`, `source/ui/model_gallery*` | JSON-каталог и витрина моделей |
| `source/documents/` | MOB/MPR/RES, транзакции, сохранение, графы, мировые сессии |
| `source/render/`, `source/documents/world_terrain_*` | Вид, кисти/полотно соседних карт, отображение рельефа |
| `source/resources/` | Профили, RES-индексы, база и разрешение ресурсов |
| `source/mob/`, `source/objects/` | MOB, поведение, свойства типов объектов |
| `source/ui/` | Панели, диалоги, виджеты и тема |
| `source/runtime/` | Изолированный запуск игры, bridge/host и владение процессами |
| `tests/`, `source/app/*_check.*` | Отдельные наборы и встроенные проверки EXE |
| `scripts/`, `packaging/`, `translations/` | Сборка, упаковка и локализация |

Начинайте от обработчика реального действия и ищите первое неверное состояние;
имя файла само по себе не устанавливает причину. Не смешивайте данные документа
с UI-кэшем, профильными ресурсами и владением игровым процессом.

## 7. Состояние на момент передачи и незакрытые проверки

Последняя версия88 устраняет измеренную задержку выбора объекта: на синтетическом
наборе 7164 текстур/493 модели проверены реальные вызовы выбора, медиана около
20 мс. Файлы MOB при обычном выделении не пересканируются. Свидетельства:
[исправление88](validation/ATAMAN_SELECTION_PERFORMANCE_88_20261001.md).

В [распространении88](validation/ATAMAN_DISTRIBUTION_88_20261001.md) пакет и хеши
проверены, scenario — 50 PASS/0 FAIL. Первоначально UI-check дал отказы
`selectedComponentCopy`/`numericComponentPaste`, повторные прогоны тех же исходников
прошли; причина нестабильности не установлена. Не скрывайте первый отказ и не
объявляйте проблему буфера обмена доказанно закрытой.

Интерактивный выбор на исходной пользовательской карте и игровой результат
остаются отдельными проверками. Старые пункты о патрулях, воде, сохранении,
стыках двух/трёх карт, общей кисти, переходах и переносимом запуске не закрываются
передачей документации или зелёным общим набором. Сверяйте каждый исходный случай
с ROADMAP и соответствующим отчётом. Частный ремонт zone9 и исторические хеши
конкретного мода не являются основанием ремонтировать данные соавтора.

## 8. Передача результата

Длительная или многоэтапная работа ведётся в текущем пункте ROADMAP; обновление —
при существенном изменении состояния и перед передачей незавершённой работы.
Для небольшого самостоятельного вопроса достаточно цели и результата в разговоре.
Основную цель сохранять; согласованные изменения фиксировать scoped-коммитом main.
Отдельная правка программы/функция получает следующий VERSION и CHANGELOG;
документация, аудит без исправлений и повторная сборка номер не увеличивают.
Несколько участников согласуют номера и базу; рабочие ветки для заданий не создают.

В итоге сообщить результат, существенные проверки и ограничения. Для коммита или
сборки указать полный SHA, ветку, применимую версию и путь; подробности можно дать
ссылкой на evidence. По поручению «отправь на GitHub» обновляют main очищенной линии
без отдельного запроса об интеграции. Чужие пути и приватные данные не публикуют.

Запрос runnable-сборки включает обновление одной постоянной папки по
[TEST_BUILD_HANDOFF.md](TEST_BUILD_HANDOFF.md). На другом компьютере путь считается
от своего checkout; чужие установки не трогают. Закройте запущенный редактор
перед заменой, сохраните неуправляемые файлы и проверенный откат. Финализатор
запускают только на новом собственном staging, никогда на постоянной установке.
Игровые данные/личные JSON не входят в чистый пакет; код проверки не требует
раздачи запрещённых fixtures. Другой адрес установки согласуют до замены.

Для первого задания используйте [CODEX_TASK_TEMPLATE.md](CODEX_TASK_TEMPLATE.md).
