Как готовить модели и создавать сборки в EI Mapper Ataman

Текст для передачи чату, который делает модели для «Проклятых Земель».
Сверено с реализацией Ataman 106, 4 октября 2026 года.

Твоя задача — подготовить совместимые игровые детали, из которых в маппере
можно собрать дом, ворота, ограду, мост или другой готовый комплект. Если
поручено также создать библиотечную сборку, её нужно сохранить средствами
маппера после размещения деталей. Одной Blender-сцены для этого недостаточно.

1. Что здесь называется сборкой

Есть два разных уровня:

• Игровая модель с внутренними частями: один объект маппера. Внутренние части
  модели, варианты формы и их экспорт относятся к устройству самой модели.
• Сборка маппера: несколько обычных игровых объектов, сохранённых как готовый
  комплект в каталоге. На карте такой комплект выделяется, перемещается и
  вращается целиком; его можно разобрать на самостоятельные объекты.

Коллекция Blender, объединение meshes и Blender-parenting сами по себе не
создают сборку маппера. Сборка не превращает несколько моделей в один FIG и
не объединяет их коллизии. Магнитные стыки помогают установить детали; для
сохранения сборки они необязательны, если детали уже расставлены правильно.

2. Подготовь набор модулей

До массового изготовления согласуй габариты, единицы экспортированной модели,
назначение деталей, количество объектов и бюджет треугольников. Произвольный
общий лимит полигонов этим гайдом не задаётся.

Например, для дома можно подготовить прямую стену, стену с дверью, стену с
окном, угол, пол, секцию крыши и торцевую крышу. Отдельная деталь оправдана,
если её будут независимо заменять или повторять. Не дроби объект без пользы:
каждая размещённая деталь остаётся отдельным объектом карты.

Для всех совместимых модулей соблюдай один договор:

• Одинаковые размеры соединяемых краёв и шаг повторения. Углы и крыша должны
  соответствовать той же сетке. Проверяй швы, просветы и пересечение геометрии.
• Согласованные локальные оси и понятное начало каждой модели. Запиши, где
  находится начало: например, центр основания стены. Не меняй его после
  измерения стыков без пересчёта координат стыков.
• Масштаб, поворот и смещение экспортёра учитываются одинаково для геометрии
  и точек стыковки. Blender-координаты нельзя просто объявить координатами
  маппера: сначала проверь один экспортированный образец.
• У моделей должны быть устойчивые технические имена, назначенные текстуры
  и понятные русские названия для каталога. Составь таблицу «модель — русское
  имя — текстура — габариты — назначение».
• Для модульных швов используй жёсткую геометрию. Если у модели есть варианты
  FIG8 или анимация, стыки должны оставаться на тех же местах во всех нужных
  вариантах. Маппер не хранит отдельный набор стыков на каждую форму и не
  пересчитывает их по деформированной геометрии.

Не исправляй совпадение краёв случайным масштабированием каждого экземпляра.
Масштаб X/Y/Z в свойствах нельзя считать единым геометрическим масштабом всей
сборки: он меняет параметры комплекции отдельных объектов.

Сначала сделай один асимметричный тестовый модуль: различимый левый край,
правый край и верх. Проверь его фактические оси, габариты, начало и текстуру
в маппере. Только после этого производи остальные детали по той же системе.

3. Контракт точки стыковки

Стыки хранятся в профильном model-catalog.json рядом с выбранным database.res:
в models.<идентификатор модели>.connections.

У одной модели может быть не более 128 точек. Поля каждой точки:

id       — непустой уникальный идентификатор внутри этой модели.
label    — понятная подпись, например «Правый край». На совместимость не влияет.
type     — непустой тип соединения. Для стыковки строки должны совпасть точно,
           включая регистр. Одинаковый type ставь только совместимым краям.
position — [X, Y, Z] точки в локальных координатах экспортированной модели.
normal   — направление наружу из соединяемой поверхности.
up       — направление верха соединения, определяющее поворот вокруг normal.

Все векторы содержат три конечных числа. normal и up не могут быть нулевыми
или параллельными. Для ясности задавай единичные перпендикулярные векторы.
При стыковке маппер совмещает точки, направляет normal навстречу друг другу
и согласует up. Это координаты модели, а не положение объекта на карте.

Ниже пример значения connections для стены шириной 4 и высотой 2 условных
единицы модели. Начало — в центре основания, ширина идёт вдоль X, высота
вдоль Z. Эти единицы не являются утверждением о масштабе Blender-экспортёра.

```json
[
  {
    "id": "left",
    "label": "Левый край",
    "type": "wall-w4-h2",
    "position": [-2, 0, 1],
    "normal": [-1, 0, 0],
    "up": [0, 0, 1]
  },
  {
    "id": "right",
    "label": "Правый край",
    "type": "wall-w4-h2",
    "position": [2, 0, 1],
    "normal": [1, 0, 0],
    "up": [0, 0, 1]
  }
]
```

У двух таких стен с одинаковой исходной ориентацией соединение правого края
первой с левым краем второй даёт смещение их начал на 4 вдоль X, без поворота.
Для горизонтального соединения можно использовать normal=[0,0,1], up=[0,1,0];
у ответного нижнего стыка normal направлен вниз. Конкретные координаты крыши,
углов и других деталей вычисляй по их собственной геометрии.

В Blender можно создать Empty как вспомогательные маркеры и передать таблицу
их координат и направлений. Это рабочее соглашение автора, а не встроенный
формат импорта. Автоматического импорта Blender-маркеров в маппер сейчас нет.
Не обещай, что имя Empty или его пользовательские свойства будут прочитаны.

Предпочтительный способ внесения: витрина → выбрать модель → «Точки стыковки…»
→ «Добавить» → заполнить поля → «Сохранить стыки». Точку можно поставить ЛКМ
на поверхность и уточнить численно; жёлтая стрелка показывает направление,
зелёная — верх. Подготовленный JSON-фрагмент тоже можно передать сопровождающему,
но нельзя заменять им весь существующий каталог: остальные модели, текстуры,
стыки, сборки и сведения об экземплярах должны сохраниться.

4. Собери образец на карте

1) Используй настроенный профиль с нужными моделями, текстурами и database.res.
   Размещай все детали будущей сборки в одном активном MOB. Заверши каждую
   операцию размещения перед следующими действиями.
2) Расставь основу комплекта. Для точного соединения выдели одну деталь,
   включи «Магнит», нажми G и подведи её стык к совместимому стыку соседней.
   Жёлтое превью означает захват; Tab переключает варианты. ЛКМ подтверждает,
   Esc отменяет перемещение. Если захвата нет, проверь наличие точек, type,
   координаты, направления и видимость ответной детали.
3) Проверь геометрию, текстуры и высоту всех деталей. Не рассчитывай, что
   стыковка проверяет проходимость, коллизии или игровую работу двери.
4) Сохрани MOB: для библиотечного образца нужны полные исходные записи деталей.
5) Выдели весь нужный состав, без посторонних объектов. Нажми нижнюю кнопку
   «Сборки» → «Сохранить выделенное как сборку…» и введи понятное название.
   Например: «Гипат — дом с крыльцом».
6) В каталоге назначь подходящую категорию и остров, нажми «Сохранить описание».
   После группировки снова сохрани MOB, чтобы записать сведения об экземпляре.

Допустимо от 1 до 512 деталей. Поддержаны объекты мира, рычаги, факелы, свет,
звук и частицы. Существа и ловушки с поведенческими ссылками в сборки не входят.

Для обычной статической группировки не задавай игровой Parent ID специально:
маппер хранит группу отдельно. Если настоящая игровая связь с родителем нужна,
включи родителя в состав. Ссылка на объект вне состава не переносится молча;
циклы родителей недопустимы.

Не составляй assemblies вручную только из имён моделей и смещений: этот раздел
требует полных записей объектов MOB, включая исходные байты. Создавай образец
через маппер. ID новых объектов при размещении выдаёт маппер; их не нужно
заранее назначать в Blender или копировать из исходного образца.

5. Проверь повторное размещение и редактирование

Открой «Сборки» → «Каталог сборок…», выбери образец → «Разместить сборку».
Комплект следует за курсором; ЛКМ или Enter подтверждает, Esc отменяет весь
комплект. После размещения клик по одной детали выделяет всю сборку, G переносит
её, R вращает вокруг общей оси с сохранением взаимного расположения деталей.
Ctrl+C/Ctrl+V одной выбранной сборки создаёт самостоятельный экземпляр.

Точка размещения вычисляется маппером по началам объектов: центр диапазона
X/Y и минимальный Z их мировых позиций. Это не автоматически вычисленная
нижняя грань всей геометрии. Проверь посадку фундамента, пола и крыши повторным
размещением на ровном месте и на склоне; при необходимости исправь образец.

Магнит работает с одной деталью, а не с целой сборкой. Для изменения состава
используй «Сборки» → «Разобрать выделенную сборку», отредактируй отдельные детали, выдели
новый состав и в каталоге выбери исходный образец → «Заменить состав из выделения».
Сохрани MOB после изменений. Замена библиотечного образца не обновляет
автоматически уже размещённые экземпляры.

В MOB сохраняются обычные игровые объекты. Библиотека и редакторская группировка
живут в model-catalog.json: assemblies и assemblyInstances. Поэтому передавай
нужный MOB вместе с каталогом и ресурсами. Без JSON объекты карты остаются,
но библиотека и выделение готового комплекта как группы будут потеряны.

Не считай плитку каталога окончательной проверкой: предпросмотр не полностью
воспроизводит комплекцию и дополнительные текстуры, а свет/звук/частицы не
имеют архитектурного превью. 60000 треугольников — ограничение предпросмотра,
а не разрешённый бюджет игрового ассета. Каталог ограничен 32 MiB.

6. Что передать по результату

• Исходную Blender-сцену и готовые экспортированные модели/текстуры.
• Таблицу технических имён, русских названий, текстур, габаритов, числа
  треугольников и доступных форм. Укажи принятые единицы, оси и начала моделей.
• Список стыков для каждой детали: id, label, type, position, normal, up.
• Если доступен маппер: сохранённый тестовый MOB с образцом и каталог с созданной
  записью сборки. Если доступа нет: схему расстановки с положением и поворотом
  каждой детали; явно напиши, что библиотечная сборка ещё не создана.
• Скриншоты общего вида и швов, перечень проверок и оставшихся вопросов.

Перед передачей проверь: загрузку всех моделей и текстур; совпадение двух
повторяемых модулей; соединение угла и крыши; размещение двух независимых
экземпляров; перенос/вращение; отмену размещения; разбор; сохранение и повторное
открытие MOB с восстановлением группы. Игровую проходимость, коллизии,
двери/рычаги и поведение вариантов проверяй отдельно в игре. Если такой проверки
не было, обозначь это прямо.

Источники и границы

Правила сборок: docs/OBJECT_ASSEMBLIES.md, source/documents/object_assembly.cpp,
source/render/view_assemblies.cpp, source/mob/mob_assemblies.cpp.
Правила стыков: source/documents/model_connections.cpp,
source/render/view_model_connections.cpp, source/ui/model_connection_editor.cpp.
Документ описывает обычный код маппера; недоступные в этой сессии специализированные
инструкции по моддингу и приватным источникам не использовались. Формат FIG/BON
и настройки конкретного Blender-экспортёра здесь не специфицированы. Реальные
экспортные оси и игровой результат требуют проверки на передаваемых моделях.
