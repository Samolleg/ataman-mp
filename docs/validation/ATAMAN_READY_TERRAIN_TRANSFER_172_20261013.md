# Ataman 172 — передача готового рельефа при переключении карт

Поручение13.10: внедрить подготовленную передачу готовой сцены поверх принятой171. База main `0ed00bd297ba184c3b30039cb10a57ead91fec7d`, программный коммит171 `36cfb48c6b82daba50fda7e2942d3933159db4b8`. Исправление170 было отклонено владельцем: оно сохраняло остальных соседей, но заново строило целевую и прежнюю активную карты. Текущий результат продолжает исходную задачу, сохраняя HD/resolve171.

## Механизм

- Адрес активного singleton CLandscape сохраняется. Между ним и фоновым экземпляром передаётся полный payload: существующие CSector с VBO/index buffers, таблицы, базовый/рабочий atlas texture и его lease, shadow texture/future, размеры и происхождение MPR. Raw-пointers секторов на таблицы перепривязываются без updateDrawData. Права readonly остаются у экземпляра.
- При закрытии прежнего активного MPR готовая сцена передаётся фону. При открытии готовой цели проверяются её revision, размеры, сохранённый world document и источники атласа после binding preflight. При совпадении readMap/buildLandTex/new CSector не вызываются. Изменённые источники идут обычным путём загрузки.
- Точное совпадение таблиц материалов/анимации не выставляет флаг пересборки всех секторов. Рабочая модель общей кисти восстанавливается в редакторе без повторной GPU-публикации уже отображённого рельефа/атласа. Снимок камеры и relative origins применяются согласованно; промежуточное пустое workspace не очищает последнее представление, таймер воды не перезапускается при навигации.
- Отдельная подтверждённая причина: CSector::setWorldOffset вызывал updatePosition, который выполнял allocate для буферов земли/индексов/сетки/воды. Теперь смещение меняет только model matrix и culling center на дельту; локальная геометрия, индексы, VBO и water index count сохраняются. Первичное построение и настоящие правки продолжают использовать обычную загрузку буферов.
- Revision соседей больше не включает чужой map-local override активной карты. Каждый готовый рельеф хранит фактические источники своих MMP-страниц и проверяет их изменения. Перед активацией дополнительно проверяется совпадение с binding цели.
- Ближняя/дальняя роль не удаляет готовые фоновые world objects. Чистый завершаемый CMob может передать собственные готовые обычные объекты фону после очистки Undo и проверки originalData против файла под ReadLease. Старые raw owning references удаляются, QObject parent отсоединяется, единственным владельцем становится QSharedPointer. Несохранённые отвергнутые MOB-правки не переносятся; units/helpers остаются обычной загрузкой редактора.

## Проверка и границы

Статическая проверка пути загрузки/владения и совместимости с171 выполнена; исходные черновые копии целиком не переносились. Свежий Release172 и текущие x86 runtime-компоненты собраны в `build-release-172-ready-terrain-final`, exit0 (`release-repair2.stdout.log`, `release-repair2.stderr.log`). EXE SHA256 `C3EF3B08E07ECFD65B8AAECC7F5A6B49BB5237288BC1DB13FE6BE23F9E7A4427`; CLI с явными Qt plugins/offscreen/memory clipboard сообщает `EI Mapper Endurance Edition 172`, exit0 (`version-receipt.json`). Чистый package manifest и установка проверяются следующим этапом. Ручная приёмка переключения остаётся открытой.

Начальные ошибки не названы PASS: обёртка PowerShell приняла штатный qmake stderr за исключение; два compile-прохода выявили недостающие include resource_name.h/backup_manager.h, исправленные в172. Прямые version-запуски без заданных Qt plugins/clipboard не дали корректного результата; версия подтверждена отдельным завершившимся CLI. Ни один из этих вызовов не был функциональным сценарием переключения.

По предыдущему прямому решению владельца «хватит тестов, я сам сейчас проверю» новые native/UI-сценарии и интерактивный запуск редактора здесь не выполняются. Успешная сборка и проверка пакета не будут названы подтверждением реального переключения.

1. Открыть zone1, дождаться готового рельефа соседей. Переключиться zone1→zone7→zone3obr и обратно. Уже построенные карты сохраняют рельеф и готовые фоновые объекты; камера не смещается относительно мира.
2. Повторить переход после общей правки рельефа; проверить возврат, Undo/Redo и сохранение на своей рабочей копии. Проверить сохранение HD171.

В workflow.log готовой цели и прежней активной соответствуют сообщения `Ready terrain activated without atlas/sector rebuild` и `Ready terrain retained as background without sector rebuild`; при неизменённых источниках для них не должно появляться нового `Start read terrain`.
