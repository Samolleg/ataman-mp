## Причины и исправление

1. MainWindow восстанавливал Qt dock state раньше создания TravelEditorDock и mapScenarioDock.
   Независимый исходный Qt-контроль build-audit-window-layout-89-20261002/result.log:
   restoreState возвращает true, но две сохранённые плавающие панели становятся пристыкованными;
   контроль с созданием всех dock до restore возвращает исходные размеры. Это воспроизведение,
   а не только предположение по тексту кода.
   Теперь state восстанавливается в конце конструктора, после создания всех dock, подключения
   настроек, ресурсов и обработчиков. Отдельные floating geometry/maximized/screen сохраняются
   для всех dock главного окна (QPointer-список до восстановления, включая переподчинённые плавающие группы); нативный контроллер отслеживает их состояние.
   Сохранены имена и прежние ключи раскладки/размеров, lifecycle защиты завершения.
2. Витрина, создание объекта и многие диалоги задавали размеры конструктором без сохранения
   геометрии. Части модели и дипломатия запоминали только размер. Новый WindowGeometry использует
   явные стабильные ID в QSettings ui/windows/<id>/geometry, восстанавливает при Show после
   начальных resize/layout и записывает изменения с debounce250мс. Hide фиксирует последние
   данные при Accept/Reject/Esc/Close, в том числе closeEvent с hide. Непоказанные окна не
   перезаписывают предпочтения. Развёрнутое окно сохраняет normalGeometry и состояние Qt.
   Видимые рабочие окна успевают записать геометрию до штатного закрытия приложения.
3. Покрыты витрина, создание, части модели, свойства MOB/дипломатия/диапазон ID, скрипт MOB,
   настройки, выбор объектов/статистики/случайных значений/тайлов, коллекции, сравнение MOB,
   конструктор предметов/заклинаний, база и редактор её поля/обзор, многострочное значение,
   технический просмотр текстуры, новые MPR/MOB, проверка ID, map.txt и маршруты/обратные
   переходы/глобальная карта, карты мира/их свойства/общая кисть, обзор публикации/её имя,
   преобразование прототипа и обзор изменений ресурсов. Уже существующие отдельные ключи
   геометрии каталога карт, экспорта миникарты, атласа и MPR Settings сохранены; уведомления,
   прогресс, меню и временный переключатель MOB не превращены в сохраняемые рабочие окна.
4. QRect ограничивается доступной областью существующего монитора; поддержаны отрицательные
   координаты. Floating host также проверяется при восстановлении. Диалог setup после Show
   больше не принудительно центрируется поверх восстановленной геометрии.
   Режим ландшафта остаётся закрытым на старте по прежней продуктовой политике.
5. Все headless-команды с UI имеют отдельные временные QSettings, поэтому новые geometry
   записи проверок не попадают в обычные предпочтения владельца.
