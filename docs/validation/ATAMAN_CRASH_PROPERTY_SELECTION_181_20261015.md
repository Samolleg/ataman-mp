## Подтверждённая причина

15.10.2026 в13:44:34, версия181, поток43788, read access violation `0xc0000005`, EXE offset `0x2e452c`, адрес `0x6e452c`, target0, RAX0. Стек, восстановленный из dump context/stack по Windows x64 unwind tables:

4. `COperation::mouseReleaseEvent(...)+0x20`.

`source/layout_components/tablemanager.cpp:1409` безусловно запрашивает `eObjParam_TEMPLATE` (4, поле Model) через `util::constProp`. В `source/core/utils.cpp:1163–1171` поиск отсутствующего свойства заканчивается `Q_ASSERT(false); return aProp.back();`. В Release assert отключён. При пустом списке возвращается недопустимая ссылка; копирование QSharedPointer на следующей инструкции `mov (%rax),%rdx` обращается к0. Проверка `if(modelProperty...)` находится уже после аварийного копирования и не защищает его.

Пустой список подтверждается состоянием после constProp: R10=0 (end-begin), R9=R11=`0x68c1c6b0`; fallback загружает нулевое значение перед массивом и возвращает RAX0. В восстановленном кадре CView RBX=1 — commonType `eBaseType`. `viewParameters` проверяет только непустоту выбранных типов, но не непустоту собранных свойств (`view.cpp:21474–21515`). Смешанные логические типы могут дать общий базовый тип1; их collectlogicParams отвергают такой тип и оставляют aProp пустым.

Доказанное пользовательское действие — отпускание ЛКМ в инструменте выделения и последующее обновление панели. Наиболее вероятный сценарий — смешанное выделение логических узлов без общих свойств. Конкретные выбранные узлы, Shift/рамка/точка и режим не записаны в журнал достаточно подробно, поэтому их точный состав не объявляется установленным. Последние сообщения про BatRedM7/ToadM4 не определяют выбранные объекты и не доказывают сбой анимации.
