## Причина и исправление

138 повышала целую страницу из 64 ячеек при доступном HD хотя бы для части слотов.
`carrySdTile` растягивала остальные изображения 128→256 без новой детализации.
Публикация добавляла новый namespace и оставляла прежний в RES.

Теперь страницы однородны по размеру ячейки: native SD 128 и HD 256.
Исходные SD pixels и BC1-блоки сохраняются; новые страницы дополняются только до кратности 64.
Номера физических слотов могут меняться: явная инъекция old→new применяется к ссылкам SEC,
классам MP, анимациям, palette definitions/family slots и привязке семантики.
Повороты и прочие байты SEC не изменяются. Неиспользуемый padding не получает активных ссылок.
Укороченная таблица MP tileTypes поддерживается; предел — штатные 16384 packed slots.

Анимационные диапазоны остаются непрерывными и в прежнем порядке.
Если среди кадров есть SD без доказанного HD, весь диапазон остаётся128.
Например, zone6: 32 кадра, SD-кадры16/29. Разнести только эти два кадра по страницам128,
сохранив непрерывную последовательность32 кадров, невозможно при64 ячейках на странице.
30 остальных кадров не повышаются; счётчик и причина показаны в подтверждении.
Смешанный уже-native диапазон, который нельзя сохранить, даёт явный отказ.

Удаление прежнего namespace разрешается только при hash-имени, approved portable-working/
portable-finalized profile и полном читаемом инвентаре обеих папок Dejavu/Maps и Base/Maps.
Stock/исходный профиль, общий namespace, недоступный или изменившийся инвентарь сохраняются
с причиной. Удаляются только точные страницы, профиль, recovery и semantic members этого namespace.

Порядок публикации: новый RES через существующий coordinator → MPR через существующий
save/recovery путь → очистка старого namespace. При отказе MPR работает прежний hash-owned
rollback RES. Очистка имеет отдельный backup, PublicationLease/reader-drain, QSaveFile/retry,
повторную проверку RES и всего MPR inventory перед commit и точный readback.
Если очистка отказала, новая пара остаётся пригодной, старые данные сохраняются с сообщением.
Это последовательность атомарных записей с восстановлением, не единая файловая транзакция.

До записи появляется подтверждение с HD/перерисованными переходами/native128,
ожидаемым приростом и итогом HDPack в МиБ, судьбой прежнего атласа и анимационным ограничением.
По умолчанию выбрано «Нет». CLI допускает только пути внутри явного canonical `build-tests-*`
корня; выходной каталог должен быть новым. Запись CLI в живые данные отклоняется.

Повторная пересборка выявила ещё две причины неидемпотентности: уже повышенные тайлы
исчезали из локального набора источников рецептов, а физическая перестановка меняла порядок
выбора равнозначных источников. На zone9 это давало сначала 54, затем 3 ложных новых перехода.
Теперь native HD сопоставляется одновременно по точным HD pixels и native128 mip,
а исходный логический порядок восстанавливается из проверенного recovery remap и сохраняется
как sourceOrder. Проверяются namespace, размеры, диапазоны, уникальность и padding;
старые receipt 138 поддерживаются, повреждённое отображение отклоняется.
Конечный повтор всех четырёх карт даёт 0 новых members и точное совпадение MPR/страниц.

Отдельно исправлен допуск команды для уже сохранённого portable-working профиля в HDPack:
общий признак рабочего профиля больше не считается несохранённым изменением этой команды.
Проверки грязной карты/параметров сохранены; до подготовки профиль побайтово сравнивается
с сохранённым embedded profile. Реальный CView проверен с ответами Cancel и Yes.
