# EI-ZONE3-ADDON-CRASH-20261019: Zone3 на game.exe и Rebuild

Дата: 19.10.2026, местное время Asia/Yekaterinburg (UTC+5).
Диагностика без исправлений, версии, сборки, установки и коммита.
База: main `219955a494e91cd1706ea2018bdf34d2d3528859`, VERSION 207.
AGENTS.md SHA256 `0c4f9c7ea51a36d54cde243728a4b6ca577645bfb61c7a1deef5149b05521b36`:
подтверждены база131 и запрет автоматического возврата нового baker по решению14.10.
Прочитаны верх ROADMAP, CONTRIBUTING и PROJECT_CONTRACT. Исходная чужая правка
ROADMAP сохранена; добавлен только пункт этой диагностики.

## Вывод и степень подтверждения

**Подтверждён отказ памяти в game.exe в 22:07:07, непосредственно перед закрытием
аддона в 22:07:12.** В `Engine/owned_exceptions.log` записано исключение
`E06D7363`, `p2=0077EE38`, game_base=`00400000`. Чтение PE установленного
game.exe по этому адресу даёт MSVC ThrowInfo с первым catchable type
`.PAVCMemoryException@@`, затем `CSimpleException*`, `CException*`, `CObject*`,
`void*`. Это конкретный `CMemoryException*`, а не предположение по надписи
Runtime Error. Расшифровка воспроизводится `build-tests-zone3-crash/binary.py`;
полные поля и SHA находятся в `binaries.json`.

**Основная причина с высокой вероятностью: чрезмерно разросшийся атлас Zone3
исчерпывает адресное пространство/доступный блок памяти старого загрузчика.**
Проблемная пара данных:

- `C:/GOG Games/PZ/MODS/Dejavu/Maps/zone3obr.mpr`, member
  `zone3obr_0bcba8177f9a.mp`: `nTexture=174` (offset16), `textureSize=2048`
  (offset20), `nTile=11117` (offset24), `tileSize=256` (offset28).
- `C:/GOG Games/PZ/MODS/Dejavu/res/HDPack_Terrain.res`, namespace
  `zone3obr_0bcba8177f9a`:174 страницы,438320312 байт DXT1, из них151 страницы2048².
  Это2508 MiB при разворачивании базовых уровней в RGBA32 или3344 MiB с mip-цепями.
  Расчёт по общему MP2048 для всех174 страниц дал бы2784 MiB только базового уровня.

Это **расчёты ёмкости, не измеренная конкретная аллокация game.exe**. Нет дампа
или стека именно22:07, поэтому нельзя честно назвать функцию/размер неудачной
аллокации и окончательно отделить общий бюджет, фрагментацию, ошибочное
вычисление размера либо внутренний предел старого загрузчика. Сам факт
CMemoryException подтверждён; причинная связь с объёмом атласа сильная, но
остаётся гипотезой до получения такого стека или контролируемого сравнения.
Точного времени скриншота в поручении нет: привязка скриншота к22:07 основана
на соседних событиях, а не на метаданных самого изображения.

## Предлагаемое исправление, не выполнено

1. Подготовить отдельную компактную runtime-публикацию: оставить нужные карте
   тайлы и полные анимации, перепаковать их с согласованным remap SEC/MP,
   типов, профиля и семантических привязок. Сейчас7729 неиспользуемых слотов;
  3388 используемых с кадрами дают теоретический минимум53 страниц по64,
   до дополнительных требований размещения. Сохранить исходный авторский
   набор для редактирования, а не терять материалы/рельеф/воду/объекты.
2. Для совместимости выбрать единый размер страниц; если компактный HD всё
   ещё не помещается в original loader, сделать отдельный согласованный
  128-вариант. Простое выравнивание всех174 страниц вверх до2048 увеличит
   расход памяти и не является достаточным исправлением.
3. До применения сравнить на отдельных копиях исходное падение и компактный
