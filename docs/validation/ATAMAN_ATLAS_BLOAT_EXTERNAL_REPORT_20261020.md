# Разрастание атласов террейна Дежавю (20.10.2026)

Разбор `HDPack_Terrain.res`, атласов карт и кода маппера (https://github.com/Samolleg/ataman-mp,
версия 208, коммит 982eb168). Ничего не менялось, только чтение и подсчёт.

Причин две:
1. «Перевести базовые тайлы в HD» размножает тайлы. Из-за этого у zone3obr стало 173 страницы
   текстур, а предел game.exe — 126 страниц на карту.
2. Старые опубликованные namespace никогда не удаляются. 43 namespace, на которые не ссылается ни одна
   карта, занимают 427 МиБ, около 37% нынешнего пака. Это началось ещё до функции HD.

Хеши коммитов из записки (fb16fe8a, 09195d83, 87fa0825) в публичном форке не найдены. Соответствующие
публичные коммиты: 94994f34 (190), 6f5cb2ff (193), 24c8cc49 (195) и 555824ee (196).

## Что делает перевод в HD (`source/render/terrain_base_hd.cpp`)

- **Целые наборы вариантов (строки 211-221).** Для каждого используемого картой слота земли
  импортируются подобранный HD-якорь и все его варианты, а также каждый другой исходник того же
  материала с таким же краем и все его варианты. То есть импортируются целые наборы, а не только
  тайлы, которые ставятся в клетки.
- **Четыре поворота и край исходного слота (строки 228-241, с версии 196 / 555824ee).** Каждая
  картинка импортируется четырьмя отдельными тайлами, по одному на поворот, и в каждую копию
  вмешивается старый край исходного слота (`baseHdWithOriginalRim`). Копии для разных исходных
  слотов никогда не совпадают, поэтому ничего не переиспользуется. Поле поворота в тайлах сектора
  (`replacement.rotations`) больше не заполняется.
- **Отклонённые тайлы остаются (строки 252-298).** Клетки, не прошедшие проверку стыков, откатываются,
  но импортированные для них тайлы остаются в атласе. Неиспользуемые импорты ничто не удаляет.
- **Старые страницы сохраняются (строка 299).** `setPreserveNativePages(true)` оставляет старые
  страницы 128 px; импорт дописывается после них и пропускает только точные дубликаты.
- **Повторный запуск добавляет, а не переиспользует.** Первый запуск на zone2 добавил 376 вариантов
  (страницы 16-21). Сейчас на эти страницы нет ни одной ссылки. Второй запуск добавил 3988 тайлов
  (63 страницы): 16 + 6 + 63 = 85. (Отсутствие ссылок измерено; то, что повторный запуск считает
  тайлы первого запуска новыми исходниками, — вывод по коду.)
- **Запись в исходные namespace.** При сохранённых старых страницах сохранение идёт через
  `SaveEditableModernDraft` (`view.cpp` 10057, 10375-10790) и пишет в тот namespace, который уже указан
  в MP карты. Для карты, ни разу не опубликованной под хешем, это голое исходное имя: `zone2` вырос
  на месте с 16 до 85 страниц, `gipat1` создан под голым именем (20 страниц). Сжатие 208 удаляет только
  namespace с хешем, поэтому эти два оно очистить не может.

## Откуда берутся HD-копии

Из локальной папки маппера `hd-library` (на этом компьютере её нет): импортированные страницы
террейна из архивов Дежавю, Base и HDPack JMV. Якоря — родные тайлы 256 px со страниц 2048 px,
на деле это HD-арт JamaisVu135. Варианты — не апскейл: маппер делает их сам (texture quilting),
сохраняя исходный край 24 px. В паке Дежавю до перевода (16.10) не было ни одной страницы 2048 px:
все карты были пересобраны на тайлах 128 px. Перевод возвращает арт JMV 256 px обратно.

## Предел движка: 126 страниц текстур на карту

Проверено по коду загрузчика секторов game.exe. Число материалов сектора считается как
(страниц + 2) × 2, а тайлы подсчитываются в таблице фиксированного размера 4 × 256. При 127 страницах и
больше цикл задания размеров читает за пределами таблицы. В последней части он читает мусор со стека,
передаёт его в выделение памяти под массив, выделение не удаётся, и MFC бросает CMemoryException.
При 173 страницах за пределы таблицы читается около 94 значений — это совпадает с сегодняшним дампом
падения zone3. Вторая ошибка, уже запись за пределы, возможна, когда тайл-оверлей лежит на странице p
с p + страниц + 2 ≥ 256. Не проверено: каждая страница 2048 px, вероятно, ещё занимает около 2,7 МБ
адресного пространства 32-битной игры.

## Что исправить в маппере

1. Использовать биты поворота тайла (как до 196), а не импортировать четыре повёрнутые копии.
2. Не вмешивать край исходного слота в каждый вариант; если края нужны — импортировать по одному разу на
   каждую реально используемую пару «вариант + край».
3. Импортировать только тайлы, которые ставятся в принятые клетки; отклонённые импорты удалять до сохранения.
4. При повторном запуске пропускать слоты, которые уже являются результатом HD, и переиспользовать
   существующие импорты по источнику, а не по совпадению пикселей.
5. Сжимать при сохранении: удалять слоты и страницы, на которые не ссылается ни тайл, ни анимация, ни
   палитра. Не давать сохранить карту больше 126 страниц и предупреждать примерно со 100.
6. Никогда не писать в голый или исходный namespace; всегда публиковать в собственный namespace карты с хешем.
7. После публикации удалять предыдущий namespace карты с хешем, когда на него больше никто не ссылается
   (отсюда 427 МиБ мусора).

## Как пересобрать чистый пак без потери арта

1. Сделать резервную копию пака и карт.
2. Составить список namespace, которые указаны во всех картах `Dejavu\Maps` (и при необходимости `Base\Maps`).
3. Скопировать в новый пак только страницы и JSON-профили этих namespace, без 43 неиспользуемых.
   Арт не теряется: он остаётся в JMV135 и в `hd-library`.
4. Сжать zone2 и gipat1 кнопкой 208 с публикацией в namespace с хешем; так же — любую карту, которая
   использует меньше примерно 70% своих слотов.
5. Проверить, что у каждой карты не больше 126 страниц, затем открыть каждую в маппере и в игре.
