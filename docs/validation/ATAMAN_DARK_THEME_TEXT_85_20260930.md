# Ataman85: читаемый текст тёмной темы

Дата:2026-09-30. EI-DARK-THEME-TEXT-85. Ветка codex/dark-theme-text-v85; база84 ce50af4c4dbef4e4c5dea1067970651acf84ab5a. Запрос: исправить чёрные строки иерархии со скрина a479bfd4 и проверить остальные окна при тёмной теме по умолчанию.

## Причины и исходное воспроизведение

1. CTreeView::acquireRow очищал цвет через setForeground(QBrush()). QVariant при этом остаётся валидным с чёрным цветом, и делегат не наследует Text из палитры. Проверка групп, экземпляров и всех трёх колонок до правки отказала; повторное использование строки оставляло ту же ошибку. Скрин baseline.png визуально подтверждает чёрные подписи на тёмном фоне.
2. runHeadlessCommand вызывался до установки CEnduranceStyle/Fusion и darkPalette. Поэтому прежний ui-widget-check не проверял производственную тему.
3. Disabled-текст128/128/128 на53/53/53 и65/65/65, тёмные keyword/string/function в MOB-скрипте, сообщения error/warning, ссылки базы и серые заблокированные строки имели низкий контраст. Исходная проверка дала17 отказов, из которых один был дефектом новой fixture QInputDialog (ленивое создание полей). Исправлена fixture через реальный TextInput; этот отказ не объявляется дефектом продукта.
4. В дипломатии Qt::darkYellow (#808000) всегда получал белые цифры: контраст около4.2. При смене значения цвет также обновлялся отдельно от текста. Теперь нейтральные цифры чёрные (контраст около5), ally/war белые, неизвестный сохранённый код использует обычный фон. Числовые значения MOB не изменяются.
