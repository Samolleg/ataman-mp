# EI-HD-VARIANTS-WANG: сменяемые кромки HD

Дата: 2026-10-11. Исследование варианта «Б», без версии, коммита, сборки и
установки. **Инженерный прототип выполнен; критерий «нет видимой сетки» НЕ
пройден. Минимальный достаточный банк не установлен.** Два и три цвета проверены
на четырёх материалах; увеличивать банк и объявлять его пригодным по одному
уменьшению шва нельзя. Массовый прогон не рекомендуется.

## Результат

- Реализованы полные рёберные Wang-банки: **2 цвета / 16 тайлов** и
  **3 цвета / 81 тайл** на материал. Всего **388 искусственных HD256**.
  Ноль сохраняет исходную кромку; новые цвета действительно меняют её пиксели.
- Тундра: отношение градиента стыка к внутреннему на поле 24×24 уменьшилось
  **2,084 у А → 1,028 у Б с тремя цветами**. Однако корреляция через одну клетку
  ухудшилась **0,122/0,123 → 0,236/0,237**. Постоянные воротники и угловые
  фрагменты образуют новый повтор вместо прежнего. Это не решение всей задачи.
- **518 560 допустимых направленных пар**: обе оси, четыре общие SEC-ориентации,
  семь уровней 256/128/64/32/16/8/4, все комбинации внутри двух банков.
  На новых кромках mip256…16 худшая средняя по ребру ошибка пары не превышает
  **1,360** внутреннего градиента. Уже существующие швы цвета 0 сохранены.
- Цвет 0 относительно исходного anchor: **max RGB delta = 0** на всех семи
  уровнях, для всех его сторон и четырёх поворотов. На mip8/4 используется
  **явный общий stock fallback**; независимые Wang-цвета там исчезают.
- **3436 структурных/readback-проверок PASS**, **8 из 8 банков отклонены**
  автоматическим критерием периодичности. Художественная приёмка человеком
  не выполнялась. PNG ниже предназначены для такого отбора, а не подтверждают его.

## Рёбра или углы, число цветов и повороты

| Свойство | Wang по рёбрам | Wang по углам |
|---|---|---|
| Ключ клетки | N,E,S,W | NW,NE,SE,SW |
| Условие соседа | равенство общего ребра и его направленного pixel contract | совпадение двух вершин общего ребра; сам рисунок ребра должен быть функцией обеих |
| Защита stock-перехода | закрепить одну сторону в 0 | закрепить обе вершины стороны; дополнительно выбрать точный stock anchor этой стороны |
| Два цвета | 16 комбинаций, 6 алгебраических орбит C4 | 16 комбинаций, 6 орбит C4 |
| Три цвета | 81 комбинация, 24 орбиты C4 | 81 комбинация, 24 орбиты C4; до 9 упорядоченных типов ребра |
| Слабое место | общая картинка углов сохраняет узлы сетки | несколько закреплённых stock-сторон могут требовать разные пиксели одного угла |
| Перекраска одной клетки | четыре соседа закрепляют все четыре ребра | четыре соседа также закрепляют все четыре вершины |

Выбран **рёберный** вариант для проверяемого первого Б: он непосредственно
выражает требование владельца «0 на стороне к старому/иному материалу» и
не требует переопределить существующие переходы. Сравнение с угловым здесь
структурное, не второй растеризованный corner-Wang эксперимент. Возможное
преимущество сменяемых углов после обнаруженной сетки остаётся гипотезой.

Формула орбит только для C4: `(C^4 + C^2 + 2C) / 4`. Отражения не вычитаются:
SEC их не хранит. **6/24 нельзя выдавать за размер проверенного банка.**
Исходные стороны цвета 0 не вращательно-симметричны, а новая полоса имеет
направленные половины. В реализованном pixel contract ориентация является
частью ключа. Все четыре SEC-поворота поддержаны как общая ориентация связной
области; независимые разные повороты соседей запрещены. Проба таких пар
отдельно записана как `crossFrameColorOnlyMean`: одной цветовой метки мало.

Именно поэтому физический бюджет здесь **16/81**, а не 6/24 и не умножение
на четыре. Каждый физический тайл можно повернуть вместе с областью без
создания нового слота. Это ограничение относительно независимых поворотов136;
оно заметно увеличивает повтор. Для их возвращения нужен новый синтез
вращательно согласованных воротников или расширенная направленная грамматика,
с собственным доказательством всех пар. Простое включение random rotation неверно.

**Минимум:** два цвета являются минимальной нетривиальной рёберной грамматикой.
Но если 0 нужен только снаружи, внутри остаётся единственная новая кромка.
В испытанном C2 ноль участвует и внутри с вероятностью 1/2, поэтому часть
старого периметра неизбежно остаётся. C3 резервирует 0 для границ, а внутри
использует 1/2. Это минимальные два новых цвета при отдельном stock-нуле.
Оба банка не прошли критерий отсутствия сетки; утверждения «81 достаточно»
или «нужно ровно больше трёх цветов» результатами не доказаны.

## Синтез

1. Из каждого HD-пула создаются две полосы **96×224**. Доноры назначаются
   детерминированной перестановкой, используются окна настоящих HD и четыре
   поворота. Полосы сшиваются по minimum-error DP-шву в перекрытии 8 px.
   Каждый донор имеет сохранившиеся пиксели непосредственно в двух половинах
   видимого стыка; количества и координаты сохранены в `edgeTraces`.
2. Противоположные стороны получают соседние половины одной полосы: top/left
   от строки48, bottom/right до строки48. В центре ребра это соседние сэмплы
   исходной живописи, а не искусственно одинаковые граничные пиксели.
3. Интерьер как в PROTO: 16 патчей80×80, 48 кандидатов на шаг, overlap16,
   локальные DP-разрезы, детерминированный PCG64. Все доноры участвуют в quilting.
   После вставки воротников их доли в окончательном интерьере отдельно не
   гарантируются. Это локальный quilting, не глобальный graph cut.
4. Новая полоса соединяется с интерьером минимальным швом в диапазоне
   **16…39 px внутрь видимого тайла**. Исходные угловые квадраты **8×8**
   сохраняются, чтобы боковая кромка цвета 0 не была перезаписана соседней.
   Это сознательный источник остаточных одинаковых узлов, а не скрытый успех.
5. Видимый размер224×224 внутри carrier256 с UV inset1/16. Для нулевой
   стороны сохранены наружные24 px соответствующего исходника. Кромка 0
   привязана к **первому исходному anchor**, его ориентации и mip-политике.
   Другой старый вариант или другой normalised anchor139 нельзя автоматически
   считать тем же нулём: нужен отдельный банк/проверка, иначе отказ.
6. Ранговое восстановление гистограммы применяется внутри унаследованного
   quilting до вставки новых воротников. Точная итоговая гистограмма не
   обещается. Для Stony gray это не сохраняет крупные камни: части объектов
   режутся, их масса превращается в мелкие тёмные фрагменты.

Все 388 изображений искусственные, а не новые авторские варианты или новые
найденные HD. Исходные тайлы сохранены отдельными `donor-*.png`.

## Решатель и подключение к 136/139

Прототип `layout()` использует глобальный ID каждого ребра:
`H(x,y)`/`V(x,y)`. SHA256 от seed, оси и мировых целочисленных координат
даёт цвет. Это переносимый prototype hash, **не побайтный FNV-selector136**.
Порядок по умолчанию row-major; обратный обход даёт те же refs. Нет зависимости
от времени, глобального RNG, номера мазка или порядка контейнера.

До выбора собираются обязательные ограничения от уже стоящих Wang-соседей.
Они важнее hash-предложения. Граница с transition/другим материалом/старым
тайлом закрепляется в 0, только если точная привязка к stock anchor доказана.
Для исходного прямоугольного опыта граница задана bounds; существующие клетки
передаются через `fixed`. Непрямоугольные реальные semantic masks адаптером
маппера не реализованы. Полная C^4 грамматика даёт тайл любому непротиворечивому
набору четырёх цветов; конфликт закреплённых соседей отклоняет всю операцию.

При перекраске одной клетки четыре соседа обычно фиксируют весь tuple.
В этом банке на tuple один интерьер, поэтому проверенный результат **no-op**.
Чтобы действительно перемешивать одну клетку без движения соседей, нужны
минимум два интерьера на tuple: **32/162 слота** на материал. Другой путь,
изменение общего ребра и соседней клетки, требует явно расширенной атомарной
транзакции, не молчаливого изменения за пределами выделения. Если отбраковщик
удалил единственный тайл tuple, банк не полон: нельзя заменять его несовместимым.

`solve_cohort()` сначала сверяет bank SHA, anchor, frame, seed, затем готовит
обе карты. Проверено равенство одной области24×24 и двух12×24 с общим origin;
различие любого из четырёх идентификаторов даёт отказ. Неизвестный сосед должен
считаться закрытой границей0 до подключения проверенного cohort. Это проверка
Python-планировщика, **не** реализованная world-кисть, Undo или запись SEC.

## Mip до4×4

Входные уровни созданы BOX из декодированного mip0, затем задаются кромки
по отдельному контракту уровня. Это не прочитанная цепочка игровых mip.
Измеряется bilinear выборка фиксированного UV1/16…15/16 в центрах выходных
пикселей; при малых размерах учтены оба затронутых texel, а не округлённый crop.

На128…16 для каждой стороны берётся один общий образец соответствующего цвета;
в пересечениях защищённых footprints приоритет stock-угла. На8/4 воротники
перекрывают почти весь тайл: все варианты явно получают stock-anchor данного
уровня. Никаких подменённых заявлений о сохранении независимых цветов там нет.

Средний ratio для новых цветов C3 по всем допустимым парам; диапазон между
цветами1/2. В этом наборе denominator охватывает внутренние градиенты всей
выборки mip, в отличие от inset-8 field metric выше:

| Материал | 256 | 128 | 64 | 32 | 16 | 8 stock | 4 stock |
|---|---|---|---|---|---|---:|---:|
| Tundra | 0,944…1,066 | 0,934…1,046 | 0,947…1,020 | 0,844…0,929 | 0,733…0,792 | 1,380 | 0,671 |
| Brown | 0,943…1,025 | 0,945…1,036 | 0,962…0,970 | 0,810…0,978 | 0,504…1,080 | 2,079 | 1,109 |
| Stony gray | 1,077…1,130 | 1,076…1,131 | 0,897…1,164 | 0,968…1,019 | 1,093…1,306 | 2,233 | 1,134 |
| Common | 0,906…1,072 | 0,957…1,110 | 0,960…1,126 | 1,044…1,155 | 0,660…0,941 | 1,917 | 1,213 |

На8 stock абсолютный средний скачок всего1,35…2,94 luma, но относительное
число велико из-за почти плоского интерьера. Это унаследованное поведение,
не новая бесшовность. На256 нулевые кромки Tundra сами имеют ratio2,187.

## Полный прогон, МиБ и слоты

Один BC1 HD256 с9 уровнями256…1:
`Σ max(1,(256>>m)/4)^2 * 8 = 43 704 bytes` с целочисленным размером блоков.
Payload без заголовков/manifest, не пик RAM/GPU. Фактически выпечены только
четыре материала. Расчёт ниже предполагает **один проверенный anchor-bank**
на материал/класс/слой и один интерьер на tuple.

| Охват | C2 тайлы / МиБ | C3 тайлы / МиБ | Страницы64 C2/C3 | Синтез C2/C3 |
|---|---|---|---|---|
| 90 групп | 1440 / 60,018 | 7290 / 303,843 | 23 /114 | 5,00 /19,17 мин |
| 93 stock land | 1488 / 62,019 | 7533 / 313,971 | 24 /118 | 5,16 /19,81 мин |
| 96 static nonwater, включая overlay | 1536 / 64,020 | 7776 / 324,099 | 24 /122 | 5,33 /20,45 мин |

Охват93/96 взят из проверенного budget предыдущего PROTO; это комбинации
семантики, не просто названия материалов. Там100 групп после отдельного
разделения физических классов. Overlay не подключается к136 автоматически;
нулевой HD для Desert3 требует разрешённого reused источника, не генерации
из несуществующего HD. Несколько несовместимых stock-anchor семейств умножают
бюджет: верхняя оценка `Σ C^4 * anchors(identity) * interiors(tuple)`.

Сокращённая теоретическая C4-модель6/24 дала бы для90 групп540/2160 тайлов,
22,507/90,027 МиБ; **это не бюджет работающего данного пиксельного банка**.
Два интерьера для одиночной перепокраски удваивают настоящий банк90:
2880/14580 тайлов,120,037/607,685 МиБ.

Измеренный чистый синтез16 тайлов на материал2,51…5,71 с;81 тайла12,58…13,13 с.
Временная экстраполяция по среднему фактических четырёх случаев. Первый C2
замер медленнее остальных; параллельная задача может влиять на CPU. Полный
генератор четырёх материалов с PNG/полями/метриками занял214,30 с. BC1,
массовый отбор, повторная генерация отбракованных результатов и интеграция
не включены. Время не является обещанием качества или измерением90 материалов.

Физические слоты занимают только использованные рецепты. На текущем seed:
в полях12×12/24×24 C2 использует **16/16**, C3 **45/50** на материал.
В глубоком интерьере C3 возможны16 комбинаций1/2; в произвольной области с
нулями на границах нужен запас полной грамматики81, в узких областях возможны
также противоположные нулевые стороны. Ротация слотов не добавляет.

Бюджет карты: `ceil((existingAllocated + Σ usedNewRecipes)/64)*64`.
Старые слоты, переходы, анимации и Undo автоматически не удаляются. Например,
при исходных1216 местах полный C3 для10 материалов добавит810 → округлённо2048;
для11 даст2107 →2112 и уже превысит2048. Предел4096 также проверяется заранее;
8192 не предлагается. Это арифметическая оценка, не повторный прогон корпуса карт.
