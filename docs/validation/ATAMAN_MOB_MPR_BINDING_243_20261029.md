# EI-MOB-MPR-BIND-243 — привязка MOB к MPR

Поручение29.10, проверка30.10.2026. База main
`33a28503890e1526cfaaee7708acbdd04b76533d` /242, версия243, база131 сохранена.
Исходная проблема: у gipat2 были сохранены200 объектов в MOB, но запись мира
содержала пустой mobPath. MCP находил одноимённый файл, а обычный переход
открывал MPR без объектов. Разовая исправленная привязка живой gipat2 сохранена;
эта задача исправляет программу, без повторной расстановки или изменения карты.

## Поведение

- New MOB для MPR без её загруженного MOB выбирает основной SC_OBJECT_DB_FILE,
  предлагает имя MPR в её папке. Одни дополнительные MOB этот выбор не меняют.
  Явный основной MOB можно сохранить с другим именем и сразу привязать к карте.
- При явном открытии основного MOB пустая связь карты сохраняется и для другого
  имени файла. Обычное открытие MPR использует её явную связь, затем одноимённый
  MOB в той же папке. Тот же путь работает для уже открытой MPR и соседней карты.
- Поиск выполняется независимо от того, известен ли путь MPR в JSON. Явный другой
  MOB сохраняет приоритет, даже если отсутствует; резервные/другие папки не
  подставляются. Дополнительные MOB и AddMob-зависимости не крадут привязку.
- Save As связанного MOB обновляет только mobPath соответствующей карты, с
  проверкой предыдущего файла. Обычный Save не переписывает неизменную связь.
- Коллекции остаются отдельными рабочими пространствами: их Save As не меняет
  MOB общей карты, повторный выбор собственной MPR не добавляет карту/MOB в
  коллекцию. MPR-only MCP сохраняет исходную unmapped world identity.
- Создание коммитит проверенный MOB, открывает и сохраняет связь. При отказе
  записи выгружает новый документ и откатывает только принадлежащий операции
  файл; замена существующего MOB восстанавливается из проверенного снимка.
  Внешняя подмена не перезаписывается, неполный откат явно сообщается.
- Чтение раскладки не сохраняет обнаруженные пути. Временная отметка discovery
  не входит в JSON; origin-only Undo сохраняет исходную пустую связь, в том
  числе после исчезновения файла. MCP open_map использует подготовленную пару
  без записи; create_mob и его Undo/Redo сохраняют свой прежний договор.
- Файлы сохраняются штатными атомарными операциями и блокировками. Без членства
  MPR в мире новая запись с выдуманными координатами не создаётся: стандартная
  пара MPR/MOB открывается по имени. map.txt, игровые сценарии и движок не меняются.

## Проверки

Новый целевой `tests/mob_mpr_binding_check.cpp` использует существующий native
hook runAssemblyCatalogCheck и объектные файлы самой Release243, настоящий
MainWindow/CView и скрытый OpenGL-контекст. Скрипт
`tests/run_mob_mpr_binding_check.ps1` создаёт отдельный профиль, копирует разрешённые
MPR/MOB/resources и проверяет SHA/длину/native-mtime защищённых исходников и
установки. Ни игра, ни пользовательский GUI не запускаются/закрываются тестом.

Итоговая реализация: document6/6 PASS, GUI/MCP80 PASS /exit0,
new-process readback5 PASS /exit0. Проверены New/Open/Save As, основной MOB с
произвольным именем к пустой связи, явно выбранная другая связь, дополнительные
MOB, коллекции, MPR-only/late-MOB MCP, create_mob Undo/Redo, отказ записи/отмена,
откат нового и заменённого файла, повреждённый/отсутствующий MOB, сохранность
несохранённой MPR и загрузка200 реальных объектов из частной копии gipat2.

Инженерные артефакты, не в Git:

- `build-source-mob-binding-243/` — свежий экспорт базы с изменениями задачи,

- `build-tests-mob-binding-document-243/results.txt` — целевые тесты позднего
  MOB, origin Undo, явного выбора, no-op, отсутствующих файлов, внешнего
  конфликта и старого JSON.
- `build-test-mob-mpr-binding-243-collection-final/` —80 PASS GUI/MCP +5 PASS нового процесса;
  `process.json`, stdout/stderr, `preserved-inputs.json`.

Первые два GUI-прогона выявили недочёт теста: размеры MPR читались до штатной
отложенной инициализации документа. Проверка теперь явно дожидается её через
тот же ensureTerrainAutoCatalogReady, который использует подготовка авторинга.
Первый unit-прогон выбирал запись по индексу без учёта сортировки zoneId;
тест исправлен. Эти прогоны не объявлены PASS и не служат доказательством результата.

## Приёмка

Проверка владельцем в игре остаётся открытой. На собственной новой карте:
создать основной MOB, добавить/сохранить объект, повторно открыть MPR и проверить
объект в новом запуске игры. Автоматическая проверка200 объектов подтверждает
загрузку native-документа и сохранённую привязку; запуск игры она не заменяет.
