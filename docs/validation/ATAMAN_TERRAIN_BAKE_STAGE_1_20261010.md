## Маски: что извлечено по реальным пикселям

Точная привязка атласа Zone6 подтверждена исходным embedded profile и хэшем
всех 1216 физических мест; при подготовке комплекта повторно сверены исходный
MPR и каждый MMP payload с инвентаризацией этапа 0. Проверены 63 подходящих
straight-перехода двух материалов из выбранной шестёрки. Для каждого пикселя
оценивается `a=clamp(dot(T-A,B-A)/dot(B-A,B-A))`; перебираются все однородные
пары материалов, сохраняется пара с наименьшим RGB residual. Никакая отдельная
stock blend-mask картинка не заменяет измерение реальных переходов атласа.

Семантика определяет пару материалов, а направление кромки устанавливается
по фактическим краям картинки. Контур 50% выбирается в центральной полосе,
ширина 10–90% и низко-/высокочастотная составляющие измеряются после 1px blur
оценки. Поперечные профили выравниваются по контуру. Для передачи бахромы
используется **неразмытая** двумерная ownership residual texture относительно
среднего профиля; вдоль границы она периодически билинейно выбирается в
мировой фазе. RGB-fit близок к исходным пикселям, но не доказывает восстановление
авторской альфы: stock-смешение уже запечено в RGB, DXT и текстуры неоднозначны.

Восьмёрка с наименьшим residual: слоты 1163, 1172, 1055, 1073, 1127, 1090,
1085, 1053. Узкие каменные кромки: медиана 4px; травяные: 14–16px. Это ширина
**оценённой** RGB ownership полосы при исходных 128px, не универсальная ширина
всех игровых переходов. Крупные языки, fine fringe, промежуточные значения и
фактические alpha values каждого источника записаны в
[stock-edge-measurements.json](../../build-tests-terrain-bake-stage-1/stock-edge-measurements.json).
У рассмотренных land-переходов фактическая alpha=255: видимая бахрома/пятнышки
находятся в цвете, это не прозрачность overlay. Метод не устанавливает,
какой авторский дизеринг применялся до компрессии.

Мировая геометрия — общие bilinear scores из поля вершин, а не независимые
клеточные маски. Здесь используется непрерывный **score-distance proxy**;
метрический SDF с поправкой на градиент не реализован. Следовательно,
физическая ширина полосы меняется с формой/числом материалов и наклоном
границы. Это ограничение особенно важно для трёхматериальных узлов.
Поправка `4*w*(1-w)` обнуляет шум и residual при чистом материале.

Общие параметры: world noise 2.1/8/31 циклов на клетку, амплитуды
0.065/0.021/0.008 score; измеренный контур gain0.65, ownership fringe gain0.45;
профиль усреднён по четырём лучшим fit, ширина берётся из их медианы.
Варианты: A — strength0.55, узкая сдержанная кромка; B — 1.0, основной
компромисс; C — 1.65, более выраженные языки/бахрома и широкая полоса.
Никакой новой фазы на границе клетки/сектора нет. Точные итоговые параметры и
проверки двух сторон внутренних рёбер сохранены в stage1-result.json.
При непосредственном просмотре общего PNG и крупного фрагмента различие A/B/C
заметно прежде всего в изгибах и тонкой кромке; они всё ещё выглядят более
гладкими и менее насыщенными родной бахромой, чем current. Извлечение stock
профиля получилось, но художественная цель полного возврата рисованного
характера **не объявлена принятой**. B — база следующей настройки, не готовая
production маска. Нужны pair-specific профили и более точная нормаль/тангенс.

## Антитайлинг

**Ноль дополнительных мест:** SEC имеет два бита четверть-поворота. На
однородных клетках берётся SHA256 от координат/материала, выбирается поворот
0/90/180/270 и уже существующий uniform slot **того же материала и runtime
class**. Переходные клетки на этой панели сохранены. Новые MPR для этого опыта
не записываются, поведение маппера не меняется. Отдельный однородный тест
камня и травы показывает изменение регулярности; корреляция на лаге одной
клетки — диагностическое измерение повтора, не рейтинг художественного качества.

Случайный поворот делает заметный дешёвый выигрыш на изотропных камне/почве/
траве. Но повороты не создают новой текстуры. У Irregular один uniform вариант;
у остальных выбранных материалов 2/5/6/4/8. Автоматическая ротация недопустима
для направленных троп, досок, кладки, потоков, следов, анизотропных рисунков и
flipbook. Даже у изотропной текстуры необходимо принять стык повёрнутых краёв.
Нельзя смешивать runtime classes ради вариантов. Seed должен воспроизводиться
при повторной покраске, сохранении, открытии, Undo/Redo, а не меняться при
каждом кадре или запуске. Участок с 85% переходов слабо отражает этот выигрыш.

**Свободное запекание:** три phased/rotated uniform sources смешиваются
continuous low-frequency noise с периодами 3.7/6.1 клетки; macro brightness
0.10/0.035, периоды 7/2.3, hue0.022 с периодом9. Период текстуры ещё существует,
смешивание местами смягчает детали. Stochastic/hex tiling здесь не реализован:
текущего сочетания достаточно, чтобы увидеть выигрыш и цену слотов. Мировой
цвет/фаза превращают даже чистые клетки в уникальные; finite cache по material
и corner tuple не может дедуплицировать свободные мировые фазы без потери цвета.

## Рецепты и гарантия ребра

Реализован конечный ключ `(NW,NE,SE,SW, predecessor runtime class, interior label)`.
N=4/8 — число форм/цветовых/текстурных вариаций **внутри** клетки; для uniform
группы максимум4. Рецепты распределены детерминированно, сбалансированно внутри
группы. Это назначение учитывает всю группу: изменение её состава может
переназначить часть вариантов. Реализация должна либо сохранять авторский label,
либо выбрать стабильный координатный hash с возможной неполной заполняемостью.

Ребро определяется только упорядоченной парой endpoint materials; для разных
концов имеется одно положение пересечения — midpoint. Шум/texture mixing/macro
умножаются на `16*x*(1-x)*y*(1-y)`. На общем ребре эта функция равна0;
bilinear weights, поперечный профиль и фиксированная текстурная фаза совпадают.
Противоположные texture samples при локальных 0/1 периодически тождественны.
Растр рецептов включает оба точных крайних отсчёта. Поэтому гарантия относится
и к mask/RGB trace, и к крайним пикселям соседних PNG-клеток, включая uniform
соседей и трёхматериальные junctions. Между произвольными материалами гарантия
работает при одинаковом endpoint field; конфликтующие старые углы не исправлены.

Гарантируется C0, **не C1**: касательная/кривизна может изломиться у стыка.
Рецепты не воспроизводят произвольную свободную мировую кривую B. У них меньше
случайности на границе и заметнее клеточная структура; N8 даёт больше внутренней
вариации, но не решает это ограничение. Общая кромка может повторяться вдоль
цепочки рёбер одного типа. Макро-цвет тоже подавлен на рёбрах, что ограничивает
эффект антитайлинга и может выделять сетку. Это цена выбранного конечного бюджета.

Для более свободной формы нужны дополнительные edge labels: положения из
небольшого набора, касательная и phase/fringe state. Они выбираются **один раз
на общее ребро**, включаются в ключ клетки и согласуются через вершины.
При K состояниях каждого реально смешанного ребра ориентировочная верхняя
граница комбинаций `N*K^e` на сигнатуру с e такими рёбрами. K=3 и e=4 уже
дают81×N; фактическое использование меньше, но считать прежний N бюджет
гарантированным тогда нельзя. Полноценный edge solver и новый пересчёт нужны
до реализации более богатой grammar. DXT1 block endpoints/gutters/mip тоже
могут нарушить доказанное PNG равенство: это следующий технический gate.

### Полный корпус: условный бюджет фиксированной grammar

Взяты все79 exports этапа0. Слой, сигнатура и class остаются раздельными.
`H=Σ min(4,uniform group count)`; unique=`H+T`;
recipeN=`H+Σ min(N,transition signature/class/layer count)`.
При **одном фиксированном edge state** это теперь описывает реализованную
grammar, а не свободные мировые фазы. На всех картах pixels не запекались;
раскладка/визуальная бесшовность overlay и точное выживание animation padding
ещё не проверены. Нужны резервы для pinned flipbook/неперепекаемых ресурсов.
Корпус содержит противоречивые vertices (см. этап0), требующие отдельной политики.

## Рекомендация и порядок реализации

1. **Да, отдельной небольшой версией сначала внедрить детерминированный
   случайный четверть-поворот однородных тайлов** в текущем маппере. Это не требует
   нового атласа и новых slots. Явно разрешённый isotropic material set,
   сохранение class, exclusion анимаций и направленного рисунка, проверка
   стыков/сохранения/Undo/Redo. Выбор уже существующих variants можно добавить
   тем же механизмом после проверки совместимости; не генерировать variants
   ради обещания «ноль slots». Эта рекомендация не разрешает реализацию сейчас.
2. Для будущего bake взять B как исходный художественный кандидат; A — для
   тонкой/жёсткой кромки, C — для травы с более выраженными языками. Хранить
   профиль/бахрому по паре материалов, не один общий профиль для всех сочетаний.
   Следом метрический world SDF/нормаль/тангенс и контроль физической ширины,
   троек/диагоналей; текущая world projection вдоль x/y не является истинной
   parameterization по длине границы. Обязательна визуальная приёмка владельца.
3. Антитайлинг переходов: макро-яркость около10%, hue около2%, несколько
   согласованных uniform sources. Начать с простого low-frequency mixing;
   hex/stochastic рассматривать только если повтор остаётся неприемлемым,
   с измерением размытия/деталей и расширением recipe key budget.
4. В ёмкости сначала N4 fixed-edge + точная дедупликация и явный overflow.
   N8 оправдывать видимой прибавкой; не включать всегда. Нужен edge-state solver
   для свободнее расположенных кривых; count только по фактически используемым
   состояниям, не по optimistic rotation. Проверить полный bake Zone6/Zone9,
   DXT/gutters/mips/overlay/classes/animations и конфликтующие vertices.
5. До production bake пройти приготовленный128px game memory gate.
  256px — опция по отдельной памяти/визуальной выгоде, не default.
