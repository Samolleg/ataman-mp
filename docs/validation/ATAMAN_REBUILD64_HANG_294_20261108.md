## Причина по предоставленным дампам

Исследованы только `work/hang-293-20261108/mapper-46076-stacks-{1,2}.dmp`.
К PID46076 отладчик не подключался; его состояние/завершение не менялись.
Дампы и исходные журналы не входят в Git или staging.

Для stripped MinGW EXE выполнена повторная линковка неизменных объектов293 без
strip. Секция `.text` побайтово совпала с переданным EXE; адреса функций получены
из этой таблицы символов. Для DLL использован PDB293 R2. Стек восстановлен по
x64 `.pdata/.xdata` и контекстам потоков, не по эвристическому поиску адресов в
стеке. Результаты: `work/rebuild64-hang-294-20261108/*-unwound.{json,txt}`;
проверка идентичности и восстановление — `unwind.py`, символизация — `dump_scan.py`.

- Qt, TID26724 — `QEventDispatcherWin32::processEvents` / во втором снимке `CRebuild64Viewport::tick → projectNativeUnits289 → CLandscape::unitSurfacePosition → CSector::projectPt → CTile::isProjectPoint → CTile::pos` — первый снимок ждёт события Windows, второй выполняет повторную CPU-проекцию персонажей; frame/serial/mutex не ждёт.
- D3D/service, TID46736 — `Worker::run → host_frame → map_frame → commit_output → prepare_service293` — выполняет CPU-преобразование depth перед Present; RIP `+0x1b5` и `+0x2c7`, разные итерации/буферы, не mutex/Present wait. В этой реализации raster служебного слоя идёт на том же D3D worker; отдельного raster worker нет.
- Ресурсные workers, TID51432 и45144 — `OwnedResourceLoader::Impl::worker_main → _Cnd_wait` — ждут новые задания condition variable. Семантический `CUnit::nativeVisualPlan` в293 вызывается Qt-потоком; отдельный worker композиции текстур в этих снимках не выполняет активную работу.

Оба снимка показывают работающие/ожидающие события потоки, а не доказанную
взаимную блокировку. Группа fur и shader compiler в этих стеках отсутствуют.
Удаление маркера after_preparation само по себе не означает зависание в fur;
причину первой84-секундной паузы только по этим двум поздним снимкам установить
нельзя. Callback293 берёт mutex для копирования shared snapshot, отпускает его
до raster; admission mutex захватывается после composite непосредственно вокруг
Present. `cameraNavigationActive` не ждёт завершения кадра/serial.

Существенная причина длительного отсутствия кадров установлена воспроизведением
и кодом292/293: `editorVisuals292` выдаёт неполный пакет, ставит pending, а его
каждая новая порция меняет fingerprint документа. Qt увеличивает generation,
снова вызывает `api.document` и отменяет предыдущую подготовку мира. При этом
`nativeVisualPlan` на Qt вызывает `figurePartNames → getFigure`, декодируя полную
GL-сборку ради списка/иерархии деталей.12мс — проверка между персонажами,
не ограничение времени одной операции. Неизменная проекция всех NPC и повторный
idle `nativeServiceSnapshot` усугубляют задержку;293 добавляет миллионы целых
64-битных делений depth перед каждым Present. Бесконечность работы не доказана:
обе контрольные версии в итоге продолжили вывод.

## Исправление

1. Незавершённая внешность остаётся подготовкой; сцена получает один полный
   пакет. До него сохраняется текущая raw/accepted сцена и обновляется камера.
2. Для native-плана имена/parents из MOD читаются асинхронно по неизменным байтам,
   без создания полной GL-геометрии. Cache инвалидируется source generation;
   результат применяется только через прежние semantic/revision проверки.
3. CPU-проекция кешируется по позиции/ожидаемому drawPosition, источнику MPR и
   supportGeometryRevision; изменения terrain явно инвалидируют кеш. Удалённые
   узлы удаляются из кеша. В покое служебная геометрия обновляется порциями не
   чаще100мс; прежние сигналы немедленной invalidation сохранены. Периодический
   refresh сохраняет работу вспомогательных панелей без document-сигналов.
4. Depth одинакового размера преобразуется линейно без целочисленных делений;
   для другого размера колонки рассчитываются один раз, строка — один раз на y.
   Камера/depth текущего кадра и растеризация до Present сохранены.
5. Каждые5с журнал содержит `Rebuild64 health` с generation/ready/pending,
   appearance и возрастом последнего statistics packet. Это не счётчик Present;
   реальные Present подтверждает отдельный trace DLL. Shader/HLSL/table и
   renderer vendor не менялись.
6. При первой загрузке zone1 преждевременный MPR title вызывал полный
   `refreshMapTestContext` с повторным сканированием ресурсов до primary MOB;
   это оставляло Qt-паузу1,13с. Запрос теперь откладывается до полного workspace;
   штатный финальный refresh сбрасывает pending, незакрытый запрос выполняется
   в endWorkspaceLoad по уже загруженному каталогу. Оставшиеся стадии контекста
   разделены Qt-pulse с проверкой serial/жизни окна и запретом пользовательского
   ввода в промежуточное состояние. OpenGL-путь сохранён.
