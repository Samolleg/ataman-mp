# EI-FUNCTIONAL-AUDIT-58 — функциональный аудит

Дата: 2026-09-24. Проверена версия 58, ветка `codex/travel-toolbar-open-v58`, SHA `4f47a686e716abbbb7d28836b0b7440824a8286c`.

## Вывод

Основные подсистемы имеют работающие автоматические проверки, но считать версию полностью стабильной нельзя: подтверждён вылет при завершении, зафиксирована отдельная задержка закрытия 25,96 секунды. Общая проверка интерфейса не покрывает этот путь завершения. Часть тестового контура устарела. Аудит не является подтверждением всех игровых сценариев.

Исходники приложения, установка и игровые ресурсы не изменены. Исправления не выполнялись. Для проверки использовались отдельные сборки тестов и собственная копия чистого пакета, без интерактивного запуска редактора или игры.

## Подтверждённые проблемы

### P1. Вылет при закрытии: панель переходов обращается к удалённому окну карты

Доказательство: `artifacts/EI-Mapper-Ataman-2-first-test/logs/workflow-20260923-214936.log`, последняя запись: `0xc0000005`, адрес `0x7c9ace`, чтение адреса `0x55`, `rcx=0`, контекст `shutdown/view-deleted`. Дамп: `crash-20260923-214936-p18640-t12108.dmp` в той же папке.

`source/app/main_window.cpp:8937` удаляет `m_pView`, следующая строка обнуляет указатель. Обработчик `QDockWidget::visibilityChanged` в `source/app/main_window_travel.cpp:153–158` остаётся подключённым и без проверки вызывает `m_pView->setTravelEditing(visible)`. Тот вызывает `cancelTravelGesture`, где происходит обращение через нулевой указатель.

Адрес сопоставлен с символами повторной линковки версии 58: секция `.text` символизированного EXE побайтно совпадает с установленным EXE, SHA256 секции `70627B73BAA3674D06DBC74500A9D86B38B27520A335AFE66DB5278ED8CBAFD3`. В стеке найдены адреса `CView::setTravelEditing` и обработчика `createTravelEditor`.

Рекомендация: отключать зависимые от окна карты обработчики до уничтожения окна, защищать путь завершения и добавить проверку закрытия с видимой/скрытой/табулированной панелью переходов. Нельзя считать успешный тест открытия панели проверкой закрытия.

### P2. Закрытие может занимать почти 26 секунд

`logs/workflow-20260923-230124.log:1082–1083`: тело уничтожения окна закончено за 40 мс, завершение всего удаления — через 25960 мс. Это отдельный подтверждённый симптом, не тот же самый вылет. Точный тормозящий объект пока не установлен; необходимо измерить последующее уничтожение полей, дочерних объектов, базовых классов и графического контекста. Приписывать задержку загрузке MOB или конкретному потоку по этим данным нельзя.

### P2. Полный набор тестов не является надёжным выпускным барьером

Два набора не собираются:

- `tests/duplicate_id_report_tests.cpp:3` подключает отсутствующий `../duplicate_id_report.h`; актуальный заголовок находится в `source/documents`.
- `tests/landscape_tools_widget_tests.cpp:280` передаёт четыре аргумента `setWorldTerrainStatus`, актуальный интерфейс требует шесть.

Ещё четыре набора завершились с одним отказом каждый; причины различаются:

- `endurance_document_tests::modernSaveRoutesThroughPublicationExactlyOnce`: проверка ищет буквальную строку `archive.buildWithPublishedMembers(pages`. Актуальный код использует `sourceArchive.buildWithPublishedMembers` (`source/render/view.cpp:15262`). Это устаревшая проверка текста, само по себе не доказательство поломанного сохранения.
- `res_archive_document_tests::ordinaryMapSaveUsesBoundHdArchiveWithBackup`: ожидает обязательный ручной выбор RES при уже существующем `HDPack_Terrain.res`. Текущая политика намеренно выбирает этот архив автоматически (`source/core/terrain_save_flow_policy.h:173`). Проверку требуется согласовать с принятой политикой.
- `neighbor_map_layout_tests::placesNearestZone7BackgroundsFromPairedEntrances`: не выполняется ожидание положения gz1g слева. Данные теста содержат разреженные метки `#exit` и ссылки на отсутствующие порядковые записи, например единственную запись gz1g обозначают 4 и ссылаются на вход 4. Парсер использует порядковый номер записи (`map_table_document.cpp:335`). Нужны корректный контрольный пример и повторная проверка; неисправность расположения реальных карт этим тестом не доказана.
- `jmv_map_test_launcher_tests::rebasesRuntimeTerrainAtlasNamespace`: относительный путь к синтетическому MPR неверен при дополнительном уровне каталога сборки аудита. Это ограничение запуска теста. Попытка повторного запуска после размещения fixture не состоялась: EXE в каталоге уже отсутствовал. Поэтому результат не повышен до PASS и причина отсутствия EXE не установлена.

Рекомендация: восстановить сборку двух наборов, обновить устаревшие ожидания, устранить зависимость тестовых данных от расположения EXE. Не маскировать оставшиеся отказы общим статусом PASS.
