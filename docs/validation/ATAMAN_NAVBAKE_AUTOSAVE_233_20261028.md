## Реализация

База main `4d2d1a9dafb01935e0aacffe9be02627b749b93b` /232.
Реализация233: `6cbb62c3854cf3e0de3d7b37096e9c7330ba38a2`. Поручение владельца:
автоматически перепекать Nav64 после сохранения рельефа или статических объектов
по M1 PLAN-MAPPER-NAV64.md. Vendor, алгоритм построения и старый AI MOB/.grp
не менялись. Редактор .navsrc и другие пункты общего M1–M3 в этот scope не входят.

Событие создаётся после успешной публикации обычного MOB, проверенного MPR
или всего общего save batch. Сравниваются геометрические поля сохранённых
байтов, а не dirty flag: XY/высоты/overlay/классы поверхности, статические
OBJECT/LEVER/TORCH с NID, позицией, поворотом, моделью, комплекцией, частями
модели и родительской привязкой. UNIT/MAGIC_TRAP, скрипты, названия, текстуры
и освещение не требуют bake. Ошибка сохранения не выдаёт событие.

Очередь в существующей CNavmeshPanel запускает установленный запекатель через
тот же проверенный интерфейс. Нулевой снимок UI не копируется в producer:
читаются сохранённые файлы, новые несохранённые правки остаются отмеченными.
100мс debounce и CFileWriteActivity защищают вложенные event loop сохранения;
одна карта занимает один ожидающий запрос. Новое сохранение во время bake
вызывает один повтор; переключение карты не меняет контекст ожидающего запроса.
Отмена очищает очередь. Состояние свежести хранит время сохранения геометрии
и последнего успешного bake для пары MPR/MOB, без content fingerprint.
Позднее сохранение или ошибка не могут объявить старый результат свежим.
Отдельно учитываются известные даты сохранений без геометрических изменений,
чтобы сохранение юнита/скрипта не создавало ложную устарелость только по mtime.
Для внешних правок остаётся приблизительная проверка по датам.
