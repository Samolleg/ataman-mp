## Изменения

1. `CResArchiveTransaction` пересобирает RES по файловому индексу: исходные payload копируются порциями4МиБ в собственный временный файл; в памяти остаются таблица, имена и новые/заменённые члены. Проверяются размер/границы/достижимость игровых hash chains, точные изменённые payload, **все** неизменённые payload потоковым сравнением и их timestamps. Кандидат проверяется до замены; источник, резерв и опубликованный файл хешируются потоком. `QSaveFile` без direct-write fallback выполняет атомарную замену. Резерв не загружается целиком. Системный SHA-256 имеет переносимый fallback.
2. Save, сжатие, удаление прежнего namespace и очистка пака используют файловые транзакции. Общая операция с MPR/другими companion-файлами поддерживает файловый RES-кандидат, журнал и проверенный откат из резерва. Подготовленные и заново побайтно проверенные страницы используют уже декодированные равные изображения при принятии Save; лишние полные RGBA-копии и повторные декодирования не удерживаются. GPU-представление обновляется через существующую проверку изменившихся изображений.
3. Неизменная публикация проверяется по MMP, профилю, классам слотов и семантическому полю. Сохраняется прежний namespace; RES не записывается. Изменения только MPR идут по MPR-пути; полностью неизменный Save не переписывает и MPR. Значения bindings обновляются внутри MPR, без ложной новой идентичности атласа.
4. Recovery GC: последние N поколений **по полному пути карты**, независимо от namespace; N=5, минимум1, QSettings-ключ `recovery/terrainAtlasGenerations`. Защищены открытый документ и последнее успешное сохранение; для старых хранилищ защищается поколение фактической сохранённой MPR. Локальные leases и общий lock исключают GC во время записи, при другом открытом редакторе очистка откладывается. Неизвестный/нечитаемый manifest или ссылка останавливают удаление. Сначала удаляются manifest, затем только объекты без ссылок оставшихся поколений. Запуск в фоне после успешного Save и при обычном старте; no-op Save также допускает фоновую очистку.
5. Пустой «Очистить пак» делает только инвентарь карт/таблицы и metadata: без полного SHA, пересборки, проверки кандидата и записи RES. Новые журналы используют UTF-8 BOM. Старые журналы перемещаются без перекодирования; если старый log заблокирован, создаётся отдельный UTF-8 файл.

## Recovery: ожидаемое освобождение

Исходный живой срез скопирован:1366 файлов,81 JSON,2011485443 байт (1,873ГиБ). На копии production GC с N=5: **1 940 242 байта /1,85МиБ**,1 manifest и2 объекта. Dry-run и фактическая очистка копии совпали (`recovery-copy-final-complete.out`:2 PASS). Старые группы, у которых нельзя подтвердить последнее успешное поколение, сохраняются целиком; это приоритет сохранности над N. Новый MPR-only Save также создаёт точный recovery-manifest с переиспользованием объектов, чтобы новый успешный MPR hash был защищён. Предварительные67,87МиБ не учитывали эту необходимую консервативную защиту и заменены итоговым расчётом1,85МиБ. Остальные поколения/общие объекты нужны оставшимся manifest; освобождение всех1,87ГиБ не предполагается. Синтетический тест отдельно подтверждает защиту старого открытого поколения и последнего успешного, раздельные карты с одинаковым basename, идемпотентность и отказ при повреждённом manifest.

**Живое recovery не чистилось.** Все1366 файлов и полный их набор/хеши совпали с начальным снимком. После принятия/установки210 обычный запуск владельца выполнит фоновую очистку; при новых поколениях или другом открытом редакторе результат может отличаться.
