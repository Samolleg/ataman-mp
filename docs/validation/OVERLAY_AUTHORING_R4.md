# Overlay authoring and semantic atlas R4 validation

This increment hardens continuous overlay editing and makes the semantic-atlas
review path describe the same material/corner model already used successfully
by the authored Zone1 catalog. It does not modify atlas images, write game RES
archives, or weaken the staged MPR save contract.

## Changes

- Overlay painting now requires a valid surface pick for every pointer sample.
  Losing a thin/disconnected overlay cannot interpolate through the unprojected
  far point and create a stroke across the map.
- Pointer discontinuities are bounded to one endpoint stamp instead of
  generating an unbounded queue of interpolated edits.
- Overlay activation/deactivation mutates one detached SEC payload per touched
  sector, and overlay-only edits no longer invalidate the complete static-land
  shadow cache on every stamp.
- Overlay sculpt outlines prefer the overlay surface, fall back to terrain for
  the visual footprint outside thin cells, and remain visible through depth
  overlap.
- Authored Zone1 semantics are authoritative in both painting and atlas review.
  The review view now shows the actual named Zone1 families and corner table.
- Automatic inference no longer treats MPR tile type as material identity.
  Pure/transition tiles with different tile-type metadata can resolve to the
  same visual material families.
- Profiles generated by obsolete automatic-inference versions are rejected as
  stale and replaced with a new proposal. Custom/user-authored provenance is
  preserved.
- Atlas review has independently resizable columns, persistent geometry/header
  widths, a fixed 220-pixel preview, the exact managed profile path, and an
  explicit **Export profile copy...** action.

## Manual checks

Use only copied maps or an isolated mod workspace.

1. Add a long overlay stroke across connected cells, then deliberately leave
   and re-enter a thin/disconnected overlay while holding the mouse. The brush
   must not freeze or draw a line across the map; re-entry may resume at the
   current cell only.
2. Add and remove radius-1/radius-2 overlay surfaces continuously. Confirm the
   outline follows the cursor and record FPS; undo/redo must remain one action
   per drag.
3. Sculpt a thin overlay edge. The complete terrain-aligned orange footprint
   must remain visible, while only active overlay geometry changes.
4. Open Zone1 atlas review. Names must match Landscape Tools (for example
   Ground / common, Grass / dark, Stone / lime), and a visually mixed slot must
   show its authored mixed NW/NE/SE/SW family IDs rather than one generic ID.
5. Open Zone5_1. An older approved auto-inferred profile must not activate;
   review the new proposal. Painting remains disabled until that proposal is
   approved, while manual atlas-tile mode remains available.
6. Resize both atlas tables, close, and reopen the review. Window size and
   column widths must persist; changing Layer must not unexpectedly resize
   Name. The tile preview must remain fixed.
7. Save a draft and verify the managed profile path shown in the dialog/status.
   Use **Export profile copy...** and confirm the chosen copy is a non-approved
   JSON profile. No MPR or atlas image should become dirty from review alone.
