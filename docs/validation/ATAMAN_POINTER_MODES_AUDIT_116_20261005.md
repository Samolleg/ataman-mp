# EI-POINTER-MODES-AUDIT-116-20261005

База: main `bc951867c44b54d5b2c567288b00bc0d316608af`, VERSION116.
Запрос: почему не переносятся объекты и почему выделение срабатывает при покраске/рельефе.
Это диагностика: исходники, VERSION, установка и игровые карты не менялись. Исправление/сборка не выдавались.

## Запись владельца и перенос

Прочитано указанное владельцем видео20261005-1829-02.3395759.mp4, 4.366633с,3840×2070. Скрытый Edge декодировал кадры0/1/2/3/4с в собственную диагностическую папку `build-tests-input-audit-116-20261005`; маппер и игра владельца не запускались.

На записи активен `Autozone9camp.mob`; в «Загруженной карте» `zone9.mob` помечен «Заблокировано». Выбранные надгробия подсвечены оранжевым. Это цвет выделения неактивного MOB (`source/render/view.cpp:8423`, `:8671`), а не голубой цвет активного документа. По одной записи невозможно установить ID каждого надгробия, но режим блокировки и цвет видны явно. На2–3с появляется подсказка переноса, положение группы не меняется.

`hasEditableSelection` отвергает выбор объектов из неактивного MOB (`source/render/view.cpp:11400`). `operationSetBackup` собирает только объекты активного MOB (`:24212`), поэтому такая операция имеет0 участников. При этом старый обработчик `CSelect::keyPress(G)` напрямую создаёт CMoveAxis, обходя доступность QAction (`source/app/operationmanager.cpp:69`). Пользователь видит режим переноса без результата. Сообщение «Магнит: выберите одну деталь здания» не объясняет блокировку.

Действие без правки программы: двойной щелчок по `zone9.mob` в «Загруженной карте» либо ПКМ → «Сделать активным» (`source/app/main_window.cpp:977`, `:1027`), затем выбрать объекты заново. Автоматически переключать документ или двигать заблокированные объекты нельзя без определённого пользовательского контракта.

## Утечка жеста кисти

В `CView::mouseReleaseEvent` (`source/render/view.cpp:23320`) условие захваченного sculpt-жеста осталось без собственного блока. Оно оборачивает следующее условие RightButton, поэтому эта ветвь никогда не исполняется: один release не может одновременно быть LeftButton и RightButton.

При промахе по покрытию `mousePressEvent` устанавливает `m_sculptGestureCaptured=true`, но не начинает stroke. Release проверяет только `m_sculptStrokeActive`, а затем передаёт событие CSelect. CSelect не требует собственного предшествующего нажатия и вызывает `pickObject` (`source/app/operationmanager.cpp:195`). На native probe настоящий OverlaySculpt press по карте без покрытия дал captured1/stroke0/selected2; release дал captured1/selected0. Это подтверждённая ошибка: жест кисти изменяет выделение. GroundSculpt после промаха также не блокирует drag по одному лишь captured-флагу.

Тем же ошибочным условием не сбрасывается `m_terrainTileInformationPolicy.rightHeld()` после ПКМ покраски. Native release оставил held1. Само по себе это не доказательство выделения при нормальной покраске ЛКМ.

## Конфликт переноса с рельефом

`changeOperation` отключает editingEnabled только для трёх paint-режимов (`source/render/view.cpp:24000`, `source/core/landscape_operation_policy.h:7`). Sculpt/OverlaySculpt остаются активными после выбора Move. Настоящий LMB press/drag был принят sculpt-обработчиком: roots2/sculpt1/stroke1, XY объекта остались10,10. Hover без ЛКМ на той же карте успешно двигал оба объекта. Это отдельный подтверждённый конфликт; на записи владельца панель кисти закрыта, поэтому не подменяет объяснение блокированного MOB на видео.

## Проверки и ограничения

Диагностический `probe.cpp` использует существующий friend `runTerrainMobHeightCheck`, действующие CView/COperation/CMob из116. Перелинковка объектов собственной build-release116 заменяет только диагностическую функцию; собственный probe.exe не является новой версией и не передавался владельцу. Исходные `.o`, EXE116, исходники и установка не переписывались. Все данные probe — синтетические CMob и новый MPR из разрешённого репозиторного fixture; временные документы находятся в QTemporaryDir. Обработчики мыши вызывались в скрытом native OpenGL QWidget.
