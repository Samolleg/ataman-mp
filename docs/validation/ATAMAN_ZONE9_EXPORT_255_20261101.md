# EI-ZONE9-EXPORT-255 — источник текстур и экспорт zone9

Исправлено и установлено 01.11.2026. Ветка main, код сборки
`89c0c3b945d8c0b783190b61cf4d7120d6141ec0`, Ataman 255.
База —254, `bf509a08f41a3cd96178f6e46230067b58358194`.

## Подтверждённая причина

В 254 `prepareNeighborVisuals` декодирует текстуру в CPU worker, а
`uploadStaticTexture` помещает её в общий GPU-кэш без `textureSources`.
Последующая обычная загрузка возвращает этот кэшированный объект, не добавляя
источник. Поэтому `CTopdownExport::resolveObject` отказывает на существующей,
успешно загруженной текстуре. На zone9 первый такой объект — ID29,
`nafltr59.mod`, часть `trunk`, текстура `tree28`.

На неизменённых production-объектах 254 воспроизведены отсутствие источника,
успешный GPU upload, повторное использование того же указателя и исходный
`MISSING_RESOURCES` на ID29 за 193 мс. Проверка через настоящий MCP-мост,
штатные loader/renderer и приватную копию zone9: **17 PASS, exit 0**.
Доказательства: `work/zone9-export-255/baseline254-r4/`.
Повреждение модели/текстуры причиной не является.

## Изменение

- Точный provider/member/SHA256 исходных декодированных байтов передаётся
  вместе с `SPreparedStaticTexture` и сохраняется при создании GPU-текстуры.
- Обычная загрузка по имени также записывает идентичность источника.
  Попадание в кэш не переименовывает источник уже загруженных пикселей.
- Экспорт различает неготовую текстуру и отсутствие её источника.
  Проверки существования ресурсов, приоритета provider, SHA, ревизии и
  отказ от публикации неполного комплекта не ослаблены.
- Изменений игровых MPR/MOB/RES, моделей, UV, пикселей и правил Save нет.
