# EI-TRAVEL-SEMANTICS — исследование старых маршрутов

Дата: 2026-09-19. Анализ без изменения программы и игровых данных; версия 30.
Связано с EI-TRAVEL-DIRECTION и незакрытой игровой приёмкой EI-TRAVEL-EDITOR.

Источники прочитаны непосредственно в памяти, игровые файлы не извлекались:

Подтверждено:
1. Оригинальное описание формата определяет одну запись #exit с соседней
   зоной и соответствующим номером записи там; #deploy и #remove являются
   областями одной записи. Отдельного типа записи «появление» в этом формате нет.
2. В базовой таблице прямых game -> game ссылок нет. Пример старой пары:
   gz3g:4 -> gz3g_gz7g:1; edge:1 -> gz3g:4;
   gz7g:1 -> gz3g_gz7g:2; edge:2 -> gz7g:1.
   Обе игровые записи имеют отдельные deploy/remove. Edge задаёт связи,
   а не физический прямоугольник на карте.
3. Базовая таблица содержит 57 game-записей с обеими областями и связью,
   7 deploy-only с none и 6 deploy-only со связью. Поэтому отсутствие remove
   нельзя считать доказательством запрета перехода или повреждения формата.
4. В Жамевю найдено 5 прямых game -> game ссылок, включая два новых конца
   и три ссылки из подземелий. Само присутствие не подтверждает их runtime.
5. Новая пара по-прежнему gz1g:6 -> gz7g:6, gz7g:6 -> gz1g:4;
   обе записи deploy-only, ни одной входящей ссылки на gz1g:6 нет.
6. CTravelPanel::populate классифицирует запись только по наличию областей.
   Это корректно описывает геометрию, но ошибочно воспринимается как игровой тип.
   В source/app/main_window_travel.cpp создание добавляет #exit с none 0 и
   одной областью; редактирование назначения допускает прямую связь. Создание
   обратного перехода не строит промежуточную edge-зону.

Не установлено:
- Что конкретно пользователь называет переходом: срабатывание при входе в
  прямоугольник либо стрелка на экране выбора входа. Задан уточняющий вопрос.
- Как игра трактует отсутствующий remove: fallback на deploy, другой критерий
  или скрипт. Поиск строк в двух MOB результата не дал и не исключает скрипты.
- Обязательность edge для нового маршрута Жамевю и влияние сохранённого состояния.

Граница исследования: навыки evil-islands-modding/private-engine-reference
недоступны. Приватные исходники движка не исследовались. Поиск открытых источников
нашёл воспроизведение заголовка map.txt, но не достоверное описание fallback.

Рекомендация для следующей реализации:
- Разделить создание самостоятельного прибытия (none 0 + deploy) и полноценного
  маршрута между двумя картами; геометрию не называть доказанным игровым типом.
- Для обычного двустороннего маршрута предложить схему старых карт: два конца
  с раздельными областями и общую edge-зону с уникальными парными ID. Показывать
  оба направления и валидировать всю цепочку, а не лишь существование цели.
- Не преобразовывать существующие прямые ссылки автоматически. Не копировать
  position/figure старого edge без решения о его размещении на игровой карте.
- Причину выхода без remove подтвердить отдельным runtime сравнением сценариев:
  none+deploy, link+deploy, link+deploy+remove, парная edge-схема. Новая игра/заход
  и существующее сохранение должны различаться в протоколе проверки.
