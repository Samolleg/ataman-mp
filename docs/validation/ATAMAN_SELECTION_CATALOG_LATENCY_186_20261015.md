## Причина и изменения

В CView::viewParameters → CTableManager::setNewData → CComboDynItem::setPreferredOptions список текстур полностью доступен сразу. Заполнение QStandardItemModel само по себе не было главным расходом. Изолированная диагностическая сборка185 с таймерами показала для7164 строк: создание строк около4ms, QComboBox::setModel274–283ms, источник completion proxy около3ms. Qt заново измерял стилизованные строки QListView при каждом присоединении модели к редактору ячейки.

Для однострочного asset dropdown включён QListView::setUniformItemSizes(true). Диагностический setModel сократился до0.4ms. Полный набор строк, роли resource ID/caption/tooltips, группы, completion model и редактируемое значение сохранены; нет кеша, отложенного наполнения или сокращения каталога. После обновления ресурсов очередная панель получает свежий список.

Тот же расход найден в текстурном dropdown CModelGallery: применена такая же настройка. Каталог галереи и обработка миниатюр не сокращались.

Расширенный mouse-тест установил отдельную прежнюю ошибку: клик по disabled heading заставляет Qt активировать ранее подсвеченную первую текстуру `other`, меняет свойство `wood → other` и создаёт Undo-команду. Это воспроизведено на185 тем же новым test entrypoint. Event filter CComboDynItem теперь поглощает левый press/release/double-click по заголовкам, разделителям и пустой области viewport; выбор обычной текстуры идёт прежним путём.

В headless --ui-widget-check исходный буфер обмена теперь восстанавливается и проверяется до вложенных gallery/hierarchy/profile-тестов, которые его не меняют. Native capture/readback guard и требования его успешности не ослаблены. Обычный интерактивный запуск этим переносом не затронут.
