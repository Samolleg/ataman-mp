# Отказ исправления переходов на zone1 в120

Задача: `EI-WORLD-TRANSITION-REFUSAL-AUDIT-120-20261006`, связанная с
`EI-WORLD-MATERIAL-SEAM-FIX-119`. Запрос владельца: почему переходы не делаются.
Диагностика обычного кода и установленных данных без изменения игровых файлов.
База: main `408d19883424cbb31da7c8fa135db71c7c37ef12`, VERSION120.
Реализация120: `278d984b54c149a0258f129097247c0be54104fc`.

## Вывод

Это регресс правки119, сохранившийся в120. При согласовании рисунка общей
границы обработчик считает отсутствующее покрытие существующим тайлом.
Первая неверная команда пытается заменить покрытие zone1 в клетке175,0:
`available=false`, возвращённое значение packed tile0, планируемое значение910.
Такая же недопустимая команда подготовлена для175,1.
`CTerrainEditModel::apply` правильно отказывает с `terrain.overlay_inactive`.
Поскольку операция общая и атомарная, до пользовательских карт не доходит
ни одно из подготовленных исправлений земли или покрытий.

Отказ вызван не нехваткой места в атласе и не предупреждениями MOB.
Изменений при этих отказах нет:0 физических клеток,0 world undo commands.
Отказ повторяется даже при активной zone6, потому что связанная группа включает
zone1. В скриншоте используется группа из восьми карт.

## Первое неверное состояние и его происхождение

- `source/documents/terrain_edit_model.cpp:1610` проверяет наличие покрытия
  по типу сектора и индексу материала поверхности. Отсутствие поверхности
  передаётся из `packedTile` через отдельный выходной флаг `available=false`;
  возвращаемое число при этом0, не0xffff (`:1617–1640`). Нулевой номер сам по
  себе не означает отсутствие: slot0 может быть нормальным действующим тайлом.
- `source/documents/world_material_boundary.h:59–64` при сборе общих кромок
  сравнивает только возвращаемое число с0xffff, не читая `available` с обеих
  сторон. Так пустые покрытия попадают в список кромок.
- `source/render/view_world_terrain.cpp:835–839` собирает материалы для общего
  рисунка с такой же неверной проверкой. В `:857–875` она повторена при
  формировании физических команд. Семантические углы на границе уже могут
  быть известны из соседних активных поверхностей; это не доказывает наличие
  поверхности в самой клетке.
- `source/documents/terrain_edit_model.cpp:7477–7484` отклоняет готовую
  физическую команду, затрагивающую неактивное покрытие. Эта защита корректна
  и не должна быть снята ради получения успешного результата.
- `source/render/view.cpp:20681–20685` показывает общий отказ и записывает
  `world-refused`; транзакция в `resolveWorldMaterialBlends` ещё не применена.

`git blame` относит три неверные проверки отсутствия покрытия к реализации119
`1e995d8d3d710d620676430b40c128fbc35bd617`. Исправление clipboard120
не меняло этот обработчик.

## Native воспроизведение и причинный контроль

Собственные исходники, EXE, stdout и guards:
`build-tests-120-transition-refusal-20261006` (не включаются в Git/дистрибутив).
Пробник использует настоящие `CView::resolveWorldMaterialBlends` и модели
из120, существующие release objects120, Qt5.12.12/MinGW7.3.
Собственный entry point создаёт скрытый OpenGL context, читает восемь MPR и
расположение `deja-vu/gipat` из текущего world-map-layouts.json. Настройки,
логи и все выходы направлены в собственные scratch/case directories.
Нет записи MPR/RES, нет интерактивного редактора или передачи тестовой сборки.

| Опыт | Результат | Время |
|---|---|---|
| baseline-zone1 | Отказ overlay_inactive175,0;0 физических изменений | 33.81с |
| baseline-zone6 | Тот же отказ общей группы;0 физических изменений | 32.58с |

Каждый опыт имеет6 диагностических assertions без отказа. Успех baseline
означает успешное воспроизведение дефекта, не исправность120.
В control-zone1 изменены только две проверки перед сбором рисунка и перед
созданием физической команды в собственной копии обработчика. Указатели
`available` используются вместо догадки по packed0xffff. Маска наличия
поверхностей и пустые покрытия до/после совпадают; разрешённые физические
переходы реально меняются. Это причинный контроль, не готовое исправление
или доказательство полного регресса, Undo/Redo, сохранения и игры.
Копия helper `worldMaterialSeamSides` в этом контрольном варианте остаётся
неисправленной; полноценная правка должна начинаться с неё.

Все8 исходных MPR, world-map-layouts.json, VERSION и EXE постоянной установки
до/после опытов имеют одинаковые SHA256. Guards обоих наборов сохранены.

## Почему прежние проверки не обнаружили регресс

Проверки119 подтверждали отдельную пару zone4/zone6 и группу
zone11/zone12/zone13. Они не включали исходную связную группу из восьми
гипатских карт и этот разрыв активного покрытия на границе zone1.
Новые синтетические проверки совместного seam planning в
`tests/world_terrain_sculpt_tests.cpp:60–89` используют поля Land без геометрии
разреженного Overlay. Поэтому неверная ветка availability ими не выполняется.
Прежние PASS не подтверждают исправность исходного случая пользователя.

## Следующий необходимый шаг

Исправить проверку наличия покрытия на обеих сторонах общей кромки и обе
проверки формирования рисунка/команды; учитывать разреженность покрытий при
семантическом согласовании, не создавать поверхности или их углы по факту
наличия соседней земли. Сохранить защиту `apply` и атомарность группы.
Проверить slot0 с активной поверхностью, пустые клетки type1 и type3,
разрывы/край воды, обе активные карты, группу из8, прежнюю пару4/6, повторную
операцию, Undo/Redo, MPR/RES save/reopen и сохранность соседних внутренних
клеток. Ошибка отчёта должна включать имя карты, чтобы один и тот же локальный
адрес не маскировал соседний источник отказа.

Статус: причина установлена и воспроизведена; код проекта, VERSION, установка
и ZIP120 не изменены. Ручная приёмка швов119 и родительские terrain цели
остаются открытыми.
