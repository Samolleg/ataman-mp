# EI-CREATE-WINDOW-LAYOUT-94 — внутренние границы «Создать объект»

Дата: 2026-10-02. База установленной93: c7b83904adf7e7f4ace64b2c90a4a653ca677985. Ветка: codex/create-window-splitter-v94. VERSION:94. Полный SHA реализации и передача записываются ниже после scoped-коммита.

## Исходный случай и границы

Запись владельца20261002-1048-43.4926895.mp4 показывает узкую область свойств и чрезмерно широкое превью. Уточнение владельца: «Нельзя сместить границы внутри окна чтобы не было скрола». Это внутренние области, а не внешний заголовок окна. Кадры извлечены штатным Windows-декодером в игнорируемую build-audit-window94-video; длительность4.767с. Пользовательская запись прочитана, игровые файлы/профильный JSON не изменялись.

В93 две области были вложенными layouts в QHBoxLayout, без QSplitter. Ширина отдавалась растягивающемуся GL-превью; автоматическое resizeColumnToContents первого столбца вытесняло значения. Предыдущие проверки заголовков dock-панелей не проверяли этот случай.

## Воспроизведение

Драйвер использует настоящий MainWindow/CCreateObjectForm и технический World object, выбранный через настоящий ленивый CDynamicComboBox. Режим без игрового профиля, временные настройки, скрытые native Windows Qt-окна. Проверки: реальное нажатие/движение/отпускание на внутренней границе и границе заголовка таблицы, ширины областей/значений, горизонтальная прокрутка, повторное открытие и отдельный процесс.

Финальный исходный драйвер, связанный с неизменёнными продуктовыми объектными файлами93:5 предметных FAIL — свойства не получают достаточной доли ширины, отсутствует draggable splitter, столбец сбрасывается после refresh, нет восстановления splitter/столбца в новом процессе. Два FAIL родительских процессов являются агрегатами этих ошибок, а не отдельными дефектами. Журналы: build-tests-94-layout/repro.out, repro.err, repro-final.log. Исходная проверка отсутствующего splitter не заменена проверкой текста реализации.

Первый быстрый harness после изменения размера класса был связан с прежним main_window.o и оказался ABI-несовместимым: его дочерние сбои не являются доказательством сбоя продукта. Отброшен; окончательная проверка выполнена на полностью свежей сборке всех объектов94. Также уточнён драйвер: перед выбором типа требуется открыть ленивый popup, а списки ожидаемых размеров QSettings хранить через QVariantList. Ошибки драйвера не объявлялись PASS.

## Изменения

- Горизонтальный QSplitter с заметной8px границей, подсказкой и запретом схлопывания разделяет свойства/превью. Обе области растягиваются; начальное распределение отдаёт свойствам достаточную ширину.
- В «Параметр/Значение» сохраняется выбранная мышью ширина первого столбца. Авторасчёт длинных подписей не вытесняет редактор значения; при уменьшении окна предпочтение временно ограничивается и возвращается после расширения. Минимум прежнего растянутого последнего столбца сбрасывается, чтобы он не создавал горизонтальный scroll при сужении.
- Разделитель и столбец сохраняются отдельными ключами ui/windows/createObject в существующих QSettings, при скрытии и уничтожении. Окно, которое не открывали, не перезаписывает раскладку. Сохранение внешней геометрии90 и свойства/создание объектов сохранены.
- Тест дополнен настоящими жестами мыши, populated-table проверкой, уменьшением/расширением, обновлением свойств и независимыми процессами. Проверки таблицы не ограничены скрытым/пустым контролом.

## Приёмка и оставшиеся ограничения

Автоматически подтверждены исходное отсутствие перемещаемой границы и исправление на заполненной таблице. Нужна приёмка владельца на исходном профиле/разрешении: «Создать объект» → потянуть вертикальную границу между свойствами и превью → изменить границу «Параметр/Значение» → отменить/открыть снова → перезапустить маппер. Вертикальная прокрутка длинного списка свойств остаётся при недостаточной высоте окна.

Редактор интерактивно вместо владельца не запускался. Реальные игровые сценарии магнита/модулей, прежние ошибки clipboard/scenario и другие открытые цели не закрываются этой UI-правкой.
