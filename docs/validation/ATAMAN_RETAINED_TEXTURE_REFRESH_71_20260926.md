# EI-RENDER-RETAIN-LAYERED-TEXTURES-71 — проверка 2026-09-26

Исходный симптом: установленная версия 70 несколько раз завершалась с `c0000005` внутри `Qt5Gui.dll` после сохранения и обновления ресурсов, а один раз — позднее при обычной отрисовке. Дампы 08:46, 09:30, 10:12 и 10:34 содержат адрес `QOpenGLTexture::bind` / вызов из `render_queue.cpp`; последний случай начался после сохранения `zone6.mpr`. Данные карт не изменялись в ходе исследования.

Причина: `CView::refreshAfterResourceSetup()` вызывается после публикации ресурсов при ещё открытом MOB. `CTextureList::refreshConfiguredSources()` удаляла все составные текстуры `layers|…`, хотя объекты MOB и очередь отрисовки сохраняли на них сырые указатели. Следующий вызов `bind()` обращался к уже освобождённому Qt-объекту. Существующее правило кэша разрешало его урезать только после закрытия последнего MOB.

Проверка до исправления: отдельная OpenGL-текстура помещена в составной кэш, удерживается как указатель открытого объекта, затем выполняется `refreshConfiguredSources(true)`. Версия 70 удалила запись и проверка выдала `FAIL: composed character texture survives resource refresh while MOB is open` без намеренного разыменования освобождённого указателя. Скрытая визуальная последовательность с `zone6` до исправления превысила таймаут на ожидании завершения загрузки и не засчитана как PASS или доказательство конкретного падения.

Исправление: при наличии MOB обновляются исходные изображения и индекс ресурсов, но составные GPU-текстуры остаются живыми. После выгрузки MOB прежний путь очистки/ограничения кэша доступен. Повторное создание текстур после изменения ресурсов использует отпечаток источников в ключе.

Проверки версии 71:

- Свежая Release-сборка, `--version` = `EI Mapper Endurance Edition 71`.
- `--texture-lifetime-check`: exit 0; реальная GL-текстура выдержала три обновления ресурсов и привязки, затем была удалена при обновлении без живого MOB.
- Скрытый `--workspace-load-smoke` с `EI_ENDURANCE_RESOURCE_REFRESH_SMOKE=1`: read-only `zone6.mpr` + `zone6.mob` (1673 узла), три обновления ресурсов с открытым MOB и отрисовкой, `Resource refresh smoke complete with live MOB`, штатное закрытие `viewDeleted:1`, exit 0. Игровые файлы остались с прежним временем изменения.
- `--ui-widget-check`: новый тест и проверка общего атласа PASS, общий exit 1 из-за десяти проверок вставки/копирования через буфер обмена. Тот же список отказов воспроизведён на исходной версии 70; весь UI-набор не засчитан как PASS.
- `--scenario-layer-check`: 48 PASS, 2 FAIL из-за отказа создать резервную папку в тестовом каталоге Qt; версия 70 в этой же среде даёт те же два отказа. Набор не засчитан как PASS.
- Финализатор и независимый валидатор пакета PASS; 127 программных файлов покрыты SHA-256. Свежий EXE и пакет совпадают: `23B34DDCA1F535B6EBABEE66A263FFB6E49A169F232904403EEA7FA322002922`.
- Постоянная установка обновлена с 70 до 71: изменены 6 управляемых файлов, остальные 121 проверены, 14957 пользовательских файлов сохранены; копия прежних изменённых файлов и манифеста в `artifacts/rollback-EI-Mapper-Ataman-v70-to-71-20260926`.

Ограничение: реальное многократное сохранение и продолжительная работа в интерактивном редакторе владельца не проводились. Другие пути сбоев, не представленные этими дампами, не исключены. Ручная приёмка исходного случая остаётся открытой.
