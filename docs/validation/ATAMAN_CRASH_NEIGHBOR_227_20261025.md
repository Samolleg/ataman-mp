## Дамп и точная причина

Исходные workflow.log и crash-20261025-234751-p25940-t528.dmp только читались;
анализ выполнялся на собственной копии. Минидамп разобран через DbgHelp,
StackWalk64 с чтением сохранённой памяти и PE unwind tables соответствующих
модулей. Собственный анализатор не запускает и не подключает отладчик к мапперу.
Квитанции: `dump-stack.txt`, `resolved-stack.txt`, `dump_stack.cpp`.

Поток528: `0xc0000005`, запись по `0x29d051ff0`, RIP `0x7ffc675db3e2`,
`msvcrt.dll+0x7b3e2`, `memcpy+0x262`. Восстановленные кадры установленного EXE:

Карта адресов получена пересборкой **того же SHA226**, Qt5.12.12/MinGW7.3,
Release с дополнительным linker map. SHA256 секции `.text` установленного и
пересобранного EXE совпал:
`A1D7078EE65787B1969CC37B150CE2FD8656F77F4B0D910979184B6035A603D7`.
Это позволяет использовать карту адресов без предположения о совпадении layout.

В `unloadMob(QString())` цикл удалял zone7, оставляя указатель на него в
`m_aMob` до завершения всего цикла. При уведомлении о выгрузке второго MOB
`CScenarioPanel::scheduleRefresh()` синхронно вызывал `populate()` и
`selectedNodes()`. Последний обходил **уже удалённый первый CMob**;
неконстантный обход его `nodes()` инициировал detach освобождённого QList.
Первое неверное состояние: мёртвый CMob в публичном реестре загруженных MOB.
Минидамп не содержит полной истории аллокаций освобождённой кучи; её не выдаём
за измеренные данные. Стек, порядок кода и отдельное воспроизведение согласованы.

Гипотеза о том, что Autozone7letter освобождает GPU/анимационные буферы
удержанных объектов zone7, **не подтвердилась**. В аварийном стеке нет их
выгрузки. Регистр пути не породил второй документ: это отдельно проверяется
повторным открытием того же файла через uppercase/case alias.

## Исправление

- При общей выгрузке всё закрываемое семейство сначала снимается с реестра,
  активный/environment MOB сбрасываются; только затем выполняются уведомления
  и уничтожение. Обработчик видит согласованное живое состояние.
- Обе одиночные формы выгрузки также обновляют реестр/активный MOB до сигнала;
  документная форма освобождает свой edit lease. Никакого try/catch вокруг сбоя.
- Поиск, повторное открытие и lease MOB используют общий canonical/case-folded
  ключ. Проверка имени остаётся для старых вызовов по basename.
- Основной MOB по-прежнему передаёт собственные копии статических визуалов
  и texture leases в соседний кэш; дополнительные документы выгружаются.

## Бюджет соседей

4384/1536 МиБ — консервативная сумма стоимости держателей, а не показание
физической занятой памяти. Shared mesh/texture могут учитываться у нескольких
держателей; видимая сцена закреплена и может превышать лимит. Сам лимит не менялся.

Обнаружен отдельный связанный дефект: при refresh видимые записи переносились
во временно невидимый кэш, и `trimNeighborRenderCache()` вытеснял их **до**
повторного использования тем же набором соседей. В baseline журнале видно
вытеснение7 записей и переход от10 видимых к3 с последующей загрузкой остальных.
Теперь trim отложен до публикации нового видимого набора. Обычное закрытие/
скрытие и удаление невидимых записей сохраняют прежний лимит и LRU.

Дополнительно исправлен настоящий дефект учёта: `CSector::residentBytes()`
вызывал `QOpenGLBuffer::size()` без привязки соответствующего буфера. По
дизассемблированию используемого Qt5.12.12 это запрос GL_BUFFER_SIZE текущего
binding, а не wrapper. При нулевом element binding он создавал GL_INVALID_OPERATION.
Теперь используются CPU capacities и консервативные собственные GPU upload bounds;
подсчёт не зависит от GL binding. Тест проверил нулевые bindings, посторонний
1024-байтовый буфер и отсутствие GL error. Итоговый журнал не содержит таких ошибок.

## Проверка227 и передача

Первая полная проверка227 (`final-run`) прошла повторное использование всех10
renderer/атласов, но завершилась другим `0xc0000005` в потоке драйвера NVIDIA
после открытия zone6. Это **FAIL**, не успешный финальный прогон.
Главный поток ожидал `CPart::drawImmediate → RenderQueueContext::flush`.
Диагностический native host (`gpu-probe-run`, затем `gpu-trace-run`) установил:
`CMob::validateEditableProjection → CMob::deserialize → CLight::CLight →
CObjectBase::updateFigure/recalcFigure → CPart::attachSharedMesh` создаёт
геометрию240 вершин при `QOpenGLContext::currentContext()==nullptr`.
Неверный GPU-holder с `bufferId=0` оставался в общем кэше сборок и доходил
до draw после повторного использования. Квитанции `retained-crash-stack-all.txt`,
`gpu-create-resolved.txt`; статические/анонимные кадры без точного символа
не приписываются ближайшему именованному методу.

Исправление R3: context-free чтение сохраняет CPU-геометрию и не обращается к
общему GPU mesh cache. Копия/отрисовка/получение mesh identity создают mesh
при наличии текущего контекста; morph-upload также откладывается при его
отсутствии. Диагностические throw/печать стека существуют только в приватном
probe, в production их нет. Это отдельная причина, не переинтерпретация
исходного дампа528: тот по-прежнему однозначно указывает на stale CMob.

## Границы и инцидент диагностики

Работа не использовала приватные исходники движка, буфер обмена, понижение
приоритета, интерактивный запуск редактора, старые сборки или остановку
процессов владельца. Изменяемые игровые документы копируются; тяжёлые RES
в тестах только читаются через жёсткие ссылки. AppData/settings/automation/
backup roots тестовых процессов изолированы.

**Ошибка агента:** при извлечении `.text` вызов objcopy без отдельного
выходного EXE переписал установленный `EIMapperEndurance.exe`. Нарушена
граница «не изменять установку». Ошибка замечена немедленной проверкой SHA;
точный исходный файл восстановлен атомарно из принятого staging226.
Исходный SHA256 восстановлен и проверен:
`CA9A4C9F032B89CA3FE9F833CD7994C368A9AB3F36D284CB87F8A147589B2891`.
Начальный timestamp установленного EXE не был снят, поэтому выставлен
timestamp принятого staging226; неизменность исходного timestamp не заявляется.
Квитанция: `incident-objcopy-restore.json`. Версия227 не устанавливалась.
Оставшиеся действия с EXE выполняются только на собственных копиях.

Ручная визуальная/игровая приёмка остаётся владельцу; скрытые native-кадры и
MCP-проверка не заменяют её. Чужой суффикс ROADMAP и .mcp.json не входят в коммит.
