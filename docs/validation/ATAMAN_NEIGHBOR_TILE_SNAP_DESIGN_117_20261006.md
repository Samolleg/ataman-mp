# EI-NEIGHBOR-TILE-SNAP-AUDIT-117-20261006

2026-10-06. Исследована текущая линия main `6fc6c21000145e0f9bf8d3bcab55e3b4b55011f5`, VERSION117. Владелец показал схему несовпадающих рядов тайлов на стыке соседних карт и предложил обсудить реализацию. Объём этого пункта — диагностика и проект решения; исходники приложения, VERSION и игровые файлы не менялись. Продолжает расстановку мировых карт EI-LAYOUT-011/EI-NEIGHBOR-012; проверка швов рельефа и материалов остаётся отдельной связанной целью.

## Подтверждённая причина

- `source/render/sector.cpp:106`: позиции соседних тайлов создаются как `col*2, row*2`. Сектор имеет16 тайлов, ширина сектора32 мировые единицы. Номинальный шаг сетки тайлов — **2**, промежуточных вершин — **1**. Привязка только к целой единице тоже оставит возможный сдвиг на половину тайла.
- `source/render/view.cpp:3475–3488`: перемещение соседней карты получает новое мировое начало из движения курсора и округляет обе абсолютные координаты до **0.25**. Фаза сетки опорной карты не учитывается. Эта точность поддерживает старые дробные координаты, но не обеспечивает совпадение тайлов.
- `source/render/view_world_placement.cpp:35–59`: новое размещение уже притягивает каждую ось к краям карт в пределах2 единиц, затем снова округляет до0.25. Сетка тайлов вдоль границы не проверяется. Кандидаты X/Y выбираются независимо, без проверки реального примыкания прямоугольников: возможно притяжение к продолжению края далёкой карты.
- `source/resources/world_map_layout.cpp:96–128,245–257`: исходная расстановка выводится из разности центров областей переходов, несколько связей усредняются. Дробная координата может появиться до ручного перемещения.
- `source/app/main_window.cpp:1591–1599` передаёт результат в `CWorldMapLayoutDocument::setZoneOrigin`, который сохраняет переданное конечное значение без проверки сетки (`source/documents/world_map_layout_document.cpp:692–726`). Это раскладка в `world-map-layouts.json`, а не изменение локальных координат в MPR/MOB. По действующему коду фон раскладки не включается в Test Current Map.

Пример для обычной сетки: левая карта начинается в `(0,0)` и имеет ширину32; правая — в `(32,0.25)`. Границы по X совпадают, но ряды левой карты идут по Y `0,2,4…`, правой — `0.25,2.25,4.25…`. Текущий quarter-rounding сохраняет это несовпадение. Это проверка арифметического условия, не воспроизведение перетаскивания в GUI владельца.

Read-only проверка действующего файла раскладки Dejavu: SHA256 `02F01E4243CCFC43619C696EAE1394C34A028794EB3C3566226210C5559C5167`, schemaVersion2. В профиле deja-vu относительно указанной в JSON опорной карты вне сетки2 находятся6 из8 карт gipat,3 из4 ingos и1 из2 suslanger. Исходные данные не копировались в репозиторий; хеш повторного чтения совпал. Это подтверждает наличие сохранённых дробных фаз, но схема пользователя не определяет конкретную пару карт.

## Предложенная реализация

1. **Общая сетка относительно постоянной опорной карты.** Получать origin опорной карты по `componentAnchorZoneId` из документа раскладки; опора не зависит от активной карты и не обязана начинаться в `(0,0)`. Для каждой оси:

   ```text
   snapped = anchor + 2 * round((requested - anchor) / 2)
   ```

   Округление должно быть единым для drag/new placement/manual align и детерминированным в положительных, отрицательных координатах и половинных случаях. Если опора отсутствует, явно диагностировать это; не подменять её текущей открытой картой. При движении опоры отдельно определить перенос сетки/компоненты, а не пересчитать все координаты молча.

2. **Совмещение краёв при реальном примыкании.** Общая сетка даёт совпадение рядов, а магнит убирает зазор/наложение по нормали к стыку. Например, справа: `newX = peerX + peerWidth`; параллельная координата Y остаётся на общей сетке. Для четырёх сторон проверять перекрытие интервалов вдоль стыка и совместимость с общей сеткой. Угловой стык — отдельный кандидат. Выбирать совместимую пару X/Y как одно положение, подсвечивать выбранную границу; порог в пикселях viewport с удержанием выбранного стыка исключит скачки между близкими кандидатами при изменении масштаба камеры.

3. **Один расчёт для существующей и новой карты.** Общий небольшой UI-независимый расчёт в resources, используемый `updateNeighborLayoutDrag` и `updateWorldMapPlacement`. На каждом движении только вычисление и preview; сохранение один раз после отпускания/подтверждения. Реальную высоту/mesh не пересобирать при каждом движении. Рельеф, MOB-фон, области переходов и hit testing должны использовать один и тот же origin.

4. **Понятные элементы управления.** В режиме расстановки галочка «Привязка к тайлам», включённая по умолчанию, и подсветка совмещаемого стыка. При выключенной галочке оставить свободное размещение для старых раскладок. Существующие позиции не менять при открытии JSON. Для уже расставленных карт отдельное действие «Выровнять по тайлам» с preview изменений; при нескольких примыкающих картах можно применить выравнивание выбранной группы относительно одной опоры одним действием.

5. **Отмена и сохранность.** Esc возвращает точные исходные координаты, отпускание/подтверждение применяет одну операцию; Undo/Redo возвращают/повторяют именно мировую раскладку. Нынешний drag напрямую пишет JSON, отдельная undo-команда раскладки для этого пути ещё потребуется. Сохранение через документ с имеющимися QLockFile/QSaveFile и проверкой внешнего изменения, при отказе preview возвращается к сохранённому состоянию. Локальные MPR/MOB, переходы и исходные текстуры от перестановки не пересериализуются.

У старого соседа может быть другая фаза сетки. Тогда совмещение с ним и общей опорой одновременно невозможно: обозначить несовместимый стык и предложить явное выравнивание контактной группы, сохраняя опору. Простое `round(origin/2)*2` без учёта опоры либо разные опоры для разных сторон снова дадут несовпадения.

## Границы результата и проверки реализации

`source/render/tile.cpp:149–150` добавляет к номинальной сетке локальные `xOffset/yOffset /254`. Привязка начала карты совмещает **сетку тайлов**. Она не исправляет разные высоты, локально деформированные крайние вершины и несовместимые рисунки материалов. Для них сохраняются отдельные операции обработки шва; перестановка не должна незаметно менять terrain-данные.

После поручения реализовать нужны focused tests общего расчёта: четыре стороны, углы и T-стык трёх карт, схема четырёх карт владельца, разные размеры в секторах, опора с дробным origin, отрицательные координаты/половинные случаи, переключение активной карты, отсутствие опоры, старый дробный JSON без автоматического ремонта, несовместимые фазы, чужое изменение JSON и отказ сохранения. Native проверка обоих путей drag/new placement должна подтвердить фазу2, отсутствие зазора, preview/commit/Esc/Undo/Redo и повторное открытие JSON. Соразмерный регресс — навигация к соседям, перенос объектов, покраска/рельеф у стыка и точность hit testing.
