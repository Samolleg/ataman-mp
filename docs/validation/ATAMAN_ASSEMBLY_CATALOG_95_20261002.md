# EI-ASSEMBLY-CATALOG-95 — каталог готовых модульных сборок

Дата: 2026-10-02. База: cca391778890cd61076fc7ff8f40fd601df8ef45 (94). Ветка: codex/assembly-catalog-v95; VERSION95. SHA реализации: 3cbf3cedb9390cc1d490de000592d0b7b7006319. Постоянный путь не меняется.

## Поручение и критерии

Готовые составные постройки из нескольких деталей должны храниться в каталоге, размещаться/выделяться/двигаться целиком и разбираться обратно. Постоянную группировку подтвердил владелец. Новая функция использует обычный код проекта и синтетические данные; приватный код движка, исходный Endurance, игру и профильный JSON не меняет. Чужие изменения ROADMAP/отчёта52/QM, отчёт86 и документ для автора моделей сохранены вне scoped-коммита.

До95 существовали одиночные модели, стыки деталей и временное групповое выделение. Обычная вставка не хранит редакторскую группу и размещает детали относительно их локального рельефа. Проверяемое новое поведение: полный состав, общий мировой кадр на склоне, независимые ID, внутренняя Parent Id, каталог/поиск/категория/остров, мышь/Enter/Esc, Ctrl+C/V, Undo/Redo и независимое открытие JSON/MOB.

## Реализация

- ObjectAssembly schema1: UUID, имя, категория/остров, 1–512 деталей, offset в мировом кадре, parentPart по индексу, полный toJson и проверенные source/clean raw MOB subtrees. Циклы/внешние родители/неполные шаблоны/нулевые кватернионы отклоняются до полной вставки. Состав ограничен архитектурой/техническими объектами; неизвестные игровые байты сохраняются механизмом исходных транзакций.
- Capture разбирает/сопоставляет полный исходный MOB один раз для выбранного комплекта. Нет сканирования всех MOB на каждом выборе объекта. Каталог остаётся model-catalog.json рядом с profile database.res; неизвестные поля и существующие русские имена/текстуры/стыки сохраняются, запись атомарная с проверкой внешнего изменения.
- Редакторские instance tags не сериализуются как игровые Parent Id. Save сохраняет metadata отдельно в JSON с SHA-256 MOB и точными ID/типами/моделями. Старые группы после внешней смены MOB не подставляются к другим объектам. Ошибка JSON после записи MOB явно частичная, dirty остаётся для повторной записи; это не общая атомарная транзакция двух файлов. Путь сохранения переходов также обновляет метаданные.
- Комплект вставляется с новыми ID, включая занятые светом/звуком/частицами; внутренние игровые родители переназначаются. Preview следует мыши одним world frame, Enter/ЛКМ подтверждает, Esc удаляет все временные детали. Исправлен Enter без числа: прежний CMoveAxis переключал инструмент, не завершив pending placement. История размещения/копирования/разбора атомарна на уровне редакторского действия.
- Выбор компонента выбирает экземпляр целиком. G/R используют мировую геометрию и один центр на склоне; Undo команд группировки восстанавливает фактический MOB даже после смены активного документа. Разбор возвращает отдельные детали, Ctrl+C/V одной группы создаёт самостоятельную группу и переносит внутренние ссылки.
- Новый каталог содержит плитки состава, подписанные название/количество частей, список моделей/основных текстур, русско-технический поиск, восемь категорий с общими векторными иконками, острова, переименование/перераспределение/замену состава/удаление библиотечного образца. Изменение образца не меняет уже поставленные экземпляры. Геометрия/разделитель сохраняются.
- CPU-композит рисует детали с разными основными текстурами в одном depth buffer. Только видимые плитки, один worker/кэши, отмена закрытия, bounded preview60000 triangles. Новый resizeEvent запускает превью вновь открывшихся плиток. Native-снимок обнаружил text-size QRect вместо полной плитки; добавлен sizeHint и содержательная проверка фактического visualItemRect.

## Границы и следующая приёмка

Руководство: docs/OBJECT_ASSEMBLIES.md. В95 магнит поддерживает одну деталь после разбора; группа Scale меняет комплекцию отдельных деталей. Существа/ловушки и объединение в одну игровую mesh-модель не реализованы. Плитка использует базовую геометрию/основные текстуры; дополнительные текстуры и комплекция сохранены, но не полностью воспроизводятся в превью.

Владелец проверяет реальный комплект: сохранить MOB → выделить части → Сборки/Сохранить → категория/остров/поиск → Разместить/ЛКМ → G/R на неровном участке → Ctrl+C/V → Esc/Undo/Redo → Разобрать/Undo → сохранить/закрыть/открыть MOB. До этой приёмки родительская задача модулей/стыков и прежние реальные случаи патрулей/воды/кистей/окон не закрыты. Это проверенная новая функция с явно открытыми прежними отказами, не полное подтверждение исправности маппера.
