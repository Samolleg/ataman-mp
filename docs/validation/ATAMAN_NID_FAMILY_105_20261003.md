## Причина и исправление

На104 обработчик nidAllocationRequested оставлял локальный ID при отказе семейного suggestReplacementNid. При исчерпании эффективного диапазона это обходило меж-MOB проверку. Также кэш семейного отчёта не включал несохранённую смену ID другого открытого MOB. Локальная проверка активного MOB сама по себе эти случаи не предотвращала. Фактический конфликт пользовательской карты не воспроизводился.

На105 отказ всегда даёт0, создание прекращается. Отдельный структурный снимок семейства обновляется при изменении состава/активного MOB, скриптов, диапазонов, профиля/путей и метаданных известных файлов. Каждый ID дополнительно сравнивается с текущими объектами и auxiliary ID всех открытых MOB, а также сессионными резервами. ID0 не выдаётся; диапазон включает максимальное значение. Пропавший/нечитаемый MOB, непригодный живой снимок или неразрешённый динамический AddMob не допускают подбор; ошибочный снимок проверяется заново при следующей попытке.

Этот путь не подключает базу моделей/ресурсы и отключает анализ частей фигур. Кандидаты dirty MOB строятся при обновлении структурного контекста, не для каждого участника пакета. Автоматический обход моделей/текстур и запись каталога не возвращены.

Отказ посреди сборки/витрины удаляет все её новые узлы, сохраняет исходное выделение и историю. Связанный обычный Ctrl+V прежде пропускал неудачные объекты; теперь также отменяет весь пакет. Одиночное размещение показывает причину отказа ID. Уже существующие ID автоматически не меняются.

## Открытая ручная проверка

Владелец повторяет добавление143 реальных моделей при открытых связанных MOB, проверяет ID, Undo/Redo и сохранение. Тяжёлые реальные ресурсы/первое холодное чтение не измерены этой синтетикой. Проверка отказа при исчерпании диапазона проводится владельцем в собственной тестовой копии; исходные карты автоматически не исправляются. Если семейство не удаётся разрешить полностью, редактор отказывает, а не угадывает ID. Резервы сессии консервативны, в том числе после отменённых попыток, и очищаются при закрытии всех MOB; ручная смена уже имеющихся ID и скрытые внешние семьи не получают автоматического ремонта. Родительские задачи102/103/104 и рабочая карта не объявляются принятыми по результатам сборки.
