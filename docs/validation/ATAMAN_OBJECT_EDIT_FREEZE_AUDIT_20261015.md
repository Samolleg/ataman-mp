## Подтверждённые тяжёлые пути в исходниках, приоритет исследования

1. **Повторная генерация миникарты после правок, UI thread.** MainWindow сигналы mobStateChanged/loadedMapStateChanged и dirty-title планируют scheduleViewportMinimapRefresh, default delay250ms (main_window.h). Если генерация не locked, timer вызывает refreshViewportMinimap → captureMinimapScene. Последняя делает два полных прохода карты в resolution(sectorWidth*128,sectorHeight*128), два glFinish и readback toImage; затем bake/grade/MMP encode. Всё выполняется синхронно в GUI. Поэтому GPU paint telemetry не учитывает полную такую паузу. Источники: main_window.cpp:1853,4936,5090; view.cpp:8940,9080. Это сильный общий кандидат задержек после вставки/фиксации движения, но его фактическая длительность в журнале не размечена. Lock останавливает будущий refresh; это диагностический контроль, не программное исправление.
2. **Копирование K обычных объектов повторно разбирает MOB K раз.** selectedObjectToClipboardBuffer вызывает rawObjectTemplateBytes на каждый объект; без встроенного template тот заново loadBytes двух полных документов original/clean и CMobSemanticDiff::compare. При размере около2.17MB и множественном выборе объём работы растёт с K. Пакетный rawObjectTemplatesBytes уже существует и используется сборками, но обычная Ctrl+C ветка его не использует. Источники view.cpp:25116/25233, mob.cpp:2822/2869. Это доказанная повторная работа по коду, её миллисекунды и количество копируемых объектов журнал не содержит.
3. **Вставка: проверка ID может синхронно строить полный validated MOB candidate.** allocateFamilyNid при смене structural digest запускает mobFamilyValidationRequest(true) и CMobFamilyValidator::validate в вызывающем GUI. Для dirty MOB request сначала вызывает buildValidatedCandidate; candidate builder полностью сериализует projection, строит/проверяет lossless transaction, может перестраивать raw sequence. Соответствующие candidate/NID сообщения присутствуют в указанных паузах. Валидацию нельзя просто отключить: она защищает ID/неизвестные поля. Источники main_window.cpp:5635/5736, mob.cpp:2091.

## Вывод и следующий шаг

Журнал подтверждает интерактивные паузы между короткими кадрами, но не различает Ctrl+C/первую вставку/drag/commit. Общая причина класса — тяжёлая синхронная работа GUI, с перечисленными конкретными путями; доля каждой функции пока гипотеза. При отдельном исправлении начать с измерения полного command latency и minimap capture на одном воспроизводимом наборе, затем устранить повторные MOB parses/serializations и автоматические лишние minimap captures, сохранив validated ID/save gates и Undo/Redo. Terrain query оптимизировать отдельно под измерение. Код/сборку текущим аудитом не меняли, версия не увеличивается.
