## Изменения и причина

1. Меню «Поля»: ID / Имя объекта / Модель / Текстура, произвольная комбинация. Для каждого простого терма — ИЛИ между полями; несколько термов — И. Пустой набор флагов даёт 0 простых совпадений, пустой запрос показывает всё. Флаги сохраняются в QSettings `ui/outlinerSearchFields`, по умолчанию все четыре.
2. Простой цифровой ID — точное числовое совпадение (включая ведущие нули). Запрос 81 в режиме только ID не находит 816. Это исключает шум при поиске известного ID. Частичное совпадение явно доступно через `id:81`, точное строковое — `id=81`. При одновременно включённом имени/модели/текстуре число может встретиться в их тексте по общему правилу ИЛИ.
3. Имя/модель/текстура — contains без регистра. Модель включает каталоговый alias и сериализованные части тела юнита. Полевые `:`, `=`, `field:~value` и свободный `~value` сохраняют расширенный поиск независимо от флагов. Свободный fuzzy использует общий набор legacy-полей (в том числе type/database/MOB/validation), полевые значения сравниваются по каждому имени ресурса. Подсказка описывает различие.
4. Поисковые поля кэшируются отдельно по строкам дерева, обновляются при штатном refresh и сигнале CChangeProp::updateParam (редактирование/Undo/Redo без перестройки дерева). Асинхронное завершение визуальной подготовки юнита распознаётся по изменению публичных rendered-полей. Фильтр не загружает модели, текстуры и не вызывает runtime providers. Счётчик найдено/всего сохранён.
5. Корень дефекта раскрытия: `markNodes` безусловно раскрывал всех родителей и дерево поведения, `focusLogicSlot` — родителей и слот. Дополнительно `revealNode` вызывается не только для явного действия: view.cpp:15881/15888 — picking в 3D, 16998 — восстановление выделения. Все эти обычные пути теперь сохраняют развёрнутость. Выбран сам объект; для current/scroll используется видимый предок без выделения всей группы. `scrollToItem` не получает скрытого потомка, поскольку Qt сам раскрывает его родителей.
6. Поиск раскрывает ветки с совпадениями; очистка возвращает сохранённое состояние. Новые строки, созданные во время поиска, тоже получают исходное состояние. При быстром очистить→новый запрос до debounce прежний snapshot не перезаписывается. Существующие пользовательские клики раскрытия/сворачивания сохранены.
7. Добавлены русские строки и пересобран qm: 3330 законченных переводов, 0 unfinished.
