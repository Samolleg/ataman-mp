# Сверка переходов с исходными мапперами

14.10.2026. Поручение владельца: посмотреть код старого маппера, от которого
сделан форк. Основная задача восстановления прежнего вида переходов открыта.
Оба предложенных варианта177 отвергнуты; их программа и RES не устанавливались.
Не продолжать передачу прежних кандидатов.

## Непосредственная база форка Ataman

Endurance `19168b91a10562525fb6c83b665275c2fd43cf4c` — назначенная в AGENTS
исходная база Ataman. Сравнение с установленной131,
`5a81105903c4462a6694f2dd1aefcbdf5086404b`, подтвердило:

- `source/render/tile.cpp` совпадает целиком, включая UV, обрезку и повороты.
- Все файлы `assets/resources/terrain_blend_masks` и их QRC совпадают.
- `CTerrainVirtualAtlas::generateTile()` и `resolve()` совпадают целиком.
- Формулы с углом0.62 и боковым контуром0.50 уже есть в этой исходной базе.

Таким образом, они не возникли при добавлении HD-ядра132 и не исчезнут от
возврата одного EXE к131. Это не доказывает, каким путём впервые получены
конкретные сохранённые тайлы650/676 в zone11_96774500b145.

Отдельное отличие Ataman — `worldBoundaryTile()`, добавленный в119 коммитом
`1e995d8d3d710d620676430b40c128fbc35bd617`. В нём генерация вызывается без
материала кисти и поверх результата изменяется полоса края. В обычной кисти
базы форка передаётся requestedMaterialId; он участвует в выборе языка маски.
Потеря этого контекста — конкретное различие путей, а не установленное
происхождение всех дефектных сохранённых тайлов.

Для независимого эталона из Git извлечены и скомпилированы точные источники
19168, без изменения рабочего кода и установки. Прогон двух запросов через
старый production `resolve()` завершился успешно. Логи, исходники и входы:
`build-upstream-terrain-reference-20261014/fork-base`, `fork-reference.cpp`,
`fork-plan.json`, `fork-pixels.json`, `fork-comparison.json`.
Выбранные прежним кодом маски: R44 Stone outer и R77 Snow edge.
Их входные текстуры взяты из нынешнего пака: полученные изображения являются
эталоном работы старого алгоритма на указанных входах, а не доказательством
восстановления прежнего вида пользовательской карты.

## Более ранний исходный EI_maper

`konstvest/ei_maper`, `1cebe83d547beaac0cce919fe8b5b801ceee59bb`, — исходный
upstream Endurance по NOTICE. Этот маппер не создаёт переходные изображения:
`resourcemanager.cpp:641` загружает готовые страницы RES,
`tile.cpp:20` читает slot/page/rotation из packed-данных,
`tile.cpp:89` задаёт UV и поворот, а `landshader.fsh` выбирает texel атласа.
Ручная кисть меняет индекс/поворот готового тайла.

Обрезка UV в этом старом upstream отличается от Endurance, но в самой базе
19168 и установленной131 она уже одинаковая. Это отличие нельзя выдавать за
найденную регрессию Ataman или исправлять вслепую.

## Состояние передачи

Предыдущие предпросмотры177 не были эталоном старого маппера: сначала менялась
геометрия заглушек, затем подбирались другие готовые тайлы HD-пака по четырём
материалам. Оба подхода отвергнуты владельцем и помечены REJECTED_APPROACH.txt
в своих приватных каталогах. Scoped-коммиты a5fff0c8/f1f3652e остаются в истории;
f1f3652e является исследовательским изменением, не принятым релизом.

Программа остаётся установленной131, SHA256 EXE
`F75C9A463F7CC03FD6C9A1430645EA5C8F4B5014AF06594CA367372C5669C477`.
RES независимо изменился после подготовленного нами снимка7933; при последнем
чтении SHA256 был `1139a94ee272071076e189c17e07913cd541b009796f1df49eba42985dbc31da`.
Ни один наш кандидат не применялся. Старые guards RES более не актуальны;
их нельзя использовать для будущей установки.

Следующий шаг основной задачи: сверять конкретный живой путь выбора перехода
и его материал/источник с поведением19168 на тех же входах. Прежние кандидаты
не продолжать, не заменять рисунок подбором похожего stock-тайла и не
перерисовывать контур произвольной формулой. Ручная/игровая приёмка не проведена.
