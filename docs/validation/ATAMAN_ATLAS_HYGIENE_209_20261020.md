## Реализация

- HD-конверсия выбирает варианты для конкретных клеток; импортирует по стабильной идентичности банка/якоря/варианта, канонического края и назначения. Поворот передаётся битами SEC; четыре картинки на поворот не создаются. Сначала проверяется готовый вариант без вмешательства; только если его видимая граница отличается, создаётся единственный используемый вариант с каноническим старым краем. BC1-палитры и селекторы вращаются без переквантования. После проверки стыков спекулятивный атлас отбрасывается, принимаются только импорты реально принятых клеток. HD256 и уже помеченные HD-результаты повторно не переводятся; происхождение хранится в профиле.
- Перед применением HD показан рассчитанный прогноз компактных страниц, DXT1 с mip и RGBA базовых уровней. Он получен из того же кодирования и удержания208, что используется при сохранении, а не из количества всех вариантов банка.
- Обычные Save/Save As, editable modern draft, финальная modern-публикация и общая кисть проходят подготовку компактного атласа. Удерживаются land/активные overlay, все анимационные диапазоны, обязательные thumbnails и uniform seeds, категории палитры, назначения/классы/происхождение и семантические поля по договору208. Native128/256 пакуются отдельно, независимые DXT-блоки переносятся точно; пустые native-страницы не сохраняются. После перенумерации начинается новая история Undo/Redo, старые команды со старыми номерами слотов не остаются активными.
- Компактный результат больше126 страниц отклоняется до публикации; от100 показано предупреждение. Дополнительный жёсткий guard есть в общем валидаторе конечного сохранения, байтовом и транзакционном MPR-координаторах и пакетном сохранении. Промежуточная проверка транзакции разрешает большие атласы до сжатия. Старый raw fallback без рабочего атласа закрыт: при отсутствии подтверждённой привязки сохранение явно отказывает до записи, предлагая восстановить атлас/каталог. Ошибка называет фактическое число, предел126 и предлагает сократить используемые варианты/материалы либо сжать атлас.
- Публикация, включая SaveEditableModernDraft, получает собственный namespace карты с hash. Даже уже плотно упакованный голый namespace при «Сжать атлас карты» мигрирует под hash. Прежний hash namespace удаляется только после успешной новой пары и полного неизменившегося читаемого инвентаря MPR Dejavu/Base. Save As сохраняет исходную публикацию для прежней карты. Голые исходные namespace не удаляются никогда.
- «Очистить пак» расположена в «Диагностика и атлас». Фоновая подготовка читает все MPR Dejavu/Base, показывает две таблицы: удаление и сохраняемые исходники/используемые публикации. Поля: namespace, страниц, МиБ, использование; отдельно точный размер всего пака до/после. По умолчанию отмена. Удаляются только hash namespace без MPR-ссылок, их JSON-профили и семантика. Перед записью повторно проверяются SHA исходного RES и полный инвентарь. Сборка нового RES доказывает сохранность остальных payload/timestamps; существующий координатор выполняет backup, staging/reopen, QSaveFile и readback.
