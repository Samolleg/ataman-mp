## Подтверждённая причина

Несогласованные критерии допустимости перехода:

1. `CTerrainWorkingAtlas::installCatalogVariants`, source/documents/terrain_virtual_atlas.cpp:5233, пропускает регистрацию нового перехода, если `hasSelectableAuthoredCandidate` находит совпадающие углы и runtime type в исходном каталоге.
2. Этот helper (:5262) не учитывает `routeOwnerMaterial` и `canonicalGeneratedRoute`. Исходный каталог может содержать ранее сгенерированные переходы с определённым направлением, а не только нейтральные авторские тайлы.
3. `CTerrainTransitionCatalog::selectCandidates`, source/documents/terrain_edit_model.cpp:929–955, исключает переход другого владельца. Таким образом, новый вариант ошибочно подавлен, старый недопустим, хотя разрешение/генерация уже сообщило успех.
4. Финальная `makeVirtualStrokeResolution` не находит допустимый вариант и выдаёт `terrain.virtual_release_unresolved`. Мазок отклоняется целиком. Выборочность зависит от сочетания соседних материалов и направления перехода; одинаковые углы не всегда означают взаимозаменяемые изображения.

Это отдельный дефект от исправленного в98 двойного отражения Y; тот код присутствует в100.
