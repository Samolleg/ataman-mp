## Причина и результат

У неизменённой `zone5_1.mpr` namespace `zone5_1`, три страницы /192 слота.
Страницы находятся в HDPack_Terrain.res, отдельного встроенного профиля нет.
Профиль корректно формируется при открытии, но кнопка сравнивала его JSON с
пустым RES payload и ошибочно требовала сохранить карту. Перед commit стояла
такая же безусловная проверка.

249 допускает отсутствие служебного профиля. При наличии профиль сначала
читается штатным декодером; форматирование JSON и поддержанная миграция схемы
не считаются пользовательским изменением. План сохраняет точные исходные
bytes/отсутствие member; добавление, удаление, неоднозначность или замена после
расчёта отклоняются перед записью.

У точной исходной zone5_1 все192 слота нужны: сжатие сообщает «Атлас уже
упакован. Файлы не изменены». Перестановка кадров анимации и нормализация старых
SD-полей MP при HD-страницах сами по себе не являются экономией. Новый namespace
создаётся при уменьшении страниц или физического объёма текстур. Принудительная
публикация при Save по-прежнему создаёт собственную identity и native MP sizes.

Связанная инъекция отказа выявила прежний пробел commit: сравнивались только
декодированные базовые пиксели. Усиленная проверка сохраняет SHA всех полных MMP
и один раз читает каждую страницу перед записью. Изменения mip-уровней,
обрезание и замена той же длины теперь также отменяют публикацию.

использовались только для чтения; запись выполнялась в собственных временных
каталогах. Игровые payload не входят в Git или комплект программы.

- `baseline248-run.log`: production UI/WGL на точной копии подтверждает чистую
  карту и воспроизводит исходный ложный отказ248. Это ожидаемый FAIL регресса.
- `guard249-final-run.log`: **84 PASS, exit0**, скрытый production UI/WGL249.
  Точная исходная карта даёт no-op без записи и дублирующего namespace.
- Контролируемая копия с одной лишней неиспользуемой страницей: **4→3**,
  256→192 физических слота; DXT1 2,67→2,00 МиБ, RGBA base16→12 МиБ.
  Отмена побайтно сохраняет оба файла; подтверждение действительно публикует
  пару, принимает чистый baseline и повторно открывает карту. Повторное сжатие
  не пишет файлы.
- Сохранены точные декодированные пиксели всех удержанных слотов, runtime types,
  все SEC bytes кроме намеренной перенумерации слотов, материалы и параметры
  высоты. Секторы сопоставляются по координатам, поскольку смена namespace
  меняет порядок RES members. Посторонний member и timestamp, исходные страницы
  общего namespace сохранены точно.
- Dirty MPR, другой/повреждённый/пустой профиль, добавление/удаление/замена
  профиля после расчёта, внешняя правка MPR, обрезание mip и same-size MMP edit
  отказывают без замены данных. Форматированный профиль и схема9 принимаются;
  оба полных shared-corner field сохраняются и перепривязываются, чужой hash
  профиля отклоняется.
- `raw249-widgets.log`: focused штатный `--ui-widget-check`, exit0;
  кнопки/сигналы сжатия и очистки, nativeAttempts=0. Буфер обмена не используется.

Начальный тестовый RES-builder не создавал пустые members; этот повреждённый
вход затем построен явной правкой DataSize в собственной тестовой копии.
Промежуточные FAIL по no-op, ошибочному сравнению порядка SEC и mip-guard не
считались успешными проверками; окончательный84-check прогон проходит целиком.
