# Ataman200 — подвисания при выставлении патрулей

2026-10-17. EI-PATROL-STALLS-200. Поручение: найти блокирующий вызов,
убрать лишнюю работу, сохранить линии/маркеры, Undo/Redo и сохранение,
проверить связанные сценарии и установить. База main199:
`12baa4eb4badfa8c2a5fc43baae6972f7275c0e0`.
Диагностика исходного инцидента:
[аудит199](ATAMAN_PATROL_STALL_AUDIT_199_20261017.md).

## Подтверждённая причина

Владелец подтвердил воспроизведение без движения мыши, затем сообщил о
текущем подвисании при добавлении точки. В установленном процессе199
PID6636, GUI thread27264 сняты24 стека. Большинство попало в nvoglv64
через Qt5Gui QOpenGLShaderProgram::setUniformValue(const char*, ...).
Внутри драйвера наблюдался GetExitCodeThread/ZwQueryInformationThread.
Стеки содержали CLogic::drawHelp, CLogic::draw, RenderQueueContext::flush
и CView::draw. Это не только стоимость изменения геометрии маршрута.

Точный вызов — **glGetUniformLocation**. В Qt5.12 строковый setter сначала
запрашивает расположение параметра у драйвера. Возвратный адрес
`Qt5Gui+0x37a926` следует за косвенным вызовом dispatch slot0x2f0, до
UniformMatrix4fv. Слот соответствует GetUniformLocation в установленном
qopenglfunctions.h. Аналогичны стеки scalar/vector setters. Адреса приложения
сопоставлены с linker map из объектов199; SHA-256 секции .text нового
приватного link совпал с установленной199:
`8652fc360d1ed114bb18e5dd5e778fb1da5bf1d5e0624d7ab4266aad9b1c795c`.

Приватные свидетельства в `build-patrol-stalls-200-20261017`:
`live-stacks.txt`, `mapped199.map`, `mapped199.exe`, WCT-снимок,
baseline/candidate native outputs и receipts. WCT не показал отдельного
объекта ожидания; WPR CPU не стартовал из-за Windows policy0xc5585011.
Стековый sampler приостанавливал только GUI-поток на короткое время
с гарантированным Resume до записи/разрешения имён; первый снимок20ms,
остальные ограничены20ms. Процесс редактора не завершался и его память
не изменялась. Старые многосекундные паузы зарегистрированы до sampler.

## Изменения

- Общий кэш uniform/attribute locations привязан к QObject программы,
  её GL ID и потоку. Отрицательные locations также сохраняются. Удаление
  QObject очищает запись; явный linkShaderProgram сбрасывает её перед relink.
  Все затронутые программы используют эту границу. Несвязанные программы
  и вызовы из чужого потока сохраняют прежний uncached путь.
- Горячие setters земли, объектов, линий, общей настройки света/теней,
  preview и очередей получают целочисленные locations. Значения, GLSL,
  геометрия, ширина/цвет/порядок линий и shader branches не изменены.
  Входы первого патруля подготовлены при инициализации object shader.
- Helper-проход пропускает обычные узлы без логики. Отбор маршрута
  использует фактические projected линии, радиус помощи и bounds маркеров,
  а не положение владельца. Пересекающий экран длинный маршрут сохраняется
  даже с закадровыми концами. Отдельно отбираются закадровые patrol/look
  модели. Scope действует только во время helper-прохода; picking сохраняется.
- Родственная проверка выявила в199 неточное Undo сдвига патруля с дочерними
  look-точками: обратное сложение float не всегда восстанавливает биты.
  CChangeLogicParam теперь хранит before/after снимки полных позиций для
  координат патруля и восстанавливает их через существующий movement API.
  Другие свойства и команды сохраняют прежний путь.
