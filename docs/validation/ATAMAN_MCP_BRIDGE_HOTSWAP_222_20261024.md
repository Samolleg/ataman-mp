## Каталог и протокол

- Редактор экспортирует `mcp_catalog`: protocolMajor1, catalogVersion1, VERSION,
  tools, resources, resourceTemplates, instructions. `mcp_resource_read` обслуживает
  содержимое ресурсов. Мост берёт каталог/ресурсы/инструкции отсюда, а проверку
  аргументов пересылаемых инструментов выполняет редактор. Три инструмента
  list_instances/connect_instance/disconnect_instance принадлежат транспорту.
  Неизвестный старому мосту будущий инструмент больше не блокируется его списком.
- Новый запрос добавляет protocolMajor1 к прежнему newline JSON/id/secret/method/
  arguments. Отсутствующее поле принимается как1; иной major явно отклоняется.
  Ответ старого218–221 `Unknown read tool` на mcp_catalog включает запасной каталог
  один раз за подключение. Неподдерживаемая схема/major нового каталога возвращает
  явную ошибку обновления/переподключения, без тихого fallback.
- tools.listChanged объявлен в initialize и server/discover. Уведомление
  notifications/tools/list_changed не имеет id. Отправляется после подключения,
  при отключении и изменении каталога/версии. Qt event loop работает, даже если
  stdin клиента молчит; один поток читает ограниченные кадры, основной поток
  последовательно обслуживает сокет и stdout. EOF штатно завершает мост.
- Каталог опрашивается раз в секунду в простое и по запросам tools/resources.
  На время незавершённых фоновых операций опрос приостановлен: его короткий
  deadline не должен уничтожать поток длительного штатного commit. Завершённые
  операции снимают эту паузу, забытые операции имеют ограниченный срок.
- При новом MCP-подключении единственный доступный включённый редактор отдаёт
  метаданные уже для initialize/tools/list. Рабочая карта автоматически не
  выбирается: чтение/правка по-прежнему требуют connect_instance. Это даёт
  актуальный начальный список клиенту, игнорирующему уведомления. При нескольких
  редакторах мост не угадывает выбор; для такого клиента оставляют включённым
  один нужный редактор перед переподключением. disconnect_instance запрещает
  повторное автообнаружение до connect_instance или нового MCP-сеанса.
- Набор222 одинаков в режимах Чтение/Правка; полномочия проверяются в редакторе.
  Смена режима, как221, пересоздаёт канал/ID. Нужны list_instances/connect_instance;
  мост не включает режимы и не запускает редактор. Актуальные instructions также
  доступны в ataman://tools; клиент не обязан менять уже сохранённые инструкции
  initialize посреди сеанса.

Мост218–221 с редактором222 сохраняет прежние инструменты/проводной протокол.
Уже работающий221 не приобретает новый код сам: после первой установки222 надо
один раз штатно переподключить MCP-сервер. Далее мост222+ получает будущий каталог
совместимого редактора без замены своего процесса. Новые несовместимые major
требуют обновления моста, что явно сообщается.

## Установка и откат

Канонический установщик: packaging/install_program.ps1; общие функции:
packaging/program_files.ps1; шаблон отката: packaging/rollback.ps1.
Все три включены в tools комплекта. Созданный резерв содержит отдельные копии
rollback.ps1/program_files.ps1 и rollback-state.json с точным target.
Прежние чужие rollback.ps1 и резервы не исправлялись.

Установщик проверяет оба manifest и SHA, отказывает при изменённом managed-файле
или коллизии с неуправляемым файлом, резервирует все прежние программные файлы и
manifest, проверяет резерв, публикует manifest последним, читает все новые SHA.
Маппер и игровой runtime этого target должны быть закрыты; EIMapperMcp.exe,
Codex и Claude Code закрывать не требуется. Процессы не завершаются.

Для каждого заменяемого файла проверяется занятость. Свободный файл заменяется
атомарно; занятый переименовывается в `<path>.old-ataman-<guid>`, а проверенный новый
получает обычное имя. Windows этой машины разрешил бы File.Replace даже для
отображённого exe, поэтому явная проверка занятости обеспечивает предсказуемый
rename и наблюдаемую очистку. Гонка с новым загрузчиком также обрабатывается через
rename. Отказ самого rename не скрывается; выполняется проверяемый rollback.
При восстановлении уже совпадающий со старым SHA файл повторно не заменяется.

Список собственных retired-файлов с SHA хранится в .ataman-retired.json.
Следующая установка/откат удаляет только совпавшие и доступные для исключительной
записи записи; занятые сохраняются. Чужие .old-* не ищутся и не удаляются по маске.
Старые поколения резервов автоматически не удаляются.
