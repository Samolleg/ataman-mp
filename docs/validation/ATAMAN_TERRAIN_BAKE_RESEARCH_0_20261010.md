## Вывод

**Рекомендация: сохранять архитектуру «материалы → компиляция атласа», но менять
способ ограничения ёмкости перед реализацией.** Полностью уникальная мировая
маска каждой переходной клетки практически не помещается: 20 из 41 точно
описанных карт DejaVu превышают4096 слотов, 33 превышают2048. Варианты N=4/8/16
снижают оценку, но ограниченный набор локальных рецептов сам по себе не сохраняет
непрерывную мировую маску. Подмена произвольных клеток ближайшим рецептом
возвращает швы. Прототип подтверждает возможность непрерывной маски, а также
показывает её цену:874 уникальных тайла только на1024 клетках выбранного участка.

Следующий технический эксперимент должен сравнить конечные совместимые
граничные состояния (edge-constrained/Wang-подобные рецепты) с адаптивным
запеканием только действительно изменённых границ. Цель — ограничить число
рецептов, сохранив материал вершины и одинаковые пиксели общего ребра, затем
проверить качество на полном размере сложных Zone9/Zone19. Автоматического
понижения качества и молчаливой замены материала при переполнении быть не должно.

## Методика и достоверность

Экспортёр использует `CMprDocument`, `CTerrainEditModel`, MMP codec/inspector,
`CTerrainAtlasPresetCatalog`, встроенные профили и штатное восстановление
shared-corner field. Порядок RES берётся из `orderedResourceSources`: сначала
явный порядок `[RES]` из config.ini мода, затем оставшиеся архивы. Алфавитный
выбор первого RES не заменяет этот порядок.

Атлас содержит `textureCount ×64` физических мест. MP `tileCount` — отдельное
число terrain-class записей, оно может быть меньше полной ёмкости страниц:
например, Zone19 имеет908 записей на960 мест, Zone9 —1593 на1600.
Хэш привязки вычисляется по **всем** физическим местам, включая хвост страницы.
Самостоятельный код не переопределяет ориентацию: используется контракт
NW/NE/SE/SW, отражение Y в grid и обратный packed rotation.

- **41/41 DejaVu:** точная namespace/pixel-hash/slot-count привязка.
  На40 разных атласах —21 штатный preset и19 embedded profile; две карты
  используют один атлас. Переходы и материалы в этом корпусе измерены по
  подтверждённой семантике. Неописанных активных клеток0.
- **38/38 Base:** MPR и все страницы прочитаны, размеры/физические ссылки
  измерены. Их pixel hash не совпадает с известными original/HD bindings.
  **Гипотеза:** совпадающие namespace и число мест сохраняют известную
  топологию каталога. По этой явно условной топологии вычислены материалы,
  переходы и оценки слотов. Эти38 строк нельзя выдавать за проверенную
  семантику оригинальной игры. Для утверждения нужен отдельный exact-bound
  обзор Base-атласов; их значения не смешиваются с подтверждённой сводкой.

Переходная клетка — четыре декодированных угла содержат больше одного
материала. Это геометрическая/семантическая классификация, а не количество
отличающихся цветов в изображении. Земля считается целиком, включая землю под
водой. Overlay считается только при наличии поверхности, packed !=0xffff и
неотрицательном overlayMaterialIndex. Неактивные записи overlay не относятся
к видимому использованию. Физический слот=`packed &0x3fff`; поворот не создаёт
новый физический слот. «Материалы» — использованные семантические ID, а не
MP materialCount (таблица свойств поверхности воды) и не runtime class0..15.

У23 из41 DejaVu-карт есть хотя бы одна вершина с противоречащими ей SEC-углами;
максимум2343 таких вершины. У15 карт принят exact-bound сохранённый vertex field;
у64 восстановление выполнено детерминированно существующим кодом в памяти;
это не скрытый ремонт карт. Клеточные измерения выполняются
**до** такого выбора. Для визуального опыта выбран участок с0 изменённых
сигнатур при восстановлении. Миграция остальных старых карт требует отдельного
решения, что считать авторитетным при конфликте.

## Бюджет слотов: оценки, не результат упаковки

Пусть T — суммарное число переходных клеток двух активных слоёв. Однородные
клетки группируются по `(слой, материал, runtime class)`. Для группы с h
клетками резервируется `min(4,h)` вариантов; H — сумма этих резервов.
Это выбранный запас визуальных вариантов, даже когда сейчас у материала
меньше четырёх исходных однородных тайлов.

- **A:** `T+H`, каждая переходная клетка уникальна.
- **B(N):** `H + Σ min(N, count(signature, layer, runtime class))`.
  Сигнатура упорядочена NW/NE/SE/SW; N=4,8,16 — соответственно скромный,
  средний и расширенный набор локальных форм. Внутри перехода используется
  один выбранный исходный тайл каждого материала. Если независимо варьировать
  и формы, и исходные текстуры, состояние рецепта расширится и бюджет вырастет.
- Отдельно посчитана оптимистичная версия B с canonical quarter-turn
  сигнатурой. Она предполагает, что маску/текстуру можно вращать вместе без
  нарушения мировой ориентации/фазы. Для непрерывной мировой выборки это
  дополнительное недоказанное условие; её нельзя использовать как гарантию.

N ограничивает количество рецептов, а не доказывает пиксельную дедупликацию
мирового шума. Произвольные абсолютные шумовые фазы обычно дают разные пиксели
даже при одинаковых угловых ID. Само округление/хэширование фазы не обеспечивает
равенство общего ребра. Поэтому B — **условная оценка ёмкости конечной модели**,
а A ближе к поведению свободного мирового запекания. Ни один B-сценарий в этом
этапе не реализован и не представлен как прошедшая игровая проверка.

## Память и формат

SEC-ссылка —16 бит:6 бит местного слота,8 бит страницы,2 бита поворота.
Формат адресует256 страниц/16384 места. Это предел представления, **не**
подтверждённая ёмкость движка. 1024/2048/4096 мест —16/32/64 страниц по8×8;
при tile128 страница1024×1024, при tile256 —2048×2048.

Ниже — расчёт полной цепочки mip страницы до1×1 с округлением каждого уровня
до DXT1 блока4×4 (8 байт). Это точнее применения4/3 к независимым тайлам:
последние mip общие для всей страницы. RES metadata и76-байтные MMP headers
не включены (1216/2432/4864 байт headers для16/32/64 страниц). МиБ=2^20 байт.

| Мест / страниц | DXT1+mip tile128, МиБ | DXT1+mip tile256, МиБ | Одна RGBA8+mip копия128, МиБ | Одна RGBA8+mip копия256, МиБ |
|---|---:|---:|---:|---:|

DXT1 payload одной1024-страницы699064 байт,2048-страницы2796216 байт.
Для4096 мест128 —44740096 байт,256 —178957824 байт. Удвоение стороны даёт
практически четырёхкратную память. Одна базовая RGBA8 поверхность без mip
для4096 мест128 стоит256МиБ,256 —1024МиБ; временная вторая копия удваивает
этот компонент. Память геометрии, объектов, кэшей, decode/staging/GPU-копий,
аллокаторов и фрагментации VA сюда не входит. DXT1 с бинарной alpha для overlay
не решает требования к плавной прозрачности; DXT3/5 удвоят сжатый компонент.

«Сейчас» —текстурный план текущих SEC-ссылок: те же места, повороты и
фиксированная Y-ориентация. Учтён UV inset1/16 с каждой стороны, видимый в

На участке158 физических мест;387 различных ориентированных RGB-тайлов
после выборки/масштабирования (повороты считаются в изображениях, не в SEC).

«После»: общий массив материалов вершин, непрерывные bilinear веса.
World value noise с smoothstep lattice interpolation, частоты1.7 и6.3 на
клетку, амплитуды поправки веса0.28/0.07, разные детерминированные seeds по
материалам. Поправка умножается на `4*w*(1-w)`: однородные клетки/чистые
вершины сохраняются. Полоса смешения по score0.12, затем нормализация.
Шум вычисляется по координатам всей карты, не получает новую фазу на каждом
тайле/секторе. Поэтому одинаковая точка общего ребра даёт одинаковую маску.
Угловой grid остаётся сеткой **авторского поля**, но шумовые границы не
сбрасываются и не повторяются по шагу SEC-клеток.

Исходная текстура одного материала выбирается одна, видимая часть без gutter
повторяется с периодом одна клетка. Macro вариант отдельно умножает яркость
на `1+0.13*noise(world/7)+0.05*noise(world/2.3)`.

## Ограничение повтора и дальнейшие проверки

**Мировая выборка малого однородного тайла не убирает его период.** В этом
опыте период2 мировых единицы и он явно виден на Stone/Lime. Шум границы
решает другой компонент картинки. Возможные улучшения:

1. Несколько действительно разных бесшовных вариантов, совместимых на
   границах; случайная замена/поворот произвольных тайлов может внести новый
   текстурный шов. В текущем атласе Irregular имеет только1 uniform вариант.
2. Крупные исходные бесшовные текстуры с большим физическим периодом:
   обычное растягивание малого тайла снижает детализацию, не создаёт её.
3. Макро-вариация цвета/яркости/деталя в мировых координатах. Она визуально
   разбивает регулярность, но при offline bake делает уникальными даже чистые
   клетки: здесь874→1024. Крупная текстура при произвольной фазе даёт тот же
   риск роста слотов. Нужно совместить масштаб исходников, конечные фазовые
   состояния и общий edge contract, либо отдельно оценить runtime-расширение.

Следующие игровые проверки требуют отдельного поручения:

- Изолированная реальная карта + новый RES, SEC rotation и точные MP classes,
  gutters и page mipmaps; переходы через клетку/сектор/страницу/соседнюю карту,
  диагонали и3–4 материала. DXT1 alpha overlay, анимации и неактивный слой
  должны сохраняться, water/ambience/AI traversal не подменяются цветом.
- Выходы128px на2048 и4096 местах под фактическим DejaVu runtime:
  точные source/staged fingerprints, player-on-map, frame/dwell/cleanup,
  peak private/committed VA/largest free region.256px испытывать отдельно;
  ранее подтверждённый8192 crash не обходить увеличением ceiling.
- Реальная карта целиком: latency/memory сохранения, streaming bake без
  нескольких полных RGBA-копий, стабильная упаковка и открытие результата;
  сохранность исходных MPR/RES и editor authoring metadata.
- Подтвердить Base-семантику, политику восстановления конфликтных углов и
  визуально принять качество. Не выдавать текущие точные DejaVu-каталоги за
  проверенный исходный Base-каталог.

## Проверки и воспроизводимость

Отдельный C++ exporter собран Qt5.12.12/MinGW7.3 из уже установленного
Endurance kit; запись только в собственный build-tests. Python использует
указанный владельцем runtime, Pillow12.3.0/numpy2.3.5 уже установлены.
Все79 MPR структурно загрузились, все atlas pages доступны. Проверены
суммы active=uniform+transition+unknown, monotonic N budgets, размеры PNG,
повторное чтение PNG и совпадение79 исходных MPR SHA с измеренными.
Мировая маска дополнительно проверена по двум сторонам31 внутренних
вертикальных границ: max разность при epsilon=1e-6 клетки около4.74e-5,
соответствующая непрерывной функции, без скачка tile-local seed.
Изображения просмотрены непосредственно. Проверки программы и повторные
runtime-кампании не выполнялись: код программы не изменялся.
