## Подтверждённые причины

1. `CView::setNeighborMapContext` хешировал все83 RES даже при `placements:0`.
   5 076 885 786 байт: **22539 и20946мс** в двух запусках диагностической216.
   Каталог карт отдельно занимал737/498мс. В другом запуске полного пути
   SHA занял около15с. Системные счётчики первого процесса показали чтение
   примерно5,16ГБ и около21с пользовательского CPU. Прогретые файлы задержку
   не устраняют; небуферизованный снимок дал15033мс именно на SHA.
2. Тот же полный SHA был в `archiveIndex` менеджера ресурсов. Удаление только
   первого вызова переместило **22993мс** в GL. Оба потребителя исправлены.
3. При незавершённой сессии синхронная проверка backup/recovery на полной
   копии AppData дополнительно заняла **24736мс**. Это отдельный путь задержки.
4. Браузер ресурсов дважды создавал37133 строки: сигнал выбора корня уже
   вызывал `rebuildList`, затем его вызывал `finishLoad`. Адресный замер:
   **1324→485мс**, число строк и точная навигация сохранены.
5. При построении палитры эталон читался двумя SHA-потребителями. Кроме того,
   очередь обрабатывала **131171 запрос ключа для73 уникальных привязок**,
   повторяя проверку ревизии эталона. После объединения SHA, но до устранения
   повторов, оставались5635мс materialCatalogMs, из них около4,6с после
   основной строки фаз. Один проверенный SHA на поколение очереди сократил
   её до95мс.

Вариативность воспроизведена на одинаковых83 архивах: полный синхронный SHA
чувствителен к CPU/I/O; первые22539/20946мс получены при подготовке копии и
сборки,15033мс — на свежем небуферизованном снимке после подготовки.
Отдельно подтверждён большой recovery-проход при unclean-сессии.
Defender/сеть как конкретная причина не установлены. Старые212–213 не
запускались; их журналы без фаз не доказывают, какой из путей сработал тогда.

## Изменения

- Постоянные краткие `Startup phases`: MainWindow, иконки, настройки, профиль/БД,
  формы, доки/восстановление геометрии, recovery тестового запуска, подключение
  viewport, каталог карт, журнал резервной сессии, GL, публикация браузера
  ресурсов, готовое окно и первый кадр. Строки сохраняются и при warning-only
  уровне. Фоновые cleanup/recovery сообщают длительность и отмену.
- Пустой контекст не зависит от архивов. Для ревизий индекса и соседей применяются
  Windows file identity, размер, mtime, CreationTime и ChangeTime. При недоступной
  native-ревизии остаётся проверка содержимого. Действительные атласные привязки
  и проверки пикселей сохранены; изменение с прежними размером/mtime замечается.
- Настоящий SHA эталона вычисляется общим helper с системным SHA-256 и переносимым
  fallback, проверяется до/после чтения, сохраняется в `cache/resource-sha256-v1`
  по физической ревизии. SHA в метаданных остаётся прежним, проверен независимо.
  Неизменный эталон не читается повторно в следующем процессе. Один снимок SHA
  используется для всех ключей одного поколения очереди палитры.
- Каталог карт читает только член `map.txt` через файловый индекс RES, каждая
  папка карт перечисляется один раз. Приоритет корней и регистр имён сохранены.
- Резервная сессия регистрируется синхронно. Проверка кандидатов запускается
  в фоне после показа окна, повторный SHA одного исходника внутри прохода
  устранён. Журнал сохраняет незавершённые сканирования; отмена/раннее закрытие
  не подтверждают их завершение. Устаревший результат не обновляет новую сессию.
  При закрытии проверка отменяется между кандидатами; запись/публикация результата
  выполняется только живой сессией. Cleanup начинается после показа окна.
- Удалён второй rebuild списка ресурсов с сохранением существующего обработчика
  сброса preview и выбора корня. Splash перерисовывает только свой статус,
  события редактора обрабатываются после показа основного окна.
