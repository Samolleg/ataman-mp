GL `CLogic::draw` допускает пути отдельно от `drawHelp`; это подтверждённая причина стартового расхождения, не гипотеза.

| Объекты, drawLogic=false | Путь только выбранного NPC |

## Причина2 и исправление

Прежде `serviceInput` заново строил world-снимок на каждом Qt tick, а worker передавал его растр **после** `api.frame`. Внутри DLL мир уже композировался/показывался с новой камерой. `commit_output` при несовпадении матриц пропускал слой. Контрольная свежая сборка исходного рендеринга воспроизвела дефект: при вращении4/5 Present, при сдвиге3/4 Present без слоя; эти кадры сохранены и просмотрены.

ABI16 добавляет callback в хвост `EirCreate`; прежние поля и хвост API сохранены. DLL получает глубину завершённого мира и вызывает value-only raster на том же worker до композиции/Present. Callback берёт неизменяемую world-геометрию, меняет только матрицу проекции на фактическую матрицу кадра; подписи проецируются там же. Qt-виджеты/документы с worker не читаются. Результат передаётся через прежний проверяющий `host_service`; одинаковый geometry serial больше не блокирует новое изображение камеры. Предыдущая геометрия остаётся опубликованной до готовности следующей.

Во время навигации world-снимок переиспользуется, включая тики между мышиными событиями.
