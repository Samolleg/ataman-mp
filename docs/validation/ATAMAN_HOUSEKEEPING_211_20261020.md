## Причина незавершения и исправление

В210 владение временем жизни приложения было неполным: `MainWindow::closeEvent` завершал QWidget, но не запрашивал явный выход QApplication; завершение зависело от последнего подходящего top-level окна Qt. `CView::updateWindow` без проверки видимости вызывал `updateGL()` из отдельного постоянно работающего таймера; hide-event этот таймер не останавливал. Поэтому сохранившийся цикл Qt продолжал рендерить скрытый viewport и писать статистику. Фоновые записи210 и глобальные workers также не имели общего этапа ожидания перед разрушением viewport; несколько деструкторов делали неограниченные join.

Это подтверждённые дефекты исходного жизненного цикла. **Единственный конкретный top-level widget или участок preflight, который удержал именно процесс владельца11:00:34, по старому журналу установить нельзя**: дампа того состояния нет, старый журнал не фиксировал вход в close-event, завершённый путь удаления viewport при этом несовместим с продолжающимся Render stats. Нельзя объявить доказанной виной миникарту, определённый диалог, соседей, sun visibility, GC210 или сохранение. Исправление устраняет зависимость выхода от вспомогательных окон и сам механизм скрытого рендера, а новые квитанции различают запрос, ожидание, отмену и завершение.

- Прежний dirty-preflight Save/No/Cancel сохранён. Запрос Close во время записи возвращается из события, показывает индикатор и даёт стеку синхронного Save/фоновому autosave закончиться. Счётчик охватывает подготовку обычного MPR Save, RES/cohort-транзакции и recovery. Ни viewport, ни нужный ему GUI не уничтожаются посреди записи.
- Ожидание активной записи ограничено120с. При превышении закрытие отменяется с видимым сообщением; запись не обрывается, окно остаётся открытым, рендер возобновляется. Это сознательная защита сохранения, не «чистое завершение» зависшей записи.
- После принятого preflight останавливаются render/autosave/minimap/validation cadence, инвалидируются поколения соседей и hydration, очищаются очереди собственных пулов. GUI-индикатор ждёт workers; спустя120с зависших задач — журнал timeout/exit2 без опасных деструкторных join и без clean-marker recovery. После нормального ожидания final teardown имеет независимый30с watchdog, включая синхронные GL/static/Qt joins. Эти аварийные таймауты не подменяют PASS обычного закрытия.
- View скрывается без рендера; hide останавливает render/sculpt/overlay timers, show возобновляет render cadence. `paintGL`/`updateWindow` проверяют shutdown/видимость/минимизацию. Принятое закрытие явно вызывает QApplication quit; плавающие окна больше не определяют жизнь редактора. Snapshot secondary-windows теперь хранится через QPointer.
- Записываются `Shutdown close requested`, `Shutdown waiting for active save/recovery write`, `Shutdown started`, завершение ожидания и `Shutdown complete status:clean`; эти записи проходят даже при уровне журнала «только ошибки». Аварийный final teardown имеет отдельный timeout-result.

## Резервные копии

`CBackupManager`: по умолчанию последние3 обычные `.backup` на исходный путь **плюс все моложе3дней**. QSettings `backups/generations` настраивает количество с минимумом1; `backups/minimumAgeDays` не допускает возраст защиты ниже3дней. Open/pre-save рассматриваются вместе. Неизвестные/неполные metadata сохраняются. GC обходит только непосредственные hash-каталоги, не autosaves/terrain-atlases.

Для RES >200МиБ проверяются размер и полный потоковый SHA256; при совпадении существующая копия дополнительно проверяется по SHA и переиспользуется без новой полной записи. Метаданные также содержат mtime. Переиспользование возвращает настоящий путь и hash для существующих race/rollback checks.

Пер-source lock закрывает гонку GC со snapshot. Межпроцессная lease `.in-use` удерживается до конца RES/cohort-транзакции, включая откат. Активная копия не удаляется даже ниже лимита/старше возраста. Ссылки `map-save-recovery/*.json`210 защищают нужные копии; неизвестный recovery-journal останавливает сборку мусора. Cleanup запускается в фоне при старте и после успешной записи; перед сохранением старые поколения больше не удаляются.

На копии имён/JSON/размеров/дат production GC dry-run и удаление совпали: **2 596 758 782 байта /2,42ГиБ**. Большие payload в этом полном инвентаре представлены sparse-файлами: проверяются выбор поколений/защита/объём unlink; содержимое для dedup проверено отдельно на настоящем скопированном RES. Синтетические малые поколения содержат настоящие разные байты.
