## Causes and changes

- HD UI required a content-hashed published namespace, although zone2 has an approved, exactly bound mixed128/256 atlas. Source pages now come from actual texture resolution, independently of the configured HDPack destination. Source payloads and donor archives are checked again before pair publication. The source shared namespace is retained.
- A shared-brush session with only the active map dirty took the normal Save route, but its lower-level writer rejected any dirty shared session. It now saves the active map normally and checkpoints shared history/source bindings after successful adoption. Multiple dirty maps keep their existing batch route.
- The first native HD attempt reached a second defect: slot915 (Grass/Fresh + Grass/Common) could not produce an unambiguous color/activity mask. Its authored RGB corner separation squared is about76, below the225 pair threshold. A fallback uses the reviewed two-material corner topology and compatible native HD donors; it does not enlarge the SD artwork. The receipt identifies this reconstruction method.
- HD adoption invalidates the active shared-brush source binding so subsequent painting uses the new namespace/pages. Pending edits are saved first through normal Save; cancellation or failure stops HD conversion.
- Subsequent Save exposed recompression of existing256px animation frames. Native animation pages with supplied original payloads now retain their compressed bytes at both128 and256px. Ordinary atlas compaction may relocate the block with its references; frame order/count, pixels and mip payload remain intact. The native test now verifies this contract instead of requiring unchanged physical slot numbers.
