# EI-HDPACK-COMPARE-20261010 — сравнение HDPack и причин повторения текстур

Дата: 2026-10-10. Статус: **аудит выполнен; исправления не применялись**.
База анализа/декодеров: `main`, `f3847106f1e2eccd8deea1d5d51794510e857d2f`, версия 135.

## Основной вывод

Повторы и пониженная детализация имеют разные причины. У большинства общих
HD-страниц Dejavu отсутствует верхний mip JamaisVu135: **236 страниц — точная
сжатая цепочка JamaisVu135 начиная с mip 1**, без повторного кодирования этой
цепочки. Это уже было в резервной копии до импорта Zone19. Для Zone6, Zone9
и последней открытой Zone3obr фактический тайл поэтому 128×128 вместо 256×256.
Для исходного Zone19 преимущества JamaisVu135 нет: все восемь страниц совпадают.

Генерация переходов в Ataman действительно ограничивает разнообразие:
обычный виртуальный атлас хранит один выбранный источник на материал,
а mixed-edge 135 явно берёт первый пригодный однородный слот. Вращение и
несколько рецептов границы не создают новые рисунки самого материала.
Обычная покраска однородных клеток умеет выбирать несколько физических
вариантов; текущие SEC подтверждают использование нескольких вариантов.

**Импорт Zone19 не заменил старые страницы:** все 979 членов резервной копии
сохранились в нынешнем RES побайтно. Сохранились также все 1162 payloads
после импорта, сверенные по его независимой квитанции. Позднейшие записи
добавили новые namespaces, а не испортили эти старые страницы.
В опубликованных атласах подтверждена дополнительная DXT-компрессия; в
измеренных примерах её ошибка значительно меньше потери верхнего mip.
Назначить исполнителя/дату первоначального удаления верхнего mip по этим
трём файлам нельзя. Приписывать его импорту Zone19 или версии 135 было бы неверно.

## Границы и метод

- Игровые файлы открывались только для чтения. Сеть, установка зависимостей,
  интерактивный редактор/игра, постоянная установка и build-locks не использовались
  для записи. Весь промежуточный код, снимки исходников, CSV/JSON и игровые PNG —
  только в игнорируемом `build-tests-hdpack-compare/`.
- `AGENTS.md` прочитан с диска; SHA256
  `f4b7fdd5ea82fcdf43d002d23d64ec36be853650f054edf70376527cd6432ec3`.
  Прочитаны CONTRIBUTING, договор данных и относящиеся пункты ROADMAP.
  Последнее поручение разрешает запись только этого отчёта вне рабочей папки:
  ROADMAP, программа, VERSION и CHANGELOG этим аудитом не меняются.
- Специализированные навыки `evil-islands-modding` и
  `evil-islands-private-engine-reference` отсутствуют. Приватные исходники
  движка не исследовались; использован обычный код Ataman и разрешённые ресурсы.
- Собственный консольный `QCoreApplication` собран существующими Qt5.12.12 /
  MinGW7.3 в рабочей папке. Он вызывает **CResArchiveDocument**, **inspectMmp**,
  **decodeDxtImage** проекта, без окон/GL. Проверены все RES members,
  декодированы все base/mip уровни всех трёх паков. Другие сборки не изменены.
- Подсчёт точных дублей — SHA256 декодированного RGBA тайла, без поворотов,
  приближённого сходства и сравнения разных размеров. Слоты 8×8 на страницу;
  логическая строка слота соответствует raw MMP строке `7 - slot/8`.
- Семантика материалов Dejavu — из embedded JSON. Полный pixel hash четырёх
  активных атласов пересчитан по алгоритму CTerrainAtlasProfileInference и совпал
  с embedded профилем. В JamaisVu135 нет JSON: для неизменённых stock страниц
  подписи перенесены по доказанному совпадению mip/раскладки слотов. Это не новый
  утверждённый профиль для JamaisVu135; для отличающегося меню такая семантика
  остаётся гипотезой.
- Яркость `Y=.299R+.587G+.114B`; энергия градиента
  `G=mean(((Y[x+1]-Y)^2+(Y[y+1]-Y)^2)/2)`, высокая частота
  `L=mean((Yleft+Yright+Yup+Ydown-4Y)^2)` по внутренним пикселям.
  Метрики измеряют частоты/контраст, а не художественную ценность. Сравнение
  качества при разном размере дополнено одинаковым экранным масштабом.
- Во время аудита появились чужие незакоммиченные изменения исходников.
  Они сохранены. Выводы о коде относятся к указанной базе; её относящиеся
  исходники сохранены в `source-snapshot/`, не в Git. Последующие правки
  другого участника не объявляются проверенными этим аудитом.

по typed pixel identity; он не обязан удерживать неиспользуемую палитру всех
исходных вариантов. Это **механизм возможного сокращения** вариантов при
публикации. На исследованных картах не подтверждена всеобщая замена вариантов
одним: например, Zone6 Grass/Common имеет 8 разных RGBA слотов и все 8 используются;
Grass/Dark — 6 и все используются. Некоторые из этих различий могли появиться
от кодирования/генерации, а не от нового рисунка. Для доказательства потери
конкретного исторического варианта нужны исходный MPR/recipe и его remap.

## Источники рендера, Modern и mixed-edge

1. **Рендер:** читает конкретные namespace pages активного MPR через CTextureList;
   для Dejavu приоритет RES задаётся его config.ini и `orderedResourceSources`
   (first-match, порядок повторяющихся ключей сохраняется). `HDPack_Terrain.res`
   указан раньше обычного `textures.res`. Packed SEC выбирает slot и quarter-turn;
   renderer не заменяет сам все слоты одним материалом. При смешанных размерах
   страниц renderer использует mip размера самой маленькой страницы. Полная
   утрата/невалидность страниц вызывает defaults, но в исследованных четырёх
   namespaces страницы полные и exact embedded hashes валидны. Нынешняя карта
   Dejavu автоматически не берёт более крупный пак другого профиля.
2. **Обычная покраска / Modern без mixed-edge:** `selectUniformInteriorTile` вызывает
   `selectForPaint` с координатами и seed; `selectCandidates` выбирает физические
   варианты с весами, затем отдельно поворот. При генерации отсутствующих
   переходов CTerrainVirtualAtlas конструирует **один** local material source
   через `selectForPaint(pure,0,0,seed)` и хранит QMap<material,QImage>.
   Это один стабильный выбор для атласа, а не per-cell подбор texture variation.
   Local source приоритетен; external exact-bound global sources заполняют пробелы,
   выбирая первый успешно привязанный reviewed кандидат. External источник
   масштабируется к размеру active tile и не заменяет имеющийся local материал.
   Семейная prewarm-подготовка импортирует доступные authored варианты для обычной
   покраски, но не превращает QMap-источник генератора в массив вариантов.
3. **Mixed-edge 135:** перебирает authored slots текущего working atlas, исключает
   animated, translucent и свои прежние mixed-edge recipes. Для материала
   собирает все однородные слоты, затем **`images[uniforms[id].first()]`**.
   Для stock-кромки проверяет пары всех uniform candidates, но вход recipe material
   остаётся с одним texture source. Вызовам recipe оставлен размер 128, а fit stock
   явно масштабирует к 128. Простая смена RES поэтому не гарантирует сохранение
   256 px в этом пути; нужен отдельный согласованный HD pipeline.
4. **Прототипы:** research.py выбирает `min(sources[material])`; stage1.py уже умеет
   `variant % len(textures)` и quarter-turn, но фиксирует периодический sampling
   с одинаковой фазой на сетке. N4/N8 меняют варианты recipes и форму/внутренность
   кромки, а не дают N новых рисунков травы, когда source всего один.

### Почему возникает «калейдоскоп»

Повтор рисунка возможен уже при одном тайле, повторяемом с единичной фазой.
Новые quarter-turn варианты дают максимум четыре ориентации исходного рисунка.
У художественно симметричного источника соседние повороты подчёркивают
розетки/зеркальные стыки. На raw контактных листах похожие структуры видны
и в JamaisVu135, до обработки маппером. Для stock Zone3obr Grass/Irregular
slot26 корреляция отражения Y на масштабе 32×32 равна **0.723** уже у Jamais;
это заметная близость, не полное пиксельное равенство зеркалу. Для остальных
источников такая симметрия не предполагается автоматически.

В проверенном sampler нет построения четырёх зеркальных квадрантов из одной
четверти картинки. `FLIP_TOP_BOTTOM`/grid reflection компенсируют порядок строк
MMP и координатную систему, а не создают новый калейдоскоп. Поэтому гипотеза
«маппер зеркалит четверть каждого материала» не подтверждена. Конкретный
симптом без координат/скриншота нельзя полностью отнести одному материалу;
подтверждены ограничение source variation и периодичность рецептов.

## Варианты следующих действий — без применения

1. **Вернуть HD источники для выбранных материалов Zone6/9/3obr.** Брать exact
   stock mip0 JamaisVu135 (256 px), сохранить явный source namespace/slot и
   reviewed семантику. Для опубликованных hashed namespaces нужна новая
   согласованная публикация/remap, а не замена всего RES другим модом.
   Поддержать 256 px в working/recipe/публикации, включая stock fit и mip chains;
   проверить память: при одинаковом числе страниц цена примерно в 4 раза выше.
2. **Добавить реальные варианты однородных источников и их выбор в генераторе.**
   Передавать массив texture sources, выбирать по устойчивому пространственному
   seed и runtime class. Само увеличение N4/N8 или включение вращения не заменяет
   новые изображения. Для материалов с одним source нужны новые согласованные
   варианты или bounded stochastic/world mixing с контролем швов и резкости.
3. **Избежать накопительной компрессии authored pixels.** Сохранять исходные
   BC1 blocks при перемещении плиток без изменения пикселей; generated tiles
   кодировать один раз. При невозможности — держать стабильный pristine источник
   и всегда публиковать из него, не из предыдущего compressed результата.
4. **Удерживать нужные неиспользуемые варианты при finalize.** Резервировать их
   как reviewed/pinned stock pool с явным бюджетом и сохранением анимаций;
   отделить уникальный рисунок от codec-induced RGBA различий.
5. **Восстановление backup только по задаче на откат.** Этот backup сохраняет
   те же 128 px и старые повторы, поэтому для восстановления детализации он
   бесполезен; полный откат также удалит нужные новые namespaces. Выборочный
   перенос должен учитывать текущие MPR references и embedded hashes.
