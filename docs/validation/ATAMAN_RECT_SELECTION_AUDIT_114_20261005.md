# Аудит рамки выделения Ataman114

Дата:2026-10-05. Задача:EI-RECT-SELECTION-AUDIT-114-20261005.
Поручение: проверить выбор объектов рядом с рамкой при протягивании ЛКМ.
Ветка main, проверенный исходный SHA ee818aa6371114dec6a783e5cb71a0122a40b9bb,
VERSION114. Это диагностика; исправление и установка не выполнялись.

## Подтверждённая ошибка: невидимая геометрия получает ID

Обычный рендер `assets/shaders/fshader.fsh:126` читает текстуру и отбрасывает
фрагменты с alpha<=0.1. `assets/shaders/select.fsh:10` всегда выводит цвет ID,
вообще не читая текстуру. Оба используют `vshader.vsh`.
`source/render/part.cpp:123` дополнительно не подключает UV в selection VAO;
`source/render/render_queue.cpp:95` не сохраняет текстуру в selection item
и присваивает ему Opaque. Проблема затрагивает обычный и instanced shader path.

Следствие: рамка, пересекающая только прозрачную часть полигона кроны/листвы,
выбирает объект, видимая часть которого находится рядом. Выбор здесь происходит
по отрисованным ID треугольников, а не по попаданию CPU bounding sphere/AABB.

Скрытый native OpenGL probe компилирует **действующие** vertex/fragment shaders
с диска, рисует собственный quad с прозрачными полями и непрозрачным центром
в FBO128x128. NVIDIA GeForce RTX4070SUPER, без интерактивного запуска редактора.
В рамке20,45→35,80 обычный shader записал0 видимых пикселей объекта;
selection shader записал ID во все544 пикселя области. Ветвь u_instanced=true
дала тот же результат. Непрозрачный центр:224 пикселя в каждом проходе;
рамка полностью за геометрией:0 в каждом проходе. GL_NO_ERROR.

23 диагностических утверждения PASS; qmake/build/probe exit0. Это проверка
механизма на реальных шейдерах и собственной геометрии, не end-to-end тест
окна редактора и не воспроизведение конкретного объекта/карты пользователя.
Instanced ветвь проверена с постоянными matrix/color attributes; сам batching
RenderQueue в этом probe не исполнялся. Обе созданные картинки просмотрены:
visible.png показывает только центр, selection.png — весь quad.

## Координаты рамки и сборки

- `source/app/operationmanager.cpp:195` передаёт QRect с отрицательной высотой.
  `source/render/view.cpp:10886` берёт abs(height) и читает от inversedRect.bottom.
  На обычном drag четыре направления дают одну область. Для45..80 по Y
  прочитаны46..79: две крайние строки потеряны. Это уменьшение, а не большое
  расширение области. Для точечного/горизонтального выбора приY60 читается
  строка59 — реальная ошибка на один пиксель.
- Нормализованный положительный QRect20,45→35,80 в том же reader даёт
  screen Y9..44. Это отдельный дефект контракта reader; текущий release caller
  такого QRect не передаёт, поэтому его нельзя выдавать за причину обычного drag.
- `source/render/view_assemblies.cpp:51` намеренно включает всю сборку при
  выборе одного её участника. Остальные детали могут находиться за рамкой.
  Это существующее групповое поведение, отдельное от alpha-ошибки.
