## Исправление

Windows WaitNamedPipeW проверяет наличие канала без открытия клиентского handle;
секундное обновление каталога и list_instances больше не делают connect/abort.
Основной поток сохраняется, connect_instance к тому же экземпляру его использует.
Сбой потока увеличивает задержку1,2,4,8,16,32,60с; успешный каталог сбрасывает её.
Новый UUID после смены режима позволяет сразу восстановить каталог, не обходя
задержку повторными попытками к прежнему неработающему endpoint.

В сервере раздельные лимиты16 проверенных агентов и16 ожидающих проверки,
установленные агенты не вытесняются. Уже закрытые pending sockets не учитываются,
буфер до установки readyRead обработчика читается сразу. Док считает только
проверенных клиентов; неаутентифицированное отключение молчит. Отключение без
работы не заявляет об отброшенных операциях; незавершённые задания/preview
действительно отменяются и сообщаются. Последовательные одинаковые события
занимают одну строку со счётчиком повторений. Протокол1 и legacy fallback сохранены.
