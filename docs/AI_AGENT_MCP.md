# ИИ-агент через MCP — Ataman 273

## НПС, животные и их логика — 273

`list_units`, `get_unit`, `edit_units` работают со штатными CUnit/CMob.
Полномочия дока224, фон225, блокировки271, асинхронные операции272 и горячий
каталог222 сохранены. Скрипты SS_TEXT только читаются для поиска ссылок.
Создания из базы в этом этапе нет. Запись на диск — отдельный штатный `save`
с разрешением владельца. Правки в памяти требуют режима «Правка».

| Инструмент | Схема и результат |
|---|---|
| `list_units` | Необязательные `ids:[ID,…]`, `area` (прямоугольник/полигон272), `prototype`, `player`, `group`, `mob` (имя/путь уже открытого MOB из `get_context`). Фильтры пересекаются. Возвращает операцию; `operation_status.result`: `capturedRevision`, `units`, `count`, `sourceOperation` |
| `get_unit` | Обязательный `id`, те же необязательные фильтры; при неоднозначном ID укажите `mob`. Результат той же формы, ровно один юнит |
| `edit_units` | Обязательные `revision`, `action:"transform"|"copy"|"delete"|"points"`. Выбор `ids`/`area` с теми же фильтрами; для copy допустим `sourceOperation`. `preview:true` → `operation_status` → `apply` с operation/revision либо `cancel_operation`. Без preview применяется сразу после подготовки. Каждое применение — одна штатная Undo в целевом документе |

Каждый прочитанный юнит содержит `id`, `mob`, `prototype` (UNIT_PROTOTYPE),
`model`, `name`, `position:[X,Y,Z]`, `absoluteHeight`, `rotation:[qx,qy,qz,qw]`,
`player`, `group`, `parentId`, `inScript`, `stats`, `references`, `logics`.
`group` — тот же штатный Player, группа дипломатии; отдельной модели дружин нет.
`Z` юнита — сохранённое в MOB смещение от рельефа; `absoluteHeight` — справочная
сумма высоты рельефа и Z, её нельзя записывать вместо Z.

`logics` содержит все пять слотов, включая выключенные, с исходными именами
штатной JSON-проекции. Имена с историческими опечатками сохранены намеренно:

| Поля штатной логики | Значение |
|---|---|
| `Is logic use?`, `Model`, `Is cyclyc?` | Включение, тип поведения, цикличность |
| `Guard placement:[X,Y,Z]`, `Guard raidus`, `Help radius` | Мировая точка охраны, радиус охраны и помощи |
| `Wait`, `Alarm number`, `Alarm condition`, `Always active`, `Aggression mode` | Остальные штатные параметры панели «Поведение», в исходных единицах MOB |
| `Patrol Points:[{Position:[X,Y,Z], "Looking points":[…]}]` | Упорядоченный маршрут и точки взгляда каждого узла |
| Точка взгляда: `Position`, `Wait`, `Turn speed`, `Point flag` | Мировая цель взгляда, задержка, скорость поворота, флаг |

Все координаты точек логики — мировые, включая Z. `transform`/`copy` принимают
`delta:[dX,dY,dZ]`, `rotation` (градусы вокруг Z), `pivot:[X,Y,Z]`; без pivot
используется средняя позиция выбранных юнитов. Поворот предшествует сдвигу.
Один и тот же жёсткий XY-поворот/XYZ-сдвиг применяется ко всем точкам всех пяти
слотов. Относительный Z юнита сохраняется плюс явно заданный dZ, независимо
от нового рельефа. Радиусы и остальные параметры не меняются. Входящие
сценарные ссылки не запрещают перенос; они запрещают удаление.

Для проверки укажите подходящий `layer:0..7` как в `query_passability272`.
Для смешанной группы используйте `layers:[{id:<исходный ID>,layer:…},…]`;
запись по ID заменяет общий layer. Размер животного по имени не угадывается:
без слоя для каждого выбранного юнита запрос отклоняется. `stats` показывает
сохранённые AI Class Stay/AIClassLay; при использовании данных базы учитывайте,
что встроенные MOB stats могут ею переопределяться. Слой не записывается в MOB.
`affected` в preview и apply содержит позицию/поворот после правки,
`absoluteHeight`, `logicsAfter`, `passability` каждого юнита и `points` со всеми
точками и их `passability`: `layer`, `layerLabel`, `passable`, `inBounds`,
`outsideMap`, `inWater`, `inObject`, `graphStale`. Это тот же текущий нативный
классификатор сетки0,5м; `inObject` указывает попадание XY в footprint статической
коллизии (кроме Ignored/Bridge), `inWater` — воду навигационной поверхности.
Точки за картой разрешены, явно помечаются и диагностируются `validate_map`;
автокоррекции положения нет. Юниты — динамические участники, не статическая
коллизия: их правки, как в ручном редакторе, не делают AI-граф устаревшим.
`graphStale` сохраняет состояние графа, в том числе после прежних правок статики;
его перестроение остаётся отдельным явным действием.

`action:"points"` принимает `edits:[{id,logic,kind,action,…},…]`, индексы с0:

- `kind:"guard"`, `action:"move"`: `position:[X,Y,Z]` либо `delta:[…]`.
  Точка охраны — одно штатное поле; add/remove для неё отклоняются.
- `kind:"patrol"`, `patrol:<индекс>`: `add` с position вставляет перед индексом
  0..count, `move` меняет одну Position, `remove` удаляет узел и его взгляды.
- `kind:"look"`, `patrol`, `look`: те же add/move/remove для точки взгляда;
  `action:"direction"`, `direction:<градусы>`, необязательная `distance` задают
  цель относительно патрульной точки:0°=+X,90°=+Y, Z сохраняется. Без distance
  сохраняется прежняя длина XY. Новый взгляд получает штатные Wait/Turn speed/
  Point flag=0. Добавление/удаление не меняет тип или включение слота.

Индексы каждого следующего edits вычисляются после предыдущего edits этого
юнита. Move патруля меняет только эту точку, её взгляды не сдвигаются скрыто.
Для переноса всего маршрута используйте transform юнита. Противоречивые поля
и отсутствующие индексы дают отказ всему пакету.

При copy новые ID выделяет семейный распределитель целевого MOB с учётом
AddMob/технических/сценарных ID и резервов Undo. Внутренние ParentID/явные поля
target/object ID переназначаются по полной таблице группы. Внешние исходящие
ссылки сохраняются и проверяются обычным validate_map. Сценарии, триггеры и
переходы не копируются и не меняются; `untransferredReferences` перечисляет
исходные входящие ссылки с владельцами/строками и исходными ID. `warning`
явно сообщает, что эти ссылки не действуют для новых ID. Копия получает
InScript=false и уникальное имя `<исходное> [copy <новый ID>]` (при конфликте
добавляется суффикс); это предотвращает привязку исходного GetObjectByName к
копии. Ответ содержит `sourceName`/`nameAfter`. Исходный сценарий не владеет
новыми ID/именами; остальные параметры юнита сохранены.

Для другой карты сначала прочитайте группу `list_units`/`get_unit`, сохраните
`result.sourceOperation`, затем откройте целевую карту `open_map` и вызовите
copy с этим sourceOperation и свежей ревизией цели. Это отделённый снимок
штатных юнитов с точной raw-провенанс, не буфер обмена и не произвольные
пользовательские записи. Снимок принадлежит соединению, живёт60с после
завершения чтения, удаляется cancel/disconnect/отзывом доступа. Не отменяйте
read-operation до подготовки копии. Изменившиеся дисковые зависимости
исходника/цели и изменившаяся живая ревизия открытого исходника дают конфликт.
`targetMob` выбирает только уже открытый MOB из get_context; по умолчанию
основной MOB карты, при его отсутствии — текущий открытый MOB. Можно копировать
между разными одновременно открытыми MOB. Источник без raw-провенанс нужно
сначала штатно сохранить и перечитать. SourceOperation нельзя применить как
preview: только edit_units(action=copy) может использовать его как источник.

Удаление отклоняется при любых входящих ссылках272: ParentID, литеральные
GetObject/GetObjectByID/GetObjectByName, InScript, явные ID логики/триггеров и
переходы map.txt. Ссылки внутри удаляемой группы тоже не обходятся; force нет.
Динамические выражения сценария не исполняются; ограничение статического
анализа272 сохранено. `validate_map` дополнительно проверяет юнитов/все точки
логики за границами карты (`unit.point_outside`), дубли и отсутствующие ссылки
проверяет по всему MOB/AddMob. Исходные находки не ремонтируются.

Пределы:500 юнитов на запрос чтения/правки,200 edits и200 суммарных результирующих
точек логики (включая пять guard placement на юнит) на правку,512КиБ ответа,
16384 графовых ячейки для классификации. Превышение отклоняет запрос целиком;
молчаливого усечения/автоматического деления пакетов нет. Явный ID, исключённый
фильтром или отсутствующий, тоже даёт отказ. Подготовка30с, TTL60с, лимиты
работников/операций272 сохранены. После apply/Undo нужна новая revision.

```json
{"name":"list_units","arguments":{"ids":[159,160,161,162,1107534722]}}
{"name":"edit_units","arguments":{"revision":"<fresh>","action":"transform","ids":[159,160,161,162,1107534722],"delta":[3,2,0],"rotation":15,"pivot":[170,170,0],"layer":3,"preview":true}}
{"name":"apply","arguments":{"operation":"<preview-operation>","revision":"<preview-revision>"}}
{"name":"edit_units","arguments":{"revision":"<fresh>","action":"points","ids":[159],"layer":3,"edits":[{"id":159,"logic":0,"kind":"patrol","action":"add","patrol":0,"position":[165,175,6]}]}}
{"name":"list_units","arguments":{"ids":[159,160,161]}}
{"name":"open_map","arguments":{"revision":"<fresh>","map":"zone1"}}
{"name":"edit_units","arguments":{"revision":"<target-fresh>","action":"copy","sourceOperation":"<list_units-result.sourceOperation>","delta":[-10,-10,0],"rotation":10,"layer":3}}
{"name":"undo_last_agent_operation","arguments":{"revision":"<fresh>"}}
```

Между асинхронными вызовами дождитесь operation_status. Примеры ID и координат
относятся к конкретной брифинговой копии; для своей карты сначала прочитайте
юнитов и их логику. Инструменты273 передаются через горячий mcp_catalog и
tools.listChanged без перезапуска моста/клиента.

## Статические объекты, старый AI-граф и проверка карты — 272

Полномочия остаются224/225: человек выбирает режим в доке. `edit_objects`
и `rebuild_ai_graph` доступны только в «Правке»; они меняют память документа,
видны в открытом редакторе и не требуют разрешения Save. Только `save` с
галочкой владельца сохраняет MOB/граф штатным конвейером. Фон и обычный
редактор используют одинаковые инструменты, ревизии, Undo и замки271.
Юниты в272 доступны только для чтения: попытка изменить/создать юнит явно
отклоняется, в том числе если юнит попал в выбранную область.

| Tool | Назначение и ограничения |
|---|---|
| `edit_objects` | `revision`, `action`: `place`, `transform`, `copy`, `delete`. До500 статических объектов, одна Undo. `preview:true` возвращает `count`, `affected` с ID, MOB, исходной/результирующей позицией и поворотом, не меняя документ. Затем `apply` с ID preview и его revision, либо `cancel_operation`. Обёртка `preview` тоже поддержана |
| `query_passability` | Чтение, `layer:0..7` в порядке панели «Навигация ИИ», `points:[[X,Y],…]` до200, `radius:0..32`м (по умолчанию8). Вернёт проходимость точки и `nearest:{position:[X,Y,Z],distance}`; при отсутствии в радиусе — null. Для уже проходимой точки ближайшая — она сама, расстояние0. Классификатор штатного старого графа, сетка0,5м, текущие рельеф/статические коллизии. `graphStale` и `warning` явно сообщают об устаревшем сохранённом графе; чтение его не пересчитывает и не записывает |
| `rebuild_ai_graph` | `revision`, необязательные `preview`, `snapshot`. Штатный построитель кнопки «Обновить граф», все8 слоёв, затем штатные раскраска компонент/проверка совместимости. До16384 графовых ячеек (512×512м); встроенный граф основного MOB меняется в памяти, одна Undo восстанавливает прежние байты и состояние. Отдельный `save` сохраняет его; `.grp` и Nav64 не меняются |
| `validate_map` | Чтение текущих документов и семейства AddMob штатным валидатором: коллизии ID, ссылки, MOB/парсер, ресурсы, устаревший граф. `findings` содержит Warning/Error, `info` отдельно, счётчики `warnings`/`errors`; поля `level`, `code`, `message`, `id`, `path`, при наличии — `coordinates`. До2000 находок/512КиБ: переполнение возвращает ошибку, а не молча усечённый список. Данные автоматически не исправляются |

Все четыре инструмента возвращают ID операции; опрашивайте `operation_status`
до `complete`, проверяйте `result.error`. Подготовка ограничена30с, результаты
живут60с, действуют прежние лимиты работников/операций. Отмена и отключение
отбрасывают кандидат. Начавшийся короткий commit заканчивается целиком либо
откатывается. После изменения/Undo берите новую ревизию. Изменение документа,
семейства MOB или map.txt до применения кандидата вызывает revision conflict.
Каталог272 и примеры передаются через `mcp_catalog` и `tools.listChanged`222,
перезапуск клиента для получения новых описаний не нужен.

`place` принимает `objects:[{prototype,x,y,z?,rotation?,scale?,name?,shadow?},…]`.
`prototype` — ключ или точное имя статической записи `search_database` с
`category:"prototypes"`. Старые записи RaceModels сохраняются; статические
модели дополнены из штатной витрины и авторского `model-catalog.json` рядом
с database.res. Их ключ — `static:<имя>`, `source:"static-model-catalog"`,
`textures` содержит доступные авторские привязки. Прототипы юнитов исключены.
Модель и текстуры берутся из этой записи;
прототип/модель — разные поля MOB. `z` — смещение над рельефом, по умолчанию0.
`rotation:[X,Y,Z]` — углы Эйлера в градусах; `scale:[grace,strength,height]`
— три штатных параметра комплекции модели, по умолчанию[1,1,1], каждый0..10.
Это параметры FIG, не независимое растягивание готовой геометрии по осям.
`primaryTexture` выбирается из `textures`, иначе используется первая авторская
привязка; `secondaryTexture` должна существовать в профиле, `parts` — только
известные части модели. Эти параметры и `shadow` соответствуют ручной
расстановке. Каталог только читается; отсутствующая привязка текстуры даёт
явный отказ с предложением сначала выбрать её в штатной витрине.

Для остальных действий укажите `ids:[…]` либо `area`:

```json
{"shape":"rectangle","x":179,"y":154,"width":4,"height":5}
{"shape":"polygon","points":[[179,154],[183,154],[183,159],[179,159]]}
```

Многоугольник3..128 вершин. Необязательные `prototype` (точное имя прототипа
или модели) и `type` (тип узла из `list_objects`, не тип базы) дополнительно
фильтруют выборку. Если заданы и ID, и область, используется пересечение;
не найденный или исключённый фильтром явный ID даёт отказ. Превышение500
отклоняет весь пакет. Лимит удерживает объём Undo, публикацию моделей/дерева
и размер ответа предсказуемыми; пакет автоматически на части не делится.

`transform` и `copy` принимают `delta:[dX,dY,dZ]`, `rotation` — групповой угол
вокругZ, `pivot:[X,Y,Z]` — центр поворота; без pivot используется центр группы.
Поворот применяется до сдвига. Копии сохраняют параметры исходников, получают
свободные ID основного MOB по штатному семейному распределителю. Занятые ID
юнитов, AddMob, технических записей и сценарных ссылок не переиспользуются.
Результирующие позиции должны оставаться в границах активной карты.

Удаление и transform отклоняются при входящих ParentID, литеральных обращениях
GetObject/GetObjectByID/GetObjectByName, пометке InScript, явных ID в логике
или ссылках переходов map.txt. Ошибка перечисляет владельцев/пути/строки.
Исходящий ParentID объекта сам по себе не является входящей ссылкой на него.
`force` отсутствует. Динамические выражения сценария не исполняются; эта
проверка не заменяет игровую проверку сценария.

Пример «найти и удалить дом, обновить граф, проверить дружину»; после каждого
асинхронного вызова дождитесь результата и получите свежий `get_revision`:

```json
{"name":"search_database","arguments":{"category":"prototypes","query":"stbuho7"}}
{"name":"edit_objects","arguments":{"revision":"<fresh>","action":"delete","area":{"shape":"rectangle","x":179,"y":154,"width":4,"height":5},"prototype":"stbuho7","preview":true}}
{"name":"apply","arguments":{"operation":"<preview-operation>","revision":"<preview-revision>"}}
{"name":"rebuild_ai_graph","arguments":{"revision":"<fresh>"}}
{"name":"query_passability","arguments":{"layer":3,"points":[[161.539047,174.613968],[160.440216,170.957184]],"radius":8}}
{"name":"validate_map","arguments":{}}
{"name":"save","arguments":{"revision":"<fresh>"}}
```

Размещение, движение и копирование:

```json
{"name":"edit_objects","arguments":{"revision":"<fresh>","action":"place","objects":[{"prototype":"stbuho7","x":20,"y":20,"z":0,"rotation":[0,0,15],"scale":[0.9,0.3,0.7]},{"prototype":"stbuho7","x":26,"y":20},{"prototype":"stbuho7","x":32,"y":20}]}}
{"name":"edit_objects","arguments":{"revision":"<fresh>","action":"transform","ids":[1000,1001,1002],"delta":[2,3,0],"rotation":45}}
{"name":"edit_objects","arguments":{"revision":"<fresh>","action":"copy","ids":[1000,1001,1002],"delta":[0,15,0],"rotation":30}}
{"name":"undo_last_agent_operation","arguments":{"revision":"<fresh>"}}
```

Замените условные ID1000..1002 на `affected[].id` результата place. Каждая
Undo снимает только верхнюю агентскую операцию; чужая история защищена219.
После трёх Undo возвращаются исходные байты MOB, включая неизвестные поля.
Save устанавливает новую дисковую базу и границу истории прежним способом.

В меню «Вид» откройте док «ИИ-агент» и один раз выберите «Только чтение» или
«Правка». При необходимости включите «Разрешить агенту сохранять». Режим и галочка
запоминаются в штатных пользовательских QSettings (`ui/aiAgentMode`,
`ui/aiAgentAllowSave`) и действуют, пока человек сам их не изменит. При следующем
запуске сервер поднимается автоматически, ещё до открытия карты. Без сохранённого
значения первый запуск — «Выкл», сохранение запрещено. Секрет и ID соединения
создаются заново при каждом включении; они не являются сохраняемыми полномочиями.

Чтобы отключить доступ, выберите «Выкл» или нажмите «Отключить»: операции отменятся,
подключения разорвутся, обнаружение удалится; после перезапуска останется «Выкл».
В режимах «Выкл» и «Только чтение» галочка недоступна, её значение сохраняется
для возврата в «Правку». Снять разрешение сохранения можно в «Правке».
Док и постоянный индикатор строки состояния показывают режим и число проверенных
агентских соединений, даже когда док скрыт. Окон подтверждения доступа нет.

По решению владельца2026-10-24 мост сам запускает фоновый маппер из своей
установки, когда инструменту нужен маппер, а подходящего запущенного нет.
Открывать окно вручную не нужно. Один раз выберите режим/Save в доке; сохранённый
«Выкл» даёт ошибку «Владелец выключил доступ агентов в доке» ещё до запуска.
`list_instances`, initialize и чтение каталога сами процесс не запускают.
Готовность ограничена45с; конкурентные мосты используют блокировку старта,
фоновый процесс удерживает системный мьютекс и блокировку жизненного цикла.

`connect_instance` принимает `target="auto"|"background"|"editor"` (по умолчанию
auto) либо явный instance. background нужен для самостоятельной карты агента;
editor выбирает обычное окно. Auto выбирает единственное обычное окно, а если
его нет или у владельца есть несохранённые правки — фон. Несколько обычных окон
требуют явного ID. Выбранный сеанс сохраняется до отключения/нового выбора;
после смены сеанса перечитайте контекст и revision. Две разные карты можно
редактировать одновременно. Несохранённую карту владельца агент не переключает.

В фоне генератор, скульптинг и покраска по умолчанию меняют только активную карту.
`includeNeighbors=true` явно включает участвующих соседей: блокировка хотя бы
одного соседа отклоняет всю операцию до изменения данных. В обычном редакторе
прежняя общая кисть по умолчанию сохранена. Для согласования стыка двух карт
нужен общий сеанс после освобождения обеих карт, либо отдельная правка границы
своей карты по прочитанному состоянию соседа. Dirty-карта владельца не меняется.

После будущей установки225 один раз штатно переподключите MCP-сервер в клиенте:
уже работающий мост223/224 не получает новый исполняемый код сам. После этого
повторные задания и перезапуски фона не требуют открывать маппер вручную.

`--agent-headless` использует активный профиль и пути той же установки,
восстанавливает режим224 до первой карты и не открывает последнюю карту владельца.
Нативные поверхности GL скрыты до создания окон; заставки нет, диалоги отвергаются
с журналом/ошибкой. Пользовательские QSettings копируются во временную область,
endurance-options.json не записывается; исходные разрешения перечитываются раз в секунду.

Блокировка редактирования удерживается на физическую MPR/MOB-пару до выгрузки.
С версии271 замки карт и RES расположены в общей папке Windows
`ProgramData/EI Mapper Ataman/locks` (корень через `SHGetKnownFolderPath(FOLDERID_ProgramData)`).
При создании папки Users (SID S-1-5-32-545) получает наследуемые права чтения,
создания, изменения и удаления файлов; недостаточные права существующей папки
дают русскую ошибку с её путём без автоматического изменения ACL. Имя содержит
SHA256 канонического пути: другая установка, профиль, регистр или junction
не создают отдельного замка. Недоступное хранилище запрещает операцию.
Живые замки253–270 в `<каталог документа>/.mapper-service/locks` и более старые
sidecar-имена проверяются на чтение. Мёртвые игнорируются; старые файлы и папки
не создаются, не изменяются и не удаляются. В новом хранилище dead-PID снимается
QLockFile, живые блокировки не стареют. Для одновременной работы обновите все
копии до271: старая версия не проверяет новое хранилище и может начать работу позже.
Чужая карта отклоняется до переключения документов: агент получает ошибку MCP,
человек — сообщение строки состояния без модального вопроса и потери своей карты.
Соседние карты можно показывать; их сохранения подхватывает механизм214.
Изменения раскладки, MPR/MOB соседей и ресурсов обнаруживаются по нативным
ревизиям файлов раз в секунду. Изменившиеся источники прогреваются в фоне,
после чего сверяется стабильность ревизий и обновляются соседние сцены
и раскладка. Активный документ, его Undo и несохранённые данные сохраняются;
во время жеста/загрузки/предпросмотра обновление откладывается.
Мёртвый владелец блокировки распознаётся автоматически. Общий RES публикуется
под блокировкой с чтением актуального архива; изменённые чужие члены не заменяются.
Раскладка мира блокируется и записывается QSaveFile с трёхсторонним слиянием
независимых записей, конфликт той же записи/пересечение требует перечитать мир.
MCP не регистрирует зоны в map.txt. Явные ручные экспорты остаются отдельными действиями.
Backup/recovery используют повторно занимаемые процессные каталоги внутри
`backups/processes/<slot>`; живой слот чужого процесса не используется и не чистится.
Прежние224 резервные копии в корне сохраняются и доступны в прежнем каталоге.

`shutdown_headless` завершает только чистый фон без незавершённых операций/preview.
Есть несохранённые изменения — ошибка и процесс остаётся, нужно save с разрешением
или Undo. Окно владельца этот инструмент не закрывает. Фон сам закрывается после
10мин без рабочих запросов (метаданные не считаются работой) либо через1,5с после
отключения всех мостов; dirty/busy/preview блокируют оба пути. Штатный recovery
autosave остаётся включённым согласно настройкам. Один писатель удерживает сеанс:
следующий агент пишет после disconnect_instance предыдущего; чтение параллельно.

Полный журнал процесса: `logs/headless-<pid>/workflow.log`; общий долговечный
журнал действий, карт и Save: `logs/agent-workflow.log`, с блокировкой и ротацией.
Последние события загружаются в док ИИ-агента при следующем открытии обычного окна.
Для изолированной проверки предусмотрены `EI_MAPPER_SETTINGS_DIR`,
`EI_MAPPER_AUTOMATION_DIR`, `EI_MAPPER_BACKUP_ROOT` и сокращённый
`EI_MAPPER_HEADLESS_IDLE_MS`; реальные конфиги клиентов менять не требуется.
После перезапуска маппера или смены режима простаивающие мосты подключаются сами;
агент повторяет запрос и перечитывает контекст/ревизию. Старые операции не возобновляются.
Явный `disconnect_instance` отключает автовыбор этого моста до следующего
`connect_instance` или нового MCP-сеанса.

Сохранено поведение223: обнаружение без пробных подключений, постоянный проверенный
поток, backoff1–60с при сбое и сброс задержки для нового экземпляра. Док считает
до16 проверенных агентов, одинаковые события схлопываются.

Без галочки агент меняет карту в памяти. Человек сохраняет обычными командами
редактора (Ctrl+S/«Сохранить MPR»); это не требует разрешения агента. С галочкой
агентский `save` вызывает тот же конвейер209–216: резервные копии, проверки,
публикация в HDPack, предел126 страниц, commit/readback. Отдельного сериализатора нет.
`create_map`, `create_mob` и размещение в мире тоже пишут файлы и требуют той же
галочки, повторно проверяемой перед commit. Существующие карты и MOB не заменяются.

## Подключение

Комплект содержит `EIMapperEndurance.exe` и `EIMapperMcp.exe` рядом с Qt DLL.
Сначала разместите комплект по окончательному пути: конфиг агента содержит
абсолютный путь к мосту. Для225 подготовлен staging; установленная223 до отдельного решения не обновляется.

Кнопка «Подключить Codex/Claude Code» показывает план изменения. До нажатия OK
ничего не записывает. Для Codex она запускает найденный в PATH `codex.exe` с
показанными аргументами. Если CLI установлен через другой launcher, выполните
показанную команду вручную. Пример PowerShell:

```powershell
codex mcp add ataman -- 'C:\путь к комплекту\EIMapperMcp.exe'
codex mcp get ataman --json
```

Для Claude Code кнопка предлагает выбрать проектный `.mcp.json`, затем показывает
полный итоговый JSON и путь для отдельного подтверждения. Сохраняет другие серверы
и ключи, создаёт точную `.ataman-<uuid>.bak`, проверяет отсутствие изменения файла
после предпросмотра, заменяет файл атомарно. Пример результата:

```json
{
  "mcpServers": {
    "ataman": {
      "type": "stdio",
      "command": "C:\\путь к комплекту\\EIMapperMcp.exe",
      "args": []
    }
  }
}
```

Альтернатива в каталоге выбранного проекта:

```powershell
claude mcp add --transport stdio --scope project ataman -- 'C:\путь к комплекту\EIMapperMcp.exe'
```

Перезапустите сессию агента после настройки. В Claude подтвердите доверие проектному
MCP, проверьте `/mcp`; в Codex также доступен `/mcp`. Команды регистрации описаны
в [документации Codex](https://developers.openai.com/codex/mcp) и
[Claude Code](https://code.claude.com/docs/en/mcp). Реальные конфиги владельца
при разработке не редактируются: тесты используют отдельные CODEX_HOME,
CLAUDE_CONFIG_DIR и проектный JSON внутри каталога проверки.

Первое поручение агенту: «Прочитай get_context». Единственный включённый маппер
будет выбран автоматически; при нескольких укажите ID из `list_instances` в
`connect_instance`. Список содержит PID/версию/время включения, без секрета.

### Полный картографический экспорт238

Штатный сценарий: `connect_instance(target=background)` → `open_map` с ключом
каталога и ревизией → `get_context`/`get_revision` → `export_map_topdown` →
`operation_status`. Сам экспорт допустим в Read-only без Allow agent to save;
обычные правила открытия карты остаются прежними. Экспортируется активная карта
выбранного instance, включая его несохранённые правки, все явно загруженные MOB
и скрытые в редакторе статические объекты. Соседние карты не включаются.

```json
{
  "revision": "<get_revision.revision>",
  "outputDir": "C:/workspace/exports/zone1-new",
  "pixelsPerWorldUnit": 4
}
```

`outputDir` — абсолютный новый каталог с существующим родителем внутри рабочего
каталога маппера. У локальной установки рабочий корень находится подъёмом от EXE
до AGENTS.md/.git; у отдельного переносного пакета используется рабочий каталог
процесса. Источники профиля/игры, существующие назначения, симлинки и junctions
отвергаются. Не выбирайте игровой Maps/res. Права файловой системы сохраняются.
`pixelsPerWorldUnit`:1,2,4 (по умолчанию4). Максимум8 388 608 пикселей на слой,
дополнительно действует GL_MAX_TEXTURE_SIZE; скрытого уменьшения разрешения нет.

Ответ сразу содержит ID операции и deadlineMs120000. Фазы:
`resolving_resources`, `capturing`, `writing`; терминальные статусы:
`complete`, `failed`, `cancelled`. При отказе `result` содержит `code`, `error`
и исходную фазу, при необходимости — объект/ресурс и `incompletePath`.
Получение терминального результата освобождает слот; файлы не зависят от TTL.
`cancel_operation` отменяет ожидание/работу между проходами и кодированием файлов.
Один GPU-вызов может закончиться перед обработкой отмены. До получения результата
готовый комплект не публикуется: запись идёт в отдельный `.incomplete-<uuid>`.

Комплект: `cartographic-base.png`, `composite.png`, `terrain.png`, `relief.png`, `water.png`,
`water-mask.png`, `structures.png`, `structures-mask.png`, `vegetation.png`,
`preview.png`, `composite-preview.png`, `manifest.json`. У девяти основных изображений одинаковые размер
и охват. Слои сооружений/растительности/воды прозрачны; маски — геометрические,
независимые от освещения и цвета текстур. Вода depth-тестируется относительно
рельефа, без мостов/сооружений; учитываются авторские типы материала2/3 и нативная
высота overlay. Тип4 — травяной overlay в vegetation. Наземные overlay/decal
сохраняются в terrain. Дорожные текстуры и переходы рисует обычный renderer.
Без однозначных авторских семантических данных `roadsMask.status=unavailable`.

`cartographic-base.png` строится строго по relief и географическим water/structures
маскам: светлая нейтральная суша, геометрический рельеф, однотонная вода и контуры
сооружений внутри исходных масок. Без растительности/текстурной пестроты и выдуманной
семантики. При недоступной roads-mask `cartographicBase.status=limited`: дороги
нужно сверять в terrain/composite. Статус complete означает целостность файлового
комплекта, а ограничение читаемости основы записано отдельно и в warnings.
`preview.png` показывает основу, `composite-preview.png` — цветную сверку;
длинная сторона каждого не больше1024.

Результат содержит `exportId`. `read_export_image` возвращает метаданные и стандартный
MCP image content; `layer` — точное имя PNG из manifest. Например:

```json
{"exportId":"<exportId>","layer":"structures.png","pixelRect":[510,730,150,120],"maxSide":1024}
```

`pixelRect=[x,y,width,height]` задан в полном разрешении выбранного PNG и обязан
лежать внутри него. Если фрагмент помещается в maxSide/лимит PNG, его пиксели
не масштабируются. Ответ содержит исходный pixelRect, sourceSize и worldBounds;
для preview координаты пересчитываются по его собственным размерам. maxSide64..1024,
по умолчанию1024. Подмена файла/manifest/SHA, выход за bounds, произвольный путь и
junction отвергаются. Регистрация принадлежит этой установке и хранится отдельно
от операций в защищённом automation/exports. Просмотр доступен после TTL операции,
перезапуска bridge/instance, пока владелец не удалит комплект или регистрацию;
автоматического удаления готовых комплектов нет. Срок указан в manifest.retention.

`window_snapshot({})` внешне возвращает PNG и profile/map/capturedRevision.
Внутренний локальный вызов начинает операцию с фазами preparing/capturing/encoding;
bridge ждёт её короткими status-запросами. Общий deadline30с, ошибка
SNAPSHOT_TIMEOUT содержит фазу. GL выполняется в owning GUI-thread в отдельном FBO
с текущей камерой без вызова camera.update(), показа/активации окна и swap;
PNG кодируется отдельно. Отмена MCP-запроса (`notifications/cancelled`, requestId)
передаётся cancel_operation. При открытии/коммите карты возвращается BUSY с ID
операции, если он известен. RENDER_UNAVAILABLE/SNAPSHOT_SIZE_LIMIT/штатная отмена
сохраняют MCP-соединение; get_context можно вызывать сразу. Общий IPC timeout
остальных методов не менялся.

Растительность определяется категориями trees/bushes авторского каталога и
нативными семействами nature/flora; происхождение классификации записано для
каждого объекта. Остальная статическая геометрия сохраняется в structures.
Ресурсы разрешаются до захвата, mesh-части и текстуры удерживаются на время
операции; неполные модели/текстуры не заменяются символами или заглушками.
Изменившиеся документы/провайдеры вызывают REVISION_CONFLICT.

PNG имеют +X вправо, +Y вверх, начало в верхнем левом углу. Матрицы относятся
к границам пикселей: `u=(x-xmin)*W/(xmax-xmin)`, `v=(ymax-y)*H/(ymax-ymin)`;
центр пикселя(i,j) преобразуется обратно как(i+0.5,j+0.5). Географический север
не выводится из знака Y. `minimap_bake.gameImage` и его игровой переворот не
используются. Экспортированные исходники могут превышать1024: это материал
для художника, последующая игровая MMP ограничивается отдельно.

Результат `complete.result` содержит `manifestPath`, абсолютные `files`,
counts/warnings и небольшое стандартное MCP image-превью. Полноразмерные PNG
не передаются base64. Manifest различает SHA сохранённых файлов, baseline
документа и отдельную identity живого снимка; содержит список MOB, объектов,
частей, winning providers и хэши всех PNG. Нет регистрации миникарты, записи
MPR/MOB/RES/Nav64/каталога объектов, игровых настроек или публикации.

## Координаты, страницы и ограничения

- Высоты: `x/y` — индексы вершин, одна единица сетки соответствует1м; реальное
  положение displaced-вершины находится в `worldX/worldY`. `raw * rawToWorld`
  даёт высоту мира. `width/height` по умолчанию16, до64; `step`1–1024.
- Покраска: координаты тайлов, шаг2м; `layer` — `land` или `overlay`.
  `semanticCornersNW_NE_SE_SW` возвращается только при известном поле.
  Неизвестная семантика не восстанавливается и не угадывается. Runtime material
  MPR, физический tile и ID материала палитры — разные идентификаторы.
- Страница — до200 строк; используйте возвращённый `nextOffset`. Для объектов
  offset относится к порядку исходных объектов всех MOB; один вызов просматривает
  не более10000 после offset. Палитра использует исходный индекс, БД — индекс
  совпадения. При редактировании человеком между страницами состав может меняться.
- Фрагмент — максимум4096 значений; JSON-ответ дополнительно ограничен512 КиБ.
  При отказе по размеру уменьшите область/страницу. Кадр stdio/pipe —1 МиБ.
- Карты профиля именуются ключами `номер-корня/относительное-имя` из каталога.
  Абсолютный путь, `..` и выход через ссылку за корень запрещены. Поиск каталога
  ограничен10000 файлами. MPR/MOB — до64 МиБ каждый; рельеф — до4096 секторов.
  Большая неподдерживаемая карта остаётся нетронутой, возвращается ошибка.
- Максимум16 проверенных и16 ожидающих проверки локальных подключений,2 одновременно работающих чтения,8 операций
  с результатами. С258 результаты хранятся60с после завершения; обычная отменяемая
  подготовка ограничена30с. Неделимый GUI commit сохраняет свой ID до завершения;
  `operation_status` доступен, отмена commit отклоняется без прерывания записи.
  Парсер дисковых карт живёт в отдельном процессе с лимитом512 МиБ.
- Активная карта читается из памяти, дисковая — с диска. Снимок высот/БД фиксируется
  при запросе и может устареть после дальнейших действий человека. Инструменты чтения Undo, dirty, сохранение, файлы карты и выделение не меняют.
- Пока открыт модальный диалог, чтение редактора отклоняется; повторите после
  закрытия диалога. Не используется буфер обмена, TCP, HTTP или сетевой listener.

## Протокол, безопасность и завершение

Стандартный MCP работает через UTF-8 JSON-RPC2.0, одна строка на сообщение,
без LSP `Content-Length`. stdout моста содержит только протокол.
Поддерживается текущая [редакция2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning):
`server/discover`, metadata каждой modern-заявки, `resultType: complete`, tools/resources.
Для клиентов с handshake поддержаны initialize-редакции2025-11-25,2025-06-18,
2024-11-05. Необъявленные расширения MCP tasks/subscriptions не реализованы;
фоновые чтения используют обычные tools с явным опросом.

Мост соединяется через QLocalSocket с QLocalServer видимого редактора, Windows
`UserAccessOption`. Каждое включение создаёт новый случайный ID и секрет сессии.
Файл обнаружения находится в пользовательском AppData (`QStandardPaths::GenericDataLocation`)
по пути `EIMapperAtaman/automation/<id>.json`;
каталог получает защищённую DACL текущего Windows-пользователя, файлы наследуют её.
Секрет передаётся только внутри локального протокола и не попадает в конфиги,
списки экземпляров или кольцевой журнал200 событий панели. Такой доступ намеренно
доверяет процессам этого же пользователя; это не изоляция от вредоносной программы,
уже работающей от его имени. Stale-файлы после аварии не удаляются мостом; недоступные
каналы не показываются.

Транспортные ID моста независимы от MCP ID. Чужой/поздний ID отбрасывается;
после локального таймаута2с соединение уничтожается. Для опроса/отмены только новых
операций правки219 допускается до30с на короткую неделимую стадию штатного
файлового commit; имена, корреляция ID и очистка канала после таймаута сохранены.
Для единственного маппера следующий запрос переподключается автоматически;
поздний ответ старого потока не может стать результатом следующего запроса.
Долгая операция не удерживает этот вызов: она возвращает ID для опроса.

Контроллер хранит QPointer вместо сырого CView*. В нормальном closeEvent211
`stop()` вызывается до `prepareForApplicationShutdown` и удаления вида.
Отключение закрывает sockets, отменяет снимки, убивает только свои read-worker
процессы и удаляет свой descriptor. Чтение/индексация не ожидается в GUI-потоке;
watcher после отмены не обращается к редактору. Деструктор и destroyed-сигнал
дают дополнительную защиту альтернативного пути завершения.

## Режим «Правка»: инструменты219

Один подключённый мост получает право писателя при первом запросе правки. Второй
может читать, но его правки и отмена чужой операции отклоняются. Для передачи
права первый вызывает `disconnect_instance` или человек выключает режим.
Каждая применённая операция — одна запись обычного Undo с названием «ИИ: …».
Ctrl+Z охватывает активную карту, включённых соседей, семантику и атлас. Для
`create_map` Undo возвращает прежнюю чистую карту, Redo открывает созданную;
начальный файл/атлас остаются на диске. Удаление созданной карты не скрывается в Undo.
Сохранение с перепаковкой начинает новую историю, как штатная публикация.

| Tool | Аргументы / результат |
|---|---|
| `get_revision` | Без аргументов. Возвращает `revision`, `mode`, `allowSave` |
| `create_map` | `revision`, `name`, `sectorsX`, `sectorsY`; необязательные `height` (метры, по умолчанию0), `maxZ` (шкала текущей карты), `material` или `materialName`, `root` (индекс mapRoots, по умолчанию0). Новая MPR/атлас, затем открытие |
| `sculpt` | `revision`, `action`, `area`; `amount`, `height`, `strength` (0..1, по умолчанию1), `seed`, `grid`, `preview`, `snapshot` |
| `paint` | `revision`, `area`, `material` или точное `materialName`; `layer` land/overlay, `seed`, `shuffle`, `minimumSlope`/`maximumSlope` (градусы), `preview`, `snapshot` |
| `preview` | `tool`: sculpt/paint и `arguments` этого инструмента. Подготовка без применения; возвращает ID для `apply`, ревизию и PNG плана |
| `apply` | `operation` подготовленного preview, его `revision`, необязательный `snapshot`. Кандидат применяется только при совпадении ревизии |
| `undo_last_agent_operation` | `revision`. Отменяет верхнюю команду агента; при последующей человеческой/общей истории отказывает, чужие команды не отменяет |
| `save` | `revision`. Только с галочкой; обычное сохранение MPR, включая общий ландшафт |

`create_map`, `sculpt`, `paint`, `preview`, `apply`, `save` возвращают `operation` и
`status: running`; результат опрашивается через прежний `operation_status`.
`status: complete` содержит `result`; внутри результата `error` означает отказ.
`cancel_operation` и отключение отбрасывают незавершённый кандидат. Во время
подготовки человек может работать: изменение документа/истории/профиля/раскладки
приведёт к понятному revision conflict перед применением. Редактор не переносит
частичные данные кандидата в живой документ. Короткая фаза штатного commit
сериализуется с другими правками; начатая файловая транзакция завершается своим
обычным commit/rollback до удаления окна. Незавершённая подготовка при закрытии
отменяется, worker не держит GUI-указателей.

Ревизия — непрозрачный отпечаток документов, высот/XY, семантики, таблиц материалов,
истории, MOB-позиций, раскладки, выбранных соседей и физических поколений ресурсов.
Не подставляйте старую ревизию после правки. Получите свежую и заново подготовьте
план. Выбор режима/галочки через MCP отсутствует. При активном ручном мазке,
загрузке или модальном диалоге правка получает явный отказ с предложением повторить.

### Геометрия области

Все координаты правки и высоты задаются в метрах относительно начала активной MPR;
осьY совпадает с `read_terrain`, координаты могут выходить на включённых соседей.
В отличие от `read_paint`, здесь координаты не являются индексами двухметровых тайлов.
Общая кисть учитывает только карты, включённые человеком в штатной общей кисти.
При её выключении меняется активная карта. Геометрия стыков — штатная215, не новое ядро.

```json
{"shape":"circle","x":64,"y":64,"radius":30,"falloff":0.5}
{"shape":"rectangle","x":0,"y":0,"width":128,"height":128,"falloff":0}
{"shape":"line","points":[[0,60],[32,50],[64,65],[128,70]],"width":12,"falloff":0.4}
```

`falloff`0..1 — доля радиуса/полуширины, отведённая на плавный край; по умолчанию0.35.
Для прямоугольника x/y — нижний угол. Для линии width — полная ширина дороги/русла.
Маска добавляется к любой области: `maskWidth`, `maskHeight` до64 и `mask` ровно
width*height чисел0..1, строки по возрастающейY. Она интерполируется по bounding box.
Покраска применяет стабильное распределение по маске/плавному краю и seed;
целочисленные ID материалов не смешиваются в вымышленные значения.

`sculpt.action`: raise/lower используют `amount` в метрах; flatten — `height`;
smooth — `strength`; noise/hills — `amount` и `seed`, пространственно плавный
детерминированный рельеф. heightmap принимает `grid:{width,height,values}` с
мировыми высотами, билинейной интерполяцией и влиянием area. Сетки до64×64;
пример: `{"width":2,"height":2,"values":[10,20,14,18]}`. Произвольные файлы/URL
высот не читаются. Скульптится основная поверхность, overlay-покраска доступна
на уже существующем покрытии; создание/деактивация overlay через API не добавлены.

`paint` использует ID именно из `material_palette`, не runtime type и не packed slot.
Имя должно точно совпадать с единственным именем палитры. `shuffle:true` меняет
распределение вариантов при том же материале, результат повторяем с тем же seed.
Решатель131 выбирает существующие авторские переходы и штатно готовит отсутствующие
из проверенных источников. Старые физические слоты Undo не перерабатываются;
при нехватке ёмкости возвращается ошибка, чужая история не очищается ради мазка.

### Низкоуровневый пример219

Каждое обозначение `<revision>` заменяется текущим значением `get_revision`.
После каждого async-вызова дождитесь его `operation_status`; следующий запрос
использует новую ревизию. ID материалов берутся из вашей палитры.

```json
{"name":"create_map","arguments":{"revision":"<revision>","name":"agent_valley","sectorsX":4,"sectorsY":4,"height":10,"maxZ":100,"material":123}}
{"name":"sculpt","arguments":{"revision":"<revision>","action":"hills","amount":18,"seed":219,"area":{"shape":"rectangle","x":0,"y":0,"width":128,"height":128,"falloff":0.7}}}
{"name":"sculpt","arguments":{"revision":"<revision>","action":"flatten","height":10,"area":{"shape":"circle","x":64,"y":64,"radius":35,"falloff":0.7}}}
{"name":"sculpt","arguments":{"revision":"<revision>","action":"flatten","height":6,"area":{"shape":"line","points":[[0,60],[35,49],[65,66],[128,70]],"width":13,"falloff":0.45}}}
{"name":"paint","arguments":{"revision":"<revision>","material":123,"seed":219,"shuffle":true,"area":{"shape":"rectangle","x":0,"y":0,"width":128,"height":128,"falloff":0}}}
{"name":"paint","arguments":{"revision":"<revision>","material":456,"minimumSlope":27,"seed":219,"area":{"shape":"rectangle","x":0,"y":0,"width":128,"height":128,"falloff":0}}}
{"name":"paint","arguments":{"revision":"<revision>","material":789,"seed":219,"area":{"shape":"line","points":[[5,15],[35,25],[64,43],[125,18]],"width":7,"falloff":0},"snapshot":true}}
```

Далее можно тем же `paint` сделать подложку леса, широкую полосу берега и более
узкую воду по линии русла; никаких объектов/деревьев этот этап автоматически не ставит.
Проверка перед применением:

```json
{"name":"preview","arguments":{"tool":"sculpt","arguments":{"revision":"<revision>","action":"raise","amount":3,"area":{"shape":"circle","x":20,"y":20,"radius":12}}}}
{"name":"apply","arguments":{"operation":"<preview-operation>","revision":"<preview-revision>","snapshot":true}}
{"name":"undo_last_agent_operation","arguments":{"revision":"<revision>"}}
{"name":"save","arguments":{"revision":"<revision>"}}
```

PNG preview — подписанный вид сверху с подсвеченной областью; живой рельеф не меняется.
При `snapshot:true` успешное применение возвращает настоящий PNG окна. Мост дополнительно
выдаёт вложенные PNG стандартными image content MCP; JSON-ответы прежних клиентов сохранены.

### Ограничения219

- Создание использует явный шаблон профиля, текущую чистую карту либо первую MPR
  по имени в первом доступном mapRoot, сохраняя штатный путь213. Если в профиле
  нет доступной MPR с полным атласом, возвращается ошибка с просьбой задать template.
  Перед созданием сохраните изменённые MPR/MOB/переходы. Имя1..40 ASCII букв/цифр/_/-
  с начальной буквой, без путей и Windows device names. Только существующий mapRoot
  активного профиля; размер1..16 секторов по каждой оси. Для начального материала используется однородный тайл текущего шаблона; если
  его нет, выбирается доступная исходная MPR этого материала внутри mapRoots
  профиля. При отсутствии такого источника создание отклоняется без записи. Без material используется физический начальный тайл шаблона.
- Одна операция: до4 карт, суммарно256 секторов; область до2048м по каждой стороне,
  полилиния до128 точек, маска/сетка до4096 значений. Запросы ограничены1 МиБ.
- Один worker правки одновременно, включая ещё освобождаемый после отмены снимок;
  прежние2 read-worker и8 результатов/60с/30с сохраняются. Результат preview также
  истекает; для длительного диалога подготовьте его заново.
- Сохранение файлов не является Undo удаления: create_map оставляет начальный
  файл, Save — штатную новую дисковую базу и резервные копии.
- База131 сохранена. RecipeBaker/MixedEdge, placement объектов и самостоятельный
  agent serializer не добавлены. Ручная/игровая приёмка владельца отдельно от
  скрытого native e2e на копии профиля.

## Природный рельеф220

R3 меняет прежде всего форму, а не подгонку энергии шума:
[снимки и метрики формы](validation/ATAMAN_NATURAL_TERRAIN_220_20261024.md).
Горы используют общее направление хребтов, вытянутые ridged-поля и прорезание
притоков по накопленному стоку. Скала выбирается по сглаженной крутизне полосами;
малые изолированные пятна удаляются. У побережья — компактные острова,
сглаженная береговая маска, связные пляжи на выбранных пологих берегах и мелководье.

Параметры R3 в `parameters`:

| Параметр | Диапазон / смысл |
|---|---|
| `ridgeDirection` | 0..180°, направление хребтов; 0 вдольX,90 вдольY |
| `ridgeSpacing` | 8..256м, поперечный масштаб горных гряд |
| `anisotropy` | 1..8, отношение продольного масштаба к поперечному |
| `maximumTerrainSlope` | 15..85°, ограничение соседних перепадов высоты; это не заданный P90 |
| `streamPower` | 0..1, сила четырёх проходов прорезания накопленного стока в горах |
| `islandMinArea` | 0..4096м², порог удаления малых береговых компонент/дыр |
| `beachSlope` | 0..45°, предельная сглаженная крутизна пляжа |
| `beachDirection` | 0..360°, направление выбранных пляжных берегов;180° — западные борта |

Пресет `mountains`: направление90°, масштаб30м, анизотропия3, соседний уклон74°,
`streamPower:0.18`, террасы0.9. Параметр `ridgeSpacing` задаёт его поперечный
масштаб; для остальных пресетов крупный масштаб по-прежнему задаёт `scale`.
У `coast` `shoreWidth:10` задаёт ширину связных пляжей; песок выбирается также
по экспозиции склона, не рисуется каймой вокруг каждого острова. Мелководный
песок продолжает выбранные пляжи, а не заполняет всё морское дно.
Морской берег сглаживается на сетке1м,
затем штатные Modern131-переходы работают на сетке покраски2м.

Для перевала задавайте `carve_river` и `road` по низкой долине после просмотра
высот. `carve_river` здесь формирует сухую ложбину: без `water` в `auto_paint`
водный overlay не появляется. Линия поперёк хребтов создаст поперечный разрез.

Горный пресет также создаёт общий изогнутый водораздел с отходящими грядами.
Если естественная долина уже подходит для перевала, достаточно `road`:
дополнительное прорезание монотонным руслом может слишком глубоко срезать седловину.
Сухая дорога не ограничивается значением `waterLevel`, когда `water` не задан.
Ответ `generate_terrain` содержит `terrainMetrics.shape`: узкие выступы,
связность верхних областей, полную и локальную направленность. Метод и единицы
определены в отчёте; эти числа дополняют просмотр, не заменяют его.

Доработка R2 после отклонения9ea330cb: [сравнение и спектр](validation/ATAMAN_NATURAL_TERRAIN_220_R2_20261024.md).
`detail`0..32 регулирует мелкие складки, `detailThreshold`0..1 — порог области
их применения (пологие площадки сохраняются), `rockFraction`0..1 — ориентир доли
каменных вершин (с минимальным уклоном), `patchScale`1..64м — масштаб смеси.

Для `auto_paint` в R2 предел фоновой подготовки120с: богатая палитра побережья
может требовать больше30с для переходов Modern131. Операция остаётся отменяемой;
незавершённый кандидат не меняет документ. С258 результат хранится60с от завершения,
как у остальных операций; их обычная подготовка по-прежнему ограничена30с.
В `palette` дополнительно доступны `dark`, `light`, `forest`, `rock2`, `rock3`,
`underwaterRock`, `underwaterSand`. Песок применяется у реальной воды; сухие
низины автоматически не превращаются в песок. Пойма шире русла, линия сглажена.
Для моря выбирайте именно `Water / Emerald` и подходящую жидкую запись, а не
первый Water в палитре. Шаблон zone7 сохраняет её реальные материалы/анимации.

К прежним22 инструментам добавлены четыре. Все работают в режиме «Правка»,
асинхронно готовят отделённый кандидат, принимают актуальную `revision`,
`preview:true`, `snapshot:true` и используют одну обычную Undo «ИИ: …».
Отмена/отключение во время подготовки оставляет живой документ неизменным.
Они также принимаются обёрткой `preview` и затем `apply`.

| Tool | Аргументы |
|---|---|
| `generate_terrain` | `preset`, обязательный `seed`; необязательные `area`, `parameters` |
| `erode` | Необязательные `area`, `parameters`, `seed` |
| `carve_river` | `points:[[x,y],…]` по течению, `width`, `depth`; необязательные `level` (высота дна у истока), `floodplain`, `seed`, `area` |
| `auto_paint` | `preset`; необязательные `area`, `seed`, `parameters`, `palette`, `rules`, `road`, `water` |

Без `area` используется вся активная карта. Геометрия/маска и включённые человеком
соседи работают по договору219. Для общей генерации задайте область, покрывающую
обе карты: расчёт использует одну сетку, стык согласует алгоритм131/215. Самостоятельно
подключать или менять выключенных соседей агент не может. Рабочая сетка ограничена
1100000 отсчётами, прежний бюджет256 секторов сохраняется. Значения вне `0..maxZ`
отклоняются; масштаб MPR автоматически не меняется.

Пресеты: `plain` (равнина), `hills` (холмы), `mountains` (горы), `coast`
(побережье с бухтой), `swamp` (болото), `river_valley` (долина). Основание и
пределы измерений: [числовой эталон](research/NATURAL_TERRAIN_PRESETS_220.json),
[сравнение](validation/ATAMAN_NATURAL_TERRAIN_220_20261024.md).

`parameters` переопределяет поля выбранного пресета:

- `baseHeight`, `amplitude` (метры), `scale`4..2048м, `ridge`0..1,
  `warp`0..512м, `terrace`0..1. fBm с поворотом октав, ridged-компонента,
  domain warp и непрерывные уступы формируют неодинаковые хребты/площадки.
- `thermalIterations`, `hydraulicIterations`0..64; `talus`0.01..8 (перепад
  на метр), `rain`0..1, `erosion`0..1. Гидравлическая модель переносит и
  осаждает взвесь; это ограниченное приближение, не геологический симулятор.
- `waterLevel`, `rockSlope` (градусы), `shoreWidth`0..32м,
  `boundaryNoise`0..8м. Учитываются высота, центральный уклон, кривизна,
  близость к уровню воды и повторно вычисленная аккумуляция стока.
- `cliffX`, `cliffHeight`, `cliffWidth`: крутой уступ вдоль искажённой
  линииX. Для сложной композиции используйте области и несколько операций.

`palette:{grass,rock,shore,mud,road}` принимает ID активной land-палитры.
По умолчанию имена разрешаются по активному профилю: трава, камень,
песок у моря, грунт у реки. Используйте явные ID, если вариантов несколько.
`rules` — до32 правил с обязательным `material` и необязательными
`minimumHeight/maximumHeight`, `minimumSlope/maximumSlope`,
`minimumCurvature/maximumCurvature`, `minimumWetness/maximumWetness`.
Последнее совпавшее правило выигрывает. Пороги высоты/уклона изменяет
плавный пространственный шум; ID материалов не интерполируются.
Штатные shared corners/Modern131 обеспечивают переходы, seed перемешивает варианты.
`road` — обычная область `shape:line`; ширина немного изменяется вдоль пути.

`water:{material,liquid,level}` необязателен: `material` — ID overlay-палитры,
`liquid` — индекс существующей жидкой записи MPR (не ID палитры), `level` —
метры. В затопленных ячейках добавляется настоящая поверхность overlay штатными
командами маппера. Вода, грунт и атлас отменяются вместе. Без `water` меняется
только подложка. `carve_river` сам по себе воду не создаёт. Линия задаёт русло;
для естественных меандров используйте извилистую полилинию. Равнинный `level`
не заменяет систему разных уровней для горной реки.

### Карта по заданию: лесная равнина с рекой,8×8

Получите ID травы/воды через `material_palette`, индекс жидкости — из таблицы
материалов MPR `read_profile_map`. Пример ниже использует условные ID123/456,
индекс1: замените их значениями своего профиля. После каждого вызова дождитесь

```json
{"name":"create_map","arguments":{"revision":"<revision>","name":"forest_river","sectorsX":8,"sectorsY":8,"height":8,"maxZ":64,"material":123}}
{"name":"generate_terrain","arguments":{"revision":"<revision>","preset":"plain","seed":220,"preview":true}}
{"name":"apply","arguments":{"operation":"<preview-operation>","revision":"<preview-revision>"}}
```

## Карта по заданию без человека — 221

Человек один раз открывает редактор с нужным профилем, включает «Правка» и
«Разрешить агенту сохранять». Карта может быть не открыта. Агент подключается
автоматически к единственному включённому экземпляру; при нескольких выбирает ID
через list_instances/connect_instance. Управление окном, мышью и буфером не нужно.
Агент не включает разрешения сам. Начиная с225 мост может сам запустить фоновый маппер по сохранённым разрешениям (решение владельца2026-10-24).

Каждый изменяющий вызов получает свежий get_revision. Затем опрашивается
operation_status до complete; result.error означает отказ. Следующий шаг
использует новую ревизию. При конфликте перечитать контекст и повторить подготовку,
не повторять вслепую операцию с побочными эффектами. Фоновую подготовку можно отменить;
начатая короткая атомарная запись заканчивается целиком или откатывается.

| Инструмент | Параметры и поведение |
|---|---|
| create_map | name, sectorsX/Y; height, maxZ, material/materialName, root, template необязательны. template — ключ list_profile_maps, имя файла или зоны. Пустой редактор поддерживается. Без template выбирается текущая чистая MPR, иначе первая MPR профиля. Начальный материал требует авторского однородного тайла; недоступный шаблон/атлас даёт ошибку без записи |
| open_map | map — ключ вида 0/gipat2.mpr, имя файла или зоны. MPR с основным MOB (если он есть) и штатным контекстом соседей. Неполная MPR без MOB открывается для последующего create_mob. Любые несохранённые MPR/соседи/MOB/travel/БД/черновик скрипта вызывают отказ без discard |
| close_map | Закрывает только чистую рабочую область. При правках — ошибка «save first». Открытие/закрытие — навигация, очищают историю прежнего документа |
| place_map_in_world / set_world_position | Необязательный map (по умолчанию активный). Либо x/y и world для новой карты, либо relativeTo и side N/S/E/W. N=+Y, S=-Y; E/W выравнивают нижний край Y, N/S левый край X. Размеры берутся из MPR, совпадающие края разрешены, пересечения площадей запрещены. world-map-layouts.json профиля, тот же compare/lock/atomic и резерв миграции, что у ручной операции; одна Undo |
| create_mob | Основной пустой MOB с именем MPR в той же папке; ошибка при существующем файле. template — ключ/имя MOB профиля; copyRanges/copyScript/copyDiplomacy/copyWorld по умолчанию false. Без копирования диапазон rangeMinimum=1/rangeMaximum=999999, time=12; defaultDiplomacy=false. Используется217 reader и штатный сериализатор/валидатор, без объектов/AI/VSS. Связь в раскладке обновляется в той же операции |

Перед созданием каталог можно получить через list_profile_maps, даже если карта
не открыта. Например, задание «gipat-test рядом с gipat2, холмы, основной MOB»:

```json
{"name":"create_map","arguments":{"revision":"<fresh>","name":"gipat-test","sectorsX":8,"sectorsY":8,"height":8,"maxZ":64,"template":"0/gipat2.mpr"}}
{"name":"place_map_in_world","arguments":{"revision":"<fresh>","relativeTo":"gipat2","side":"E"}}
{"name":"generate_terrain","arguments":{"revision":"<fresh>","preset":"hills","seed":221}}
{"name":"sculpt","arguments":{"revision":"<fresh>","action":"smooth","strength":0.2,"area":{"shape":"circle","x":128,"y":128,"radius":24}}}
{"name":"auto_paint","arguments":{"revision":"<fresh>","preset":"hills","seed":221}}
{"name":"create_mob","arguments":{"revision":"<fresh>","template":"0/gipat2.mob","copyWorld":true,"copyRanges":true,"copyDiplomacy":true}}
{"name":"save","arguments":{"revision":"<fresh>"}}
{"name":"open_map","arguments":{"revision":"<fresh>","map":"gipat2"}}
{"name":"open_map","arguments":{"revision":"<fresh>","map":"0/gipat-test.mpr"}}
```

Это последовательность tools/call, не один пакет: после каждого вызова дождаться
operation_status и получить новую ревизию. Если справа место занято, выбрать свободную
сторону или координаты на основании get_context/соседей; отказ не двигает карту.
После возврата проверить get_context (worldOrigin/neighbors/MOB), read_terrain и
read_paint. При незаписанной sculpt последующий open_map отклоняется; нужен save
или решение человека в редакторе. Создание/открытие не регистрирует новую зону в
map.txt, не пишет игровой сценарий и не запускает игру. Эту часть задания агент
обязан отличать от готовности MPR/MOB для дальнейшего редактирования.

Undo создания MPR возвращает прежнюю карту или пустой редактор; Undo создания MOB
выгружает MOB и отменяет добавленную связь мира. Начальные файлы остаются на диске,
как у create_map219. Undo размещения записывает обратное изменение штатной раскладки;
для такого MCP Undo также требуется разрешение сохранять. Сохранение задаёт новую
дисковую базу: старые снимки агентских команд удаляются на границе Save.

## Обновление маппера при запущенных агентах

Начиная с222 закрывать Codex и Claude Code для установки не требуется.
Закройте только EIMapperEndurance и игровой runtime этого комплекта. После
подготовки и разрешения установки используйте `packaging/install_program.ps1`
по [договору передачи](TEST_BUILD_HANDOFF.md). Он сохраняет резерв, проверяет SHA,
при блокировке переименовывает прежний файл в `.old-ataman-<метка>` и ставит новый
под обычным именем. Работающие мосты продолжают использовать старые exe/DLL;
новые запуски берут новые. Следующая установка или rollback удаляет только
собственные, совпавшие по SHA и уже свободные старые файлы. Вручную удалять их
или завершать процессы не нужно. `rollback.ps1` в созданном резерве допускает
те же работающие мосты. Старые резервы не изменяются.

Путь `artifacts/EI-Mapper-Ataman-2-first-test/EIMapperMcp.exe` сохранён.
Перерегистрировать сервер в конфигурации Codex/Claude не требуется.
С224 обновлённый маппер восстанавливает ранее выбранные человеком режим и Save.
Новый мост224 выбирает единственный включённый экземпляр при запросе; человеку
повторно включать доступ не нужно. Работающий мост222/223 совместим с редактором224,
но ещё требует `list_instances`/`connect_instance` после смены ID; для нового
автовыбора один раз штатно переподключите MCP-сервер в клиенте после установки224.

Мост222+ берёт актуальные tools, resources, resourceTemplates и instructions
из `mcp_catalog` редактора и передаёт вызовы без проверки по устаревшему
встроенному списку. `ataman://tools` содержит текущие инструкции и версию;
инструкции первоначального initialize до подключения неизбежно запасные.
Каталог проверяется раз в секунду в простое и перед запросами списка/ресурсов;
на время незавершённых операций опрос приостанавливается, чтобы его короткий
таймаут не прервал штатную длительную запись карты. Старый редактор проверяется
на поддержку каталога один раз за подключение.
При подключении, отключении и изменении каталога/версии отправляется
`notifications/tools/list_changed` (`capabilities.tools.listChanged=true`).
Набор222 одинаков в Чтении/Правке, полномочия проверяются редактором при вызове;
смена режима разрывает сеанс; мост224 повторно выбирает единственный экземпляр
при следующем запросе, мосты222/223 требуют list_instances/connect_instance.

Если клиент поддерживает уведомление, он обновит каталог в текущем сеансе.
Если список остался прежним, выполните переподключение сервера Ataman в MCP
настройках клиента (в Claude Code `/mcp` → Ataman → reconnect). Это штатное
переподключение, без ручного завершения процессов и закрытия приложения.
При новом MCP-подключении мост автоматически читает только метаданные каталога,
если доступен ровно один включённый редактор. Поэтому новый список доступен уже
до connect_instance даже клиенту без автообновления. В224 чтение карт и правки
автоматически выбирают единственный включённый экземпляр. При нескольких
выберите ID явно через list_instances/connect_instance; мост не угадывает,
чей каталог показывать. Явный disconnect_instance отключает
автоматическое обнаружение метаданных до следующего connect_instance/нового MCP-сеанса.
Автообновление в конкретной версии клиента следует отличать от отправки
уведомления мостом; результаты и ограничения проверки приведены в
[отчёте222](validation/ATAMAN_MCP_BRIDGE_HOTSWAP_222_20261024.md).

Переход с уже работающего моста218–221: установка222 не завершает его, чтение
и прежние инструменты сохраняют совместимость с новым редактором. Такой мост
ещё не умеет получать каталог и уведомлять клиента; для активации новой
возможности один раз переподключите сервер MCP в клиенте. Дальнейшие обновления
совместимого редактора работают с уже запущенным мостом222+.

Локальный протокол: прежний newline JSON/id/secret/method/arguments сохранён;
новые запросы добавляют `protocolMajor:1`, прежние218–221 без этого поля
принимаются как1. Старые редакторы игнорируют дополнительное поле, неизвестный
`mcp_catalog` возвращает `Unknown read tool`, и мост использует запасной каталог.
Новый каталог содержит protocolMajor1/catalogVersion1. Другой major или
неподдерживаемая схема возвращают явную ошибку обновления/переподключения,
а не маскируются устаревшим списком. Запасной список не добавляет редактору
возможностей, отсутствующих в его версии; при вызове он возвращает ошибку.

С267 open_map возвращается после MPR и основного MOB. Поле loadingAddMobs в ответе и get_context означает фоновую загрузку зависимостей; дождитесь false и запросите свежую revision перед изменением/экспортом. get_context.neighborLoadStage:0 — ожидание или завершение,1 — соприкасающийся рельеф,2 — его статические объекты,3 — остальные MPR. Стадии соседей зависят от флажка показа соседних карт.
