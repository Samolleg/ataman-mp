Точки стыковки моделей для EI Mapper Ataman 128
Самостоятельный текст для автора моделей / другого чата
Восстановлено 2026-10-10: EI-PAINT-DOCS-SYNC-20261010

Задача: подготовить жёсткие архитектурные модули и точные точки соединения.
Маппер совмещает точки, поворачивает наружные направления навстречу друг другу
и согласует верх. В MOB остаются обычные позиции/повороты объектов.
Стык не создаёт игровой шарнир, родителя, коллизию или автоматическую дверь.

1. Координаты и подготовка геометрии

Для каждой модели зафиксируй техническое имя, размеры, единицы, локальные оси
и начало координат. Геометрия и стыки измеряются в одной системе после экспорта,
именно так, как модель видна в маппере. position — не мировая позиция объекта
карты. Изменение начала/масштаба/осей требует пересчёта стыков.

Конкретный Blender-экспортёр здесь не специфицирован. Его оси/единицы нельзя
считать подтверждёнными по одной Blender-сцене. Для преобразования
p_mapper = A * p_blender + t к position применяются A и t; к направлениям
normal/up — преобразование осей A без переноса t. Это правило подготовки
координат, не встроенный импорт. При отражении, неравномерном масштабе или
деформации проверь направление наружу и весь кадр по экспортированной геометрии.

2. Контракт одного стыка

id       Непустая строка, уникальная в connections одной модели. Не ID объекта
         MOB. Ответным стыкам разных моделей не нужны одинаковые id.
         Интерфейс создаёт UUID; в JSON допустимо понятное строковое имя.
label    Подпись для человека; может быть пустой, тогда показывается id.
type     Непустая строка совместимости. Соединяются только полностью одинаковые
         строки с учётом регистра. wall/floor/roof — подсказки интерфейса,
         а не закрытый перечень; разрешены собственные обозначения.
position Три конечных числа [X,Y,Z], относительно начала модели.
normal   Три конечных числа: направление наружу из соединяемой поверхности.
up       Три конечных числа: верх стыка, задающий поворот вокруг normal.

До 128 стыков на модель. Для каждого вектора квадрат длины меньше 1e12.
Для normal/up он больше 1e-8; квадрат длины векторного произведения
нормализованных normal/up больше 1e-6. Нулевые и параллельные направления
непригодны. Рекомендуются единичные перпендикулярные normal/up, хотя загрузчик
не требует точной ортонормальности: при совмещении normal нормализуется,
up проецируется перпендикулярно normal и нормализуется. Совместимость задаёт
type, а не label или id.

3. Пример повторяемых стен

Учебная стена: ширина 4, высота 2 условные единицы модели; начало в центре
основания, ширина по X, высота по Z, толщина по Y. Это договор примера,
а не утверждение о масштабе любого экспортёра. Минимальный JSON-каталог:

~~~json
{
  "schemaVersion": 1,
  "models": {
    "example_wall": {
      "russianName": "Учебная стена",
      "connections": [
        {
          "id": "left",
          "label": "Левый край",
          "type": "wall-w4-h2",
          "position": [-2, 0, 1],
          "normal": [-1, 0, 0],
          "up": [0, 0, 1]
        },
        {
          "id": "right",
          "label": "Правый край",
          "type": "wall-w4-h2",
          "position": [2, 0, 1],
          "normal": [1, 0, 0],
          "up": [0, 0, 1]
        }
      ]
    }
  }
}
~~~

При одинаковой исходной ориентации закрепи первую стену в начале карты
и присоедини left второй к right первой: начало второй сместится на +4 по X,
точки совпадут в [2,0,1], поворот останется исходным. Одинаковый type сам по
себе не проверяет размеры и шов геометрии — это обязанность автора.
Для верхнего горизонтального стыка пример normal=[0,0,1], up=[0,1,0];
у ответного нижнего — normal=[0,0,-1], up=[0,1,0].

4. Маркеры Blender и внесение данных

Можно использовать Empty как вспомогательные маркеры. Предлагаемое соглашение:
локальная ось маркера +Z = normal наружу, +Y = up, +X = up × normal.
Это соответствует осям кадра, строящегося при совмещении, но маппер не читает
Empty автоматически. Имя/свойства Empty сами по себе не создают connections.
Передай численные координаты и направления в системе экспортированной модели.

Витрина из создания/свойств объекта → модель → «Точки стыковки…».
«Добавить»: название, type, положение, направление, верх. ЛКМ по поверхности
переносит точку; численные X/Y/Z позволяют уточнить её, в том числе вне модели.
ЛКМ за жёлтый конец/линию вращает направление; Alt+ЛКМ позволяет повернуть
стрелку вдоль взгляда. Зелёный верх поворачивается вместе с направлением.
ПКМ/средняя кнопка вращает вид, колесо меняет масштаб. Esc во время жеста
отменяет жест. «Отмена» закрывает окно без записи. Запись — «Сохранить стыки».

Хранение: model-catalog.json рядом с database.res активного профиля,
models.<ключ-модели>.connections. Ключ приводится к нижнему регистру, пробелы
по краям убираются, окончание .mod/.fig снимается. Каталог schemaVersion=1,
максимум 32 MiB. Некорректный или изменённый извне JSON не перезаписывается молча.

Пример выше для отдельного нового образца, а не для замены существующего
каталога целиком. Сохраняй другие модели, текстуры, сборки и неизвестные поля.
Стыки — данные редакторского каталога, не поля MOB.

5. Проверка и ограничения

Настрой профиль с ресурсами. Выдели одну деталь, включи «Магнит», начни
перемещение G и подведи к совместимому стыку видимого соседа.
Tab переключает пары, ЛКМ подтверждает, Esc отменяет перемещение. Сохрани MOB
и каталог. Магнит перемещает одну деталь; сборки создаются отдельно по
OBJECT_ASSEMBLIES.md. Они не требуются для настройки стыков.

Сначала проверь один асимметричный экспортированный образец: начало, единицы,
оси, наружное направление и верх. Затем — пару стен, угол, горизонтальный
стык, сохранение и повторное открытие. Стыковка не доказывает проходимость,
коллизии или поведение в игре. Для FIG8/анимации не обещай автоматическую
деформацию стыков: каталог хранит фиксированные векторы, при размещении
position умножается на масштаб объекта. Используй жёсткую геометрию;
варианты и анимацию проверяй отдельно.

6. Что передать

• Исходную сцену и экспортированные модели/текстуры.
• Технические имена, размеры, единицы, оси, начало и шаг модулей.
• Для каждой модели id/label/type/position/normal/up и JSON connections.
• Асимметричный калибровочный образец, снимки швов, список проверок/вопросов.
• При доступе к мапперу — тестовый MOB и согласованную копию каталога.
  Если доступа нет, прямо укажи отсутствие установки и игровой приёмки.
