# Передача: горизонтальные точки подхода предметов (Ataman 194)

## Задача другому чату

В маппере реализована подготовка точек предметов в мировых XY. Требуется отдельно реализовать тот же контракт в игре. Эта записка не разрешает автоматически менять или устанавливать игровой addon: сначала проверить действующие инструкции игрового проекта, исходники установленной сборки и разрешение владельца. Не переносить приватные исходники в репозиторий маппера.

Исходные случаи: DejaVu, Zone1, лук uhwbw02 ID741 и кинжал uhwdg03r ID68. Поворот предмета, включая вертикальное положение, не должен поворачивать его точки подхода. Объекты остаются рычагами, RegisterLoot и условия взаимодействия сохраняются.

## Контракт координат

Для подтверждённых моделей оружия, брони, быстрых и квестовых предметов используйте фиксированные мировые оси X и Y. Игнорируется всё вращение модели, включая yaw; только удаление pitch/roll недостаточно. Центр — позиция/origin объекта, существующий GetCP, а не центр повернутого bounding box.

В levers.ldb остаются прежние поля: четыре float32 для двух смещений и число активных точек. Формат БД не расширяется, флаг режима в БД/MOB не добавлен. Режим выводится из классификации модели.

Для каждого активного d=(dx,dy):

```
s = databaseScale * complexion.tall + (1 - complexion.tall)
L = sqrt(dx*dx + dy*dy)
if L == 0: P = origin
else:
    R = L*s + actorApproachDistance
    P = (origin.x + dx/L*R, origin.y + dy/L*R, origin.z)
```

Сохранить действующее определение actorApproachDistance и проверку достижимости. Z не поворачивается и равен origin.z; это горизонтальная математическая плоскость, а не обещание высоты земли на склоне. Проекцию маршрута на землю/навигацию проверять в реальной игре отдельно. Маппер берёт XY клика по земле, игнорируя высоту попадания для сохранения двух DB-координат. Дистанция предпросмотра 0.5 — пример, она не записывается в БД.

## Как маппер определяет модели

Использованы существующие валидаторы `MapWeaponCatalog::load` и `MapInventoryCatalog::load` в source/resources/map_weapon_catalog.cpp. Новый containsModel проверяет точное имя среди принятых записей. Каталоги лежат рядом с активной database.res:

- mapweapons-catalog.json: schema2, db_weapons/db_armors, связь с текущей БД по имени и селекторам модели; проверяются архив и ресурсы модели.
- mapitems-catalog.json: schema2, db_quick_items/db_quest_items, текущие поля БД, геометрия; используется имя component (например initqi2item), а не контейнер initqi2.

Не классифицировать по префиксу имени, имени объекта, наличию RegisterLoot или одному лишь типу «рычаг». При отсутствии/невалидности каталога или неподтверждённой модели маппер оставляет старый расчёт с ориентацией объекта. Для игры нужен эквивалентный проверенный набор моделей, обновляемый при смене профиля/БД. Если выбирать другой источник классификации, сначала доказать совпадение набора с маппером, включая отсутствующие/устаревшие каталоги. Двери, сундуки и обычные рычаги не переводятся автоматически.

## Точка интеграции

В исследованном Rebuild изменение относится к генерации CLeverObject::GetUsePoints: сейчас смещения умножаются на ориентированные GetXAxis/GetYAxis. Для предметного режима заменить только базис. В доступном reference addon есть перехват генерации точек с вызовом исходной функции и отдельным fallback для отсутствующей записи БД. Проверить, что именно этот код соответствует установленному бинарнику; не использовать адреса из старой копии без проверки. Не менять условия ApplyScience, ключи/навыки, SwitchState, EnableLever, RegisterLoot, очередь выдачи и удаление объекта.

Политика отсутствующей строки/нуля активных точек остаётся прежней. Проверять диапазон 0..2, конечность значений и память в соответствии с соглашениями игрового проекта. Изменение базиса не должно обходить недостижимый путь или увеличивать разрешённую дистанцию активации.

## Совместимость и проверка

Существующие смещения автоматически не пересчитывались. Их новое толкование меняет положение подхода у ранее повернутых предметов: владелец может заново расставить точки. Не переписывать общие строки БД по одному экземпляру без явного решения. Все экземпляры модели используют одну строку БД.

Проверить:
1. ID741 и ID68 в положениях лёжа, стоя, с наклоном и разным yaw: одинаковые XY точек относительно origin.
2. По одному представителю каждой из четырёх категорий, одна и две точки, нулевое смещение, масштаб/дистанция разных персонажей.
3. Совпадение маркера маппера и выбранного маршрутом назначения, в том числе склон/препятствие/недостижимая точка.
4. Настоящая выдача RegisterLoot и удаление предмета, Save/load; обычная дверь/рычаг с вращением и проверкой ключа/навыка.
5. Неподтверждённая модель, отсутствующий каталог и отсутствующая строка БД сохраняют согласованное старое поведение.

## Отдельная диагностика БД

Пересохранение редактором сопровождалось добавлением Tools\loot.wav восьми новым рычагам. Обратное восстановление пустых звуков дало точный прежний SHA levers.ldb. Повреждение структуры этой таблицы не доказано, и пустой звук не доказан причиной сбоя ID68. Не включать непроверенный ремонт БД в изменение геометрии подхода.
