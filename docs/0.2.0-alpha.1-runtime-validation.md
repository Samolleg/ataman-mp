# 0.2.0-alpha.1 JMV zone-identity test

Alpha.58 proved playable staged-map loading and one controlled player, but its
late transition substitution left the New Game session initialized as zone1.
That produced zone1 minimap/quest/save metadata and ignored the selected
entrance even though the staged terrain, MOB, and music were correct.

This build initializes the fingerprinted engine player-default record with the
selected `map.txt` zone and entrance before the normal New Game transition. The
map loader still substitutes only the validated staged MPR/MOB pair. If the
editor cannot prove an authored deploy rectangle clear, it no longer rejects
the map: the authored entrance is retained and the game performs deployment.

Test saves are redirected to a persistent profile-specific directory below
Endurance AppData. They survive later Ctrl+F5 launches while remaining isolated
from the live JMV `saves` directory.

## Focused checks

1. Test `gz19h`; it must pass preflight and enter through a map-table entrance.
2. Test a normal gameplay zone other than zone1. Verify spawn, minimap, quest
   map, Save metadata, and Load splash identify that zone rather than zone1.
3. Test a `bz` briefing zone. Verify its authored entrance/exit and briefing UI.
4. Create a disposable save, exit normally, launch another test, and verify the
   save remains visible. Confirm live campaign saves remain absent.
5. Confirm there is exactly one controlled player, correct music, skipped
   startup movies, and graceful exit.

The bridge log should contain `initialized New Game player`, followed by a
`New Game zone identity` result of `verified`. A `fallback-substitution` result
means the early identity initialization did not take effect and should be
reported with the complete run folder.
